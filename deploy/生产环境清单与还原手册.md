## 四、从零还原生产（runbook）

```bash
# 1. 拉代码
git clone <repo> && git checkout <统一主分支>

# 2. 自有后端（5个）逐个就位 + systemd
rsync server/auth_server.py    dapeng:/home/ubuntu/auth-service/
rsync server/content_api.py server/leadgen_api.py server/imggen_api.py server/tikhub.py  dapeng:/home/ubuntu/content-api/
rsync server/dl_service.py     dapeng:/home/ubuntu/dl-service/
sudo cp deploy/systemd/*.service /etc/systemd/system/ && sudo systemctl daemon-reload
sudo systemctl enable --now huangque-{auth,content,dl,leadgen-api,imggen-api}

# 3. 填密钥（手动，不在 git）
#    /home/ubuntu/content-api/content.env  ← TIKHUB_KEY / GEMINI_API_KEY / OPENAI_API_KEY / DOUBAO_* / 代理
#    /etc/nginx/.htpasswd-hq               ← 团队密码

# 4. 上游工具（旧获客/深采，按需）
#    clone MediaCrawler → /home/ubuntu/MediaCrawler，部署 leadgen-A（app.py=server/app.py），enable leadgen-A/B
#    clone douyin-scraper → /home/ubuntu/douyin-scraper，enable xiaotan

# 5. nginx
sudo cp deploy/nginx-huangquechuanmei.conf /etc/nginx/sites-available/huangquechuanmei
sudo nginx -t && sudo nginx -s reload

# 6. 自检
curl https://huangquechuanmei.com/api/gen/health
```

## 四-B、漂移哨兵与部署保护

- 哨兵脚本：`scripts/drift_sentinel.py` → `/home/ubuntu/hq-drift/drift_sentinel.py`。
- 巡检基准：直接比较线上运行文件与服务器 checkout 的 `origin/main`，不再依赖上次 `--bless` 的线上快照。
- 合法部署：`./ship` 在 rsync 后会执行 `drift_sentinel.py --verify-deploy <本次文件>`，确认本次部署文件线上内容等于 git。
- 部署记录：`./ship` 只用 `--bless-deploy <本次文件>` 记录本次文件清单，不会把整站当前线上状态吞进基线。
- 服务器 checkout：`./ship` 会给 `/home/ubuntu/huangque-main-site` 安装 pre-commit 拦截钩子，禁止在服务器 checkout 直接提交热改。

手动巡检：

```bash
python3 /home/ubuntu/hq-drift/drift_sentinel.py --print
```
