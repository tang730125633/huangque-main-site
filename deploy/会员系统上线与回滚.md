# 会员系统上线与回滚

本流程的目标是避免代码部署后立即锁死网站或小程序。生产环境的
`HQ_MEMBERSHIP_ENFORCEMENT_ENABLED` 默认必须保持为 `0`。

## 上线顺序

1. 从已合并的 `main` 部署认证服务、内容服务、网页和 Nginx 配置。
2. 保持 `HQ_MEMBERSHIP_ENFORCEMENT_ENABLED=0`，重启认证与内容服务。
3. 验证网页充值、小程序充值、生成扣点和邀请入口仍可正常调用。
4. 只读生成候选审核清单：

   ```bash
   python3 scripts/backfill_launch_experience_members.py \
     --db /home/ubuntu/auth-service/users.db \
     --discovery-out /root/membership-candidates.csv
   ```

5. 由业务负责人逐行核对账号、注册时间和命中原因，仅将确认升级的行
   `approved` 改为 `yes`。审核清单属于用户数据，不得提交到 Git。
6. 记录确认文件摘要：

   ```bash
   sha256sum /root/membership-approved.csv
   ```

7. 先按显式清单预览，确认 `matched` 与批准人数完全一致：

   ```bash
   python3 scripts/backfill_launch_experience_members.py \
     --db /home/ubuntu/auth-service/users.db \
     --manifest /root/membership-approved.csv
   ```

8. 正式迁移。脚本会先自动备份数据库；名单外用户不会升级：

   ```bash
   python3 scripts/backfill_launch_experience_members.py \
     --db /home/ubuntu/auth-service/users.db \
     --manifest /root/membership-approved.csv \
     --manifest-sha256 <上一步确认的SHA256> \
     --apply --confirm UPGRADE-EXPERIENCE-MEMBERS
   ```

9. 核对会员、点数、免费音色槽位权益和审计台账。迁移不改变原有点数，
   不触发邀请奖励；已有会员不会降级或续期。
10. 最后将 `/etc/huangque/auth.env` 中的
    `HQ_MEMBERSHIP_ENFORCEMENT_ENABLED` 改为 `1`，只重启认证服务。
11. 分别验证网页和小程序的非会员拦截、会员充值、生成扣点与邀请流程。

## 回滚顺序

1. 立即把 `HQ_MEMBERSHIP_ENFORCEMENT_ENABLED` 改回 `0` 并重启认证服务；
   网站、小程序生成、点数充值和邀请的会员强校验随即解除。
2. 若仅业务拦截异常，不回滚数据库，保留会员与审计记录继续排查。
3. 若迁移名单本身错误，停止认证服务，保存当前数据库，再由负责人确认后
   使用脚本生成的 `.pre-membership-*.bak` 恢复；不得在服务运行时覆盖数据库。
4. 回滚代码时从 `main` 的上一稳定提交部署，不在服务器目录直接热改。

## 免费音色槽位说明

会员开通、后台设置/续费和存量迁移会在认证数据库事务内写入一次性槽位权益。
内容服务在用户读取或购买槽位时，以确定性槽位 ID 幂等落地：

- 已有有效槽位不会重复创建；
- 落地失败不会扣除 50 点，权益保留并在下次访问重试；
- 续费、重复回调和重复迁移不会产生第二个免费槽位。
