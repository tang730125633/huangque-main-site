# 工单 · 音频产出不走 COS、全回退本地 /api/gen/file（根治 yuelei 音频问题的后端根因）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+《生产环境清单与还原手册》。
> **冲突组：A（`server/content_domains/audio.py`、`core.py`、`cos.py`）+ 运维（content.env/服务重启）** —— 抢 `lock/A`。
> 相关：yuelei 反馈"音频无法试听/下载"（前端已由 audio.html 带 token blob 修好，本单治后端根因）、COS-PRIV-P2(#185)、RESIL(#196)。

## 现象
`audio_assets` 表里 **27 条音频 url 全是 `/api/gen/file/audio/...`（本地）**，没有一条 COS 直链。而 `gen_audio`（`audio.py:813`）用的是 `public_url(fn, "audio/mpeg")`（默认 `private=False`），本意是传**公开 COS**。→ COS 对音频没生效，全走了本地回退。

## 已排查（供参考，2026-07-06）
- ✅ `content.env` 里 COS 变量**全配好**：`COS_SECRET_ID`(len36)、`COS_SECRET_KEY`(len32)、`COS_REGION=ap-guangzhou`、`COS_BUCKET=huangque-media-1435693839`、`COS_PUBLIC=1`、`COS_PREFIX=huangque/`。
- ✅ `qcloud_cos` SDK **已装**（服务器 `python3 -c 'import qcloud_cos'` OK）。
- ✅ content 服务 unit 的 `EnvironmentFile=/home/ubuntu/content-api/content.env`（会加载）。
- ✅ content 日志近 7 天**无 `[cos] 上传失败` 记录**——说明 COS upload **根本没被触发**（不是抛异常回退，而是压根没进 upload 分支）。
- `cos.enabled()`（`cos.py:37`）= `bool(_SECRET_ID and _SECRET_KEY and _REGION and _BUCKET)`，这几个模块级变量在 **import cos 时**从 `os.environ` 读。

## 根因方向（按可能性，需在服务里精确验证）
1. **运行中的服务进程没拿到 COS 环境变量**（最可能）：模块级 `_SECRET_ID` 等在进程启动 import 时定死；若 COS 变量是**在服务上次启动之后**才加进 content.env、而服务没重启，进程里就没有它们 → `cos.enabled()` 恒 False。
   - 验证：在服务里打印 `from content_domains import cos; cos.enabled()`（**必须在加载了 content.env 的服务上下文里**，别用裸 python3——裸跑没 env 必然 False，是假阴性）。或加临时 `/api/gen/_cosdebug` 打印 `cos.enabled()`+各变量是否非空。
   - 若确为此因：`sudo systemctl restart huangque-content` 让进程重新 import 拿到 env。
2. **`public_url` 的文件存在判断跳过了 COS**（`core.py:77` `if fp.is_file()`）：若 `_out_path(rel)` 算出的路径和音频实际落盘路径不一致，`fp.is_file()` 为 False → 跳过 COS、返回本地。
   - 验证：确认 `gen_audio` 写文件的路径 == `public_url` 里 `_out_path(fn)`。
3. **audio 特有**：`voice_preview_*`（克隆试听）走的是 `_file_url`（`audio.py:171/173`）本就本地，不入 COS，正常；但 `aud_*`（正式配音 `audio.py:811-813`）应走 COS。核对 27 条里 `aud_*` 那部分为何也本地。

## 修复要求
1. 定位并修复 COS 对音频未生效的根因（上面 1/2 之一或组合）。
2. 修好后**新生成的配音 url 应为 COS 直链**（`COS_PUBLIC=1` → 公开直链，可直接播放/下载，无需 token）。
3. **加可观测**：`public_url` 里当 `cos.enabled()` 为真却跳过上传（如 `fp.is_file()` False）时，`print("[cos] skip upload: enabled=%s exists=%s rel=%s")` 落日志，便于以后定位。
4. **历史 27 条本地音频**：前端 audio.html 已能带 token blob 播放/下载（已上线），本单可不回填；如需可写一次性 backfill 把本地音频补传 COS 并更新 url（可选，另评估）。
5. 同理体检 image/video 产出是否也受同一根因影响（若 `cos.enabled()` 全局 False，则图/视频也在走本地）。

## 验收标准
1. 服务里 `cos.enabled()` == True（在正确加载 env 的上下文验证）。
2. 新生成一条配音 → url 是 COS 直链（`https://<bucket>.cos.<region>...` 或配置的 COS 域名），浏览器直接可播/可下载。
3. `public_url` 跳过 COS 时有日志。
4. 不影响现有音频播放/下载（前端 token blob 兜底仍在）。

- 后端改动需**部署重启 content 服务**。实测新配音出 COS 直链、可播可下。
