# 文案成片语速调节设计

## 目标

在“文案成片”页面增加统一的语速调节能力，同时支持公共音色和用户个人音色。默认语速为 `1.0x`，允许范围为 `0.5x` 至 `2.0x`，步进 `0.1x`。未提交该参数的旧客户端继续按 `1.0x` 处理。

## 交互设计

- 在“配音音色”控件下方增加“语速”滑块。
- 滑块右侧实时显示当前倍率，例如 `1.2x`。
- 初始值为 `1.0x`，最小值 `0.5x`，最大值 `2.0x`，步进 `0.1x`。
- 提交任务时发送字段 `speech_rate`，值为数值类型。
- 切换公共音色和个人音色时保留当前语速选择。

## 数据契约

主站对外任务参数统一使用：

```json
{
  "speech_rate": 1.0
}
```

主站服务端必须再次校验该字段：拒绝布尔值、非数字、非有限值以及范围外数值，并标准化为一位小数。字段缺失时使用 `1.0`。

主站调用 Pixelle 生成服务时，将其映射为 Pixelle 原生参数：

```json
{
  "tts_speed": 1.0
}
```

## 音色链路

### 公共音色

主站将 `speech_rate` 映射为生成服务的 `tts_speed`。生成服务 API schema 接收并校验 `tts_speed`，同步和异步接口都将其传给 Pixelle 标准管线。Pixelle 的 Edge TTS 服务原生支持 `0.5` 至 `2.0` 倍速，并转换为 Edge TTS 的百分比 rate 参数。

### 个人音色

个人音色仍由主站预先合成音频。主站将 `speech_rate` 传给现有的 `synthesize_owned_voice_segment(..., speed=...)`，生成后的音频继续通过 `narration_segments` 交给 Pixelle。Pixelle按音频真实时长计算分镜时长，不再对个人音色重复变速。

## 兼容与错误处理

- 旧请求缺少 `speech_rate` 时使用 `1.0x`。
- 生成服务旧版本不认识 `tts_speed` 时，主站上线顺序必须等待生成服务 PR 先合并并验证。
- 公共音色生成失败沿用现有任务失败与重试机制。
- 个人音色合成失败沿用现有分段合成错误，不生成无声替代音频。
- 最终视频时长以实际音频时长为准，语速调整不裁切文案。

## 代码边界

主站 PR：

- 页面滑块、倍率显示和任务参数提交。
- `speech_rate` 服务端校验。
- 公共音色映射为 `tts_speed`。
- 个人音色调用现有 TTS speed 参数。
- 补充页面、payload、校验和个人音色测试。

生成服务器 PR：

- Pixelle API schema 增加 `tts_speed`。
- 同步和异步生成接口透传 `tts_speed`。
- 安装补丁与回归测试覆盖。

## 验收标准

1. 页面可在 `0.5x` 至 `2.0x` 间以 `0.1x` 调节并显示当前倍率。
2. 公共音色分别以 `0.8x`、`1.0x`、`1.5x` 生成时，音频时长按预期变化且文案完整。
3. 个人音色使用相同三档测试，音频不重复变速，声音身份保持不变。
4. 视频分镜与字幕持续时间跟随实际音频，不提前截断、不产生尾部大段静音。
5. 缺少参数的旧请求正常生成；非法参数在创建任务前返回明确的参数错误。
6. 两个仓库的目标测试通过，且不影响现有公共音色、个人音色、模板和素材生成流程。

## 交付顺序

先提交生成服务器 PR，确认 Pixelle 接口支持 `tts_speed`；再提交依赖该接口的主站 PR。两个 PR 均只提交审查，不执行合并或部署。
