# 短剧内容编辑 API 补充设计

**状态：** 已确认方案 A，待实施

## 1. 目的与范围

第一阶段工作区必须让用户逐步修改并确认角色、剧本和分镜，刷新页面后修改仍然存在。现有项目 PUT 接口只支持项目设置，无法保存这三类内容，因此扩展同一个接口，不新增媒体生成能力，也不改变扣点逻辑。

本补充设计只覆盖角色、剧本和分镜的免费编辑保存。图片、配音、视频、字幕和合成仍属于后续阶段。

## 2. API 形状

继续使用：

```text
PUT /api/gen/short-drama/project?id=<project_id>
```

请求必须包含当前 `revision`，并且一次只能提交一个内容分区：

```json
{"revision": 4, "characters": []}
```

```json
{"revision": 5, "script": {}}
```

```json
{"revision": 6, "shots": []}
```

项目设置字段仍沿用现有 PUT 请求。内容分区不能与项目设置字段混在同一个请求中，避免一次更新跨越多个责任边界。

成功响应继续返回完整 `ShortDramaProject`，并把 `revision` 精确增加一次。陈旧 revision 返回现有 `409 revision_conflict`，用户不匹配返回 404，内容或阶段不合法返回 400。

## 3. 阶段门禁

- `characters` 只允许在 `characters_review` 更新。
- `script` 只允许在 `script_review` 更新。
- `shots` 只允许在 `storyboard_review` 更新。
- `draft` 阶段只能修改项目设置或生成策划。
- `stills_review` 是第一阶段终点，角色、剧本和分镜均锁定。

确认接口仍负责推进阶段；编辑接口不能推进或回退阶段。

## 4. 角色更新

角色更新复用现有角色规范化规则，要求唯一角色键、合法来源类型、提示词、电影化身 ID、独立 `voice_key` 和对象型 `voice_settings`。

服务端在同一事务中替换角色列表。若删除角色，尚未确认的分镜中指向该角色的 `character_keys` 会被移除；不会删除分镜、剧本版本或其他角色。

## 5. 剧本更新与版本

剧本更新必须提供完整剧本对象，包括标题、梗概结构字段和对白列表。对白 ID 必须唯一，角色引用必须指向当前角色。

每次成功保存都追加新的 `short_drama_scripts.version`，不覆盖旧版本。现有分镜保留，但全部关联到新剧本版本；指向已删除对白的 `dialogue_line_ids` 会从尚未确认的分镜中移除。这样用户进入分镜确认时可以看到并修正受影响镜头，同时历史剧本版本仍可追溯。

## 6. 分镜更新

分镜更新提供完整 6–10 镜头列表。每个镜头仍必须为 5 或 10 秒，总时长必须等于项目目标时长，镜头键唯一，并且角色与对白引用必须存在。

服务端在一个事务中替换当前剧本版本的分镜并保持提交顺序。分镜保存不创建新的剧本版本。

## 7. 并发、事务与安全

- 所有内容更新先以 `BEGIN IMMEDIATE` 获取写锁，再检查用户、revision 和当前阶段。
- 规范化与引用校验在写入前完成；失败时不增加 revision、不改变阶段、不留下部分更新。
- 每次成功更新只增加一次 revision。
- 角色、提示词、对白和分镜始终按项目所有者隔离。
- 内容编辑免费，不创建 job、不修改点数。

## 8. 前端行为

工作区只允许编辑当前阶段；已完成阶段可查看但不可修改。保存成功后用服务端完整响应替换本地项目，并通知画布节点更新摘要。

出现 revision 冲突时不静默覆盖，显示“项目已在其他页面更新，请刷新后重试”。占位故事梗概未被用户替换并保存之前，付费“生成短剧策划（3点）”按钮保持禁用。

## 9. 验收测试

- 三个分区在正确阶段保存成功，revision 各增加一次。
- 错误阶段、跨用户、陈旧 revision 和混合分区请求均被拒绝且无副作用。
- 删除角色会清理未确认分镜中的对应角色引用。
- 剧本保存追加版本，并清理已删除对白的分镜引用。
- 分镜保存校验数量、单镜头时长、总时长、角色引用和对白引用。
- 内容编辑不扣点、不创建生成任务。
- 前端刷新后仍显示已保存内容，并在冲突时提示用户刷新。
