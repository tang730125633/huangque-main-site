# 小程序 499 元体验官支付设计

## 目标

修复小程序非会员支付 499 元开通体验官时被微信拦截的问题。支付成功后一次性发放一年体验官、1000 点和 1 个免费音色槽位。

## 范围

- 使用微信小程序虚拟支付，不再为该数字权益调用普通 JSAPI 支付。
- 新增独立商品 `hq_member_exp_1y`，标价 49900 分，不能复用 `hq_points_5000`。
- 非会员和会员已过期用户可以购买；有效会员不能重复购买。
- 普通点数充值商品、会员充值折扣和其他会员体系功能保持不变。
- 本次只提交 PR，不合并、不部署。

## 后端设计

`server/wechat_virtual_pay.py` 增加体验官商品定义，并让商品携带 `order_type=membership_experience`、赠送点数和会员层级等履约元数据。

`virtual_pay_orders` 增加向后兼容的 `order_type` 字段，历史订单默认 `points`。创建订单时，点数商品仍要求有效会员；体验官商品只允许非会员或会员已过期用户购买。

确认支付时先向微信查单并校验订单号和金额，然后在单个 SQLite 事务内：

1. 增加 1000 点并写入点数流水。
2. 调用现有体验官激活函数，发放一年体验官和免费音色槽位，并保留邀请奖励所需记录。
3. 将虚拟订单标记为已到账。

重复确认或重复微信通知只返回既有结果，不重复发放任何权益。

退款通知对体验官订单只标记为需要人工处理，不自动扣除已使用点数、缩短会员期限或删除槽位；普通点数订单继续沿用现有自动冲回逻辑。

## 小程序设计

非会员充值页仍展示固定的 499 元体验官套餐。提交订单时调用 `/api/auth/virtual-pay/order`，传入商品 ID `hq_member_exp_1y`，随后调用 `wx.requestVirtualPayment`，成功后通过现有确认接口轮询到账状态。删除该入口对 `/api/auth/wxpay/jsapi` 和 `wx.requestPayment` 的依赖。

## 验证

- 体验官商品价格和支付参数均为 49900 分。
- 非会员可创建体验官虚拟订单，有效会员被拒绝。
- 支付确认发放一年体验官、1000 点和 1 个免费音色槽位。
- 重复确认不重复发放。
- 普通点数商品创建、价格和到账逻辑不变。
- 小程序 499 入口只调用虚拟支付接口和 `wx.requestVirtualPayment`。
