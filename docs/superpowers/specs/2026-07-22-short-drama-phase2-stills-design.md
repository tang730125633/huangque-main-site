# 短剧第二阶段 A+B（基础工作区与关键帧）设计规格

## 1. 目标

在不重新生成第一阶段角色、剧本和分镜的前提下，让现有处于
`stills_review` 的短剧项目直接进入第二阶段生产工作区，逐镜完成关键帧候选图生成、
历史版本管理、当前版本选择、锁定确认和阶段推进。

本规格只覆盖原方案中的批次 A 与批次 B。配音与字幕、视频片段、FFmpeg 合成和正式
导出分别留给后续独立规格与 PR。

## 2. 全局约束

- 支持 `9:16` 与 `16:9`，图片比例必须与项目比例一致。
- 镜头时长沿用第一阶段的 `5` 秒或 `10` 秒设置。
- 默认每次为一个镜头生成 2 张候选图。
- 所有付费生成必须先取得服务端实时报价，再由用户明确确认后提交。
- 已锁定的资产不能被批量生成覆盖；重新生成只增加历史版本。
- 保存、选择历史版本和确认阶段不扣点。
- 所有读写必须校验登录用户、项目所有权、revision、当前阶段和引用资产归属。
- 图片任务必须使用幂等键；双击和网络重试不得重复排队或重复扣点。
- 不提交测试服务器配置、密钥、数据库、用户数据和生成产物。

## 3. 范围

### 3.1 本次包含

1. 将 `stills_review` 从“第一阶段完成页”改为“关键帧画面生成与确认”。
2. 扩展完整阶段枚举，但本次只开放 `stills_review -> voice_review`。
3. 提供第二阶段三栏工作区：镜头栏、关键帧编辑区、生成控制台。
4. 支持单镜头生成、批量生成未完成镜头、重新生成和失败镜头重试。
5. 支持候选版本、历史版本、当前版本选择和锁定。
6. 支持生成报价、项目预算检查、任务费用和状态展示。
7. 支持任务刷新与服务重启后的状态恢复。
8. 增加后端、前端、权限、幂等、预算和阶段推进自动化测试。

### 3.2 本次不包含

- 配音生成、试听、音色和语速设置。
- 字幕文本与时间轴编辑。
- 电影化身视频生成。
- FFmpeg 预览合成、正式导出和资产库交付。
- 与本功能无关的画布重构或服务器部署配置修改。

## 4. 状态模型

阶段顺序扩展为：

```text
draft
characters_review
script_review
storyboard_review
stills_review
voice_review
video_review
assembly_review
completed
```

`stills_review` 的含义改为“关键帧画面生成与确认”。现有第一阶段已经推进到该阶段的
项目无需数据迁移即可进入第二阶段。

只有满足以下条件时，服务端才允许从 `stills_review` 推进到 `voice_review`：

- 项目至少有一个镜头；
- 每个当前分镜都存在 `type=still` 的资产槽；
- 每个槽都有当前版本；
- 当前版本状态成功；
- 每个资产槽均已锁定；
- 资产版本、镜头与项目画幅一致。

后续阶段在本次只作为合法只读状态存在，不提供伪造的可操作控件。

## 5. 后端设计

### 5.1 模块边界

新增 `server/content_domains/short_drama_production.py`，集中负责第二阶段生产资产、
版本、任务、报价、选择锁定和阶段推进。现有
`server/content_domains/short_drama.py` 继续负责第一阶段项目与内容，并只增加阶段定义、
初始化和 HTTP 分派入口。

如复用现有付费任务管线需要公共入口，只对 `server/content_domains/core.py` 做最小提取，
保证原 `/api/gen/image` 行为和返回结构不变，并用现有图片回归测试保护。

### 5.2 数据表

#### `short_drama_assets`

- `id`
- `project_id`
- `shot_id`
- `type`，本次只允许 `still`
- `current_version`
- `locked`
- `created_at`
- `updated_at`

同一项目、镜头和资产类型只有一个资产槽。

#### `short_drama_asset_versions`

- `id`
- `asset_id`
- `version`
- `job_id`
- `url`
- `prompt`
- `ratio`
- `cost`
- `status`
- `created_at`

生成和重新生成只追加版本，不物理覆盖历史记录。

#### `short_drama_production_jobs`

- `id`
- `project_id`
- `shot_id`
- `kind`
- `job_id`
- `idempotency_key`
- `quoted_cost`
- `status`
- `created_at`
- `updated_at`

`idempotency_key` 在当前用户和任务类型范围内唯一。点数占用从仍在执行的生产任务推导，
避免在项目表中维护第二份容易漂移的累计值。

### 5.3 接口

#### `GET /api/gen/short-drama/production?project_id=...`

返回项目生产阶段、revision、预算摘要、按分镜排序的资产槽、候选版本和关联任务状态。
只返回当前登录用户拥有的项目。

#### `POST /api/gen/short-drama/asset-quote`

请求包含项目、revision、镜头、操作类型和最终生成参数。服务端重新组装并校验实际图片
请求后返回整数点数和分类明细，不能信任前端提供的价格。

#### `POST /api/gen/short-drama/generate-stills`

请求包含项目、revision、镜头列表、候选数量、可编辑提示词和幂等键。服务端只接受
`stills_review` 项目，拒绝批量覆盖锁定镜头，按镜头关联现有图片生成任务并记录生产任务。

#### `POST /api/gen/short-drama/select-asset`

选择指定成功历史版本作为当前版本，可选择同时锁定。服务端校验版本、资产、镜头、项目
和用户归属，并通过 revision 乐观锁更新。

#### `POST /api/gen/short-drama/confirm-production-stage`

服务端重新计算所有镜头关键帧是否锁定；通过后推进到 `voice_review` 并递增 revision。

### 5.4 任务与费用

生成使用现有图片异步任务和点数能力。提交顺序固定为：

```text
校验请求 -> 实时报价 -> 用户确认 -> 幂等检查 -> 预算检查
-> 创建/复用任务 -> 记录生产关联 -> 轮询 -> 保存版本 -> 结算或退款
```

同一幂等键如果已有任务，返回原任务，不创建新任务。任务失败只影响当前镜头；其余镜头和
已锁定版本不变。服务重启后通过数据库中的通用任务和生产关联恢复状态。

## 6. 前端设计

新增：

- `site/workbench/canvas/canvas-short-drama-production.js`
- `site/workbench/canvas/canvas-short-drama-production.css`

现有 `canvas-short-drama.js` 只负责第一阶段与工作区总入口，检测到生产阶段后把渲染和交互
交给新模块，避免继续扩大单文件职责。

### 6.1 左侧镜头栏

按分镜顺序显示缩略图、镜头号、时长和状态：待生成、生成中、待确认、已锁定、失败。
支持切换镜头以及筛选失败或待确认镜头。

### 6.2 中央编辑区

显示当前镜头的 `image_prompt`、角色参考、上一镜头连续性参考、当前候选图和历史版本。
用户可以编辑提交前提示词、预览候选、设为当前版本、锁定和重新生成。

### 6.3 右侧控制台

显示本次报价、预算、累计已用、任务占用点数、任务进度和错误原因。提供单镜头生成、
批量生成未完成镜头、失败重试和确认画面阶段按钮。

所有付费按钮在服务端报价返回后弹出明确确认，取消时不提交任务。

## 7. 错误处理

- `401/403`：显示登录或初始密码限制，不提交任务。
- `404`：统一显示无权访问或项目不存在，避免泄露他人项目存在性。
- `409 revision_conflict`：冻结写操作并要求刷新项目。
- 点数或预算不足：在提交前显示服务端明细。
- 生成失败：在对应镜头显示失败原因和单独重试入口。
- 网络超时：保留幂等键；刷新后先查询生产状态，避免盲目重提。
- 已锁定镜头的批量请求：服务端跳过或拒绝，绝不覆盖。
- 引用资产不属于用户或比例不符：服务端拒绝，不依赖前端校验。

## 8. 测试设计

### 8.1 后端

新增 `tests/test_short_drama_production.py`，至少覆盖：

- 旧 `stills_review` 项目无需迁移即可读取生产状态；
- 其他用户无法读取项目或引用资产；
- 非法 revision、阶段、镜头和比例被拒绝；
- 单镜头生成创建两个候选版本；
- 幂等重试不重复任务或扣点；
- 批量生成跳过锁定镜头；
- 重新生成保留已锁定和历史版本；
- 失败只影响当前镜头并触发退款/释放；
- 全部锁定前不能推进阶段；
- 全部锁定后只推进一次。

### 8.2 前端

新增 `tests/test_canvas_short_drama_production.js`，覆盖：

- 三栏工作区和镜头状态渲染；
- 单镜头选择、候选选择和锁定；
- 报价确认后才提交；
- 取消报价不提交；
- 双击只产生一个客户端提交；
- 只读模式禁用所有写操作；
- 409 后要求刷新；
- 刷新后恢复任务与当前版本；
- `9:16` 和 `16:9` 使用正确预览比例。

### 8.3 回归与验收

- 运行全部 Python 单元测试；
- 运行现有与新增画布 JavaScript 测试；
- 检查所有 JavaScript 语法；
- 运行 `scripts/ci_validate.py`；
- 运行 `scripts/stamp_assets.py --check`；
- 本地 `8097` 分别验证两个画幅；
- 使用测试账号执行一次真实双候选图生成，核对报价、点数变化、任务、版本和刷新恢复；
- 不在自动化测试中调用真实付费生成。

## 9. 提交与交付

功能分支为 `codex/short-drama-phase2-stills`。实现按可独立复核的测试周期提交，最终只从该
分支向主站仓库提交一个新的 Draft PR。PR 不包含测试服务器配置和部署文件；CI 全绿并完成
测试环境真实冒烟后才转为可评审状态。

本批次完成的定义是：当前第一阶段项目能进入第二阶段，逐镜或批量生成关键帧候选，安全地
选版和锁定，并在全部镜头完成后推进到 `voice_review`。
