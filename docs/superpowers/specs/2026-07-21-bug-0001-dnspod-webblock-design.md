# BUG-0001 DNSPod 拦截检测设计

## 背景与根因边界

`huangquechuanmei.com` 当前部署在腾讯云主服务器 `129.204.166.13`。从中国大陆网络访问 HTTP 时，部分请求在到达站点 Nginx 之前被接入层重定向到 DNSPod `webblock.html`；同一主机的 HTTPS 访问正常。应用代码和 Nginx 无法解除上游接入拦截，根治动作是核查并恢复腾讯云备案接入状态。

本次 PR 不修改 DNS、不迁移服务器、不部署生产配置，也不尝试用站点代码掩盖备案或风控问题。PR 的职责是让该外部故障可以被稳定识别、自动回归并按手册处理。

## 目标

- 从中国大陆可用的执行节点检测 HTTP 首跳是否被 DNSPod 拦截。
- 验证 HTTP 正常跳转至本站 HTTPS，且 HTTPS 最终页面可访问。
- 用明确退出码和结构化输出支持人工执行、cron 或现有监控系统。
- 在生产还原手册中记录腾讯云备案接入核查、工单证据和回归标准。

## 非目标

- 不修改主服务器 Nginx 或业务服务。
- 不自动登录腾讯云或自动变更备案信息。
- 不将新服务器、DNS 切换或跨云迁移纳入方案。
- 不把 GitHub Actions 结果视为中国大陆访问链路的充分证明。

## 实现设计

新增 `scripts/domain_access_check.py`，默认检测 `huangquechuanmei.com`，并允许通过命令行覆盖域名和超时时间。

检测分两步串行执行：

1. 对 `http://<domain>/` 发起不自动跟随重定向的 GET 请求。期望状态为 301 或 302，且 `Location` 的主机仍为目标域名、协议为 HTTPS。
2. 对上一步得到的 HTTPS URL 发起正常 GET 请求并跟随站内跳转。期望最终状态为 2xx，最终主机仍为目标域名。

若任意响应的 `Location` 或最终 URL 指向 `dnspod.qcloud.com/static/webblock.html`，输出明确的 `DNSPOD_WEBBLOCK` 故障类型并返回非零退出码。其他异常分别标记为意外重定向、HTTP 状态异常、连接失败或 HTTPS 失败。成功时输出两段状态、目标 URL 和总耗时。

脚本仅依赖 Python 标准库，便于从大陆测试机、运维机或主服务器外部执行。网络请求函数与判定逻辑分离，使测试无需真实联网。

## 错误处理与安全

- 设置有限超时，失败后退出，不进行无限重试。
- 不输出 Cookie、Authorization 或其他凭据。
- 不接受或发送用户数据，只访问站点根路径。
- 不把任意跨域 HTTPS 跳转视为健康，防止拦截页返回 2xx 后误判。
- 脚本只读访问公网，不修改服务器、DNS 或云资源。

## 测试设计

新增 `tests/test_domain_access_check.py`，使用本地伪响应覆盖：

- HTTP 301 到本站 HTTPS，HTTPS 最终 200：通过。
- HTTP 302 到 DNSPod webblock：识别为 `DNSPOD_WEBBLOCK`。
- HTTP 跳到其他域名：识别为意外重定向。
- HTTP 非重定向状态：失败。
- HTTPS 最终落到其他域名或返回非 2xx：失败。
- 网络超时或连接错误：失败并保留可读错误原因。

回归时还需在无 hosts 覆盖的中国大陆网络连续执行至少 100 次；所有请求都应由站点返回 HTTP 到 HTTPS 跳转，且不得出现 DNSPod webblock。

## 运维手册

更新 `deploy/生产环境清单与还原手册.md`，加入 BUG-0001 专节：

1. 在腾讯云备案控制台核对域名备案状态及当前服务器接入关系。
2. 若接入失效，办理接入备案或变更接入，并向腾讯云提交包含时间、来源网络、响应头和拦截 URL 的工单。
3. 腾讯解除拦截后运行新增脚本进行单次检查与 100 次大陆网络回归。
4. 明确 hosts 覆盖、仅测 HTTPS、仅测 HEAD 均不能作为问题已解决的证据。

## 验收标准

- 单元测试覆盖全部正常与失败分支并通过。
- 现有测试保持通过。
- 脚本在正常链路返回 0，在 DNSPod 拦截及其他异常时返回非零。
- 文档明确根治动作属于腾讯云备案接入处理，而非应用代码修复。
- PR 不包含凭据、生产数据、新服务器信息或生产部署动作。
