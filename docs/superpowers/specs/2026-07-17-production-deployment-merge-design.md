把主站服务器当前实际部署版本安全合入 `LU-003/huangque-test-server`，并部署到 `8.138.143.64`。合并必须保留测试服务器已有的 PR1、PR2 画布改造和 XAI 视频续跑修复，同时保留测试服务器自己的用户、点数、任务、生成产物和密钥。

## 合并架构

采用 Git 三方合并，不直接从主站用 `rsync` 覆盖测试服务器。

1. 从测试服务器当前部署提交创建独立集成分支和 worktree。
2. 将主站仓库作为只读 `upstream` 获取，并把 `upstream/main` 合入集成分支。
3. 双方仓库提交历史彼此独立，但测试仓库根提交 `dfe9419` 的文件树与主站提交 `ad82397` 完全相同；以这两个等价快照作为人工三方合并基线，而不是使用空树合并无关历史。
4. 冲突按文件逐项审查：保留测试服务器的 PR1、PR2 和视频续跑行为，同时吸收主站新增功能、修复及部署结构。
5. 主站从等价基线到 `fde5187` 共改变 14 个路径；其中 12 个 XAI 视频路径与测试分支最终内容完全相同，只需把主站独有的 `CLAUDE.md` 更新和 `deploy/setup-dev-server.sh` 纳入合并提交，并用文件级差异命令再次验证该分类。
6. 完整测试通过后，将集成分支推送到 `LU-003/huangque-test-server`。
7. 测试服务器的运行目录以分离 HEAD 指向已验证提交，使部署版本可复现，也避免工作分支被运行目录占用。

不采用文件覆盖，因为文件覆盖会丢失 Git 历史并可能静默撤销测试服务器定制。不只挑选主站最近两次提交，因为这可能漏掉双方分叉后更早的主站变化。

## 数据与密钥保护

以下内容不得从主站复制或覆盖：

- `*.db` 数据库，包括用户、点数、任务和后台配置数据。
- 生成产物、上传文件、视频、音频、图片和缓存目录。
- 主站生产密钥、Cookie、Token、证书和 xray 客户端配置。
- `/etc/huangque-test/` 内现有测试环境值。

可以合入 Git 中的环境变量示例、变量名称、部署脚本和服务单元定义。若主站新增必需变量，先检查测试环境是否已配置；缺值时停止部署并报告，不以空值启动服务，也不从主站复制生产值。

## Nginx、systemd 与依赖

- 主站 Nginx 和 systemd 文件只作为结构来源，测试服务器继续使用 `huangque-test-*` 服务名、`/opt/huangque-test-server` 路径、测试端口和 HTTP 入口。
- 应用配置前生成差异并备份当前 `/etc/nginx/` 与 `/etc/systemd/system/huangque-test-*` 相关文件。
- 只安装合并后代码明确需要且测试服务器缺少的依赖。
- 修改 systemd 单元后必须执行 `daemon-reload`；只重启实际受影响的服务。
- 纯前端变化通过 Git 工作目录立即生效，不进行无关后端重启。

## 冲突处理原则

1. 业务行为冲突：优先保留测试服务器已经验证的 PR1、PR2 和视频续跑行为，再手工移植主站新增逻辑。
2. 测试冲突：保留双方有效测试，更新过期断言，但不得为了通过测试删除覆盖范围。
3. 部署路径冲突：使用测试服务器路径、服务名和端口。
4. 数据迁移冲突：只运行向后兼容、可重复执行的 schema 初始化；部署前备份数据库，不复制主站数据。
5. 无法明确判断的冲突：停止合并并报告，不自行选择可能导致数据或功能丢失的一侧。

- `git diff --check`
- 仓库完整 Python 测试套件
- 受影响的 JavaScript/Node 测试

- Nginx 配置检查
- 必需环境变量名称与非空检查，但日志不得输出密钥值
- 数据库和生成产物目录未进入 Git 差异

- 所有 `huangque-test-*` 服务及 Nginx 为 active。
- 后端端口只监听回环地址。
- `/api/auth/health` 与 `/api/gen/health` 成功。
- 公网 `http://8.138.143.64/` 和受影响页面返回 HTTP 200。
- PR1、PR2 画布静态资源版本正确。
- XAI 视频续跑相关测试和服务日志无启动错误。
- Git 工作目录干净，HEAD 等于记录的部署提交。

## 发布与回滚

发布前记录当前提交 `2605cc5c494ca78e82edfe83f7afb47d00326839`，备份受影响配置和数据库。新版本通过全部部署前门禁后，切换运行目录到已验证提交，再按依赖顺序重启受影响服务。

任一关键部署后检查失败时：

1. 把 `/opt/huangque-test-server` 切回 `2605cc5c494ca78e82edfe83f7afb47d00326839`。
2. 恢复本次修改过的 Nginx/systemd 配置。
3. 执行 `daemon-reload` 并重启受影响服务。
4. 再次运行完整环境和 HTTP 健康检查。
5. 保留失败集成分支和日志用于排查，不强推或删除历史。
