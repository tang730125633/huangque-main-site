# 短剧策划功能主站合入设计

## 目标

从主站最新 `main` 出发，仅合入画布中的短剧策划功能，并补齐主站要求的资源上限、分页、删除、组合校验和扣点一致性。PR 不携带测试仓库历史，也不包含测试服务器部署或本地代理配置。

## 范围

本 PR 包含：

- 短剧项目的创建、列表、详情、编辑、软删除和阶段确认。
- 短剧 AI 策划任务的报价、付费提交、恢复、结果应用和画布工作区。
- 短剧项目、策划任务、画布交互及共享路由的自动化测试。
- 短剧接口文档和画布静态资源版本戳。

本 PR 明确不包含：

- `deploy/test-server/`、测试服务器 Nginx/systemd 配置、服务器地址和服务路径。
- `scripts/dev_proxy.py`、`scripts/dev_local.sh` 等本地测试代理能力。
- 测试账号、测试数据库、真实凭证、密钥和服务器专属 `.env`。
- 与短剧无关的历史同步、生产部署迁移和测试环境设计文档。

## 项目生命周期与容量

- 每个用户最多保留 50 个未删除短剧项目，配置项为 `HQ_SHORT_DRAMA_MAX_PROJECTS_PER_USER`，默认值 50；配置非法时采用默认值。
- 创建项目时在同一数据库写事务内统计 `deleted=0` 的项目数。达到上限返回 HTTP 429，错误码 `short_drama_project_cap`，响应包含 `max_projects`。
- 项目列表接口使用 `page` 和 `page_size`，默认分别为 1 和 20；`page_size` 最大为 50。非法、布尔值、零或负数返回 HTTP 400。
- 列表返回 `items`、`page`、`page_size`、`total` 和 `total_pages`。`items` 只包含项目摘要，不加载角色、剧本版本和分镜；扣点按当前页项目一次聚合。查询只读取当前用户且 `deleted=0` 的项目，并按 `updated_at DESC, id DESC` 稳定排序。
- 删除使用 `POST /api/gen/short-drama/project/delete`，请求体包含 `project_id` 和 `revision`。后端按用户、版本号和未删除状态执行软删除，并递增版本号；重复删除按不存在处理，不暴露其他用户的项目。存在已扣点但尚未应用或退款的策划任务时返回 `short_drama_unapplied_paid_job`，禁止删除。
- 软删除后项目不再出现在列表、详情、恢复任务和更新接口中，并立即释放一个项目名额。关联任务和内容保留用于账务审计，不执行物理级联删除。
- 每个项目最多 20 个角色、每版剧本最多 120 条台词、最多保留 20 个剧本版本；前后端执行同一上限。

## 时长与镜头组合约束

- 目标时长只允许 30、45、60 秒；镜头数只允许 6–10 个；单镜头只允许 5 或 10 秒。
- 合法组合必须满足 `5 × 镜头数 <= 目标时长 <= 10 × 镜头数`。例如 30 秒只允许 6 镜，45 秒允许 6–9 镜，60 秒允许 6–10 镜。
- 同一个后端校验函数用于项目创建、项目设置修改、策划提交和策划结果应用。
- 部分更新时，后端先读取数据库中的当前时长与镜头数，再与请求中的新值合并校验，禁止只校验单个字段。
- 画布表单根据目标时长过滤可选镜头数，并在提交前执行相同约束；后端仍是最终权威。

## 扣点与展示一致性

- `jobs` 表继续作为实际扣点任务的事实源。短剧累计已用点数按当前用户和项目绑定的短剧策划任务求和：`cost > 0` 且 `refunded != 1` 的任务计入。
- `pending`、`running`、`done` 任务均已实际扣点，应立即计入项目 `spent_points`；处于退款待确认状态 `refunded=2` 时仍计入，只有明确退款成功 `refunded=1` 后才移除。
- 应用策划结果只登记 `short_drama_applied_jobs` 并更新内容，不再二次增加 `spent_points`。
- 项目详情和预算校验共用同一扣点聚合函数，避免页面展示与预算判断采用不同口径。
- 相同任务通过幂等恢复或重复应用时不得重复累计；退款后再次读取项目必须反映最新净扣点。
- 保留现有 `short_drama_projects.spent_points` 列以兼容已有数据库，但新代码不再把它作为账务事实源，也不要求破坏性迁移。

## 安全与并发

- 所有接口复用主站鉴权和浏览器变更安全校验；项目查询与修改始终绑定当前用户名。
- 创建上限检查和插入在 `BEGIN IMMEDIATE` 事务内完成，避免并发请求绕过上限。
- 修改和删除使用 `revision` 乐观锁；冲突返回 HTTP 409。删除与付费策划提交共用提交锁，并在数据库写事务内检查未应用付费任务，避免生成出已扣点的孤立任务。
- 策划提交继续使用 Idempotency-Key、付费任务原子创建、队列失败退款和恢复逻辑。
- 请求体字段采用白名单，未知字段、类型强制转换和跨用户资源引用均拒绝。
