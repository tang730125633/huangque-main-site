# 本地前端连接测试服务器后端：设计说明

## 背景

当前 `scripts/dev_local.sh` 在本机启动 `content_api.py` 和纯静态 HTTP 服务器。工作台前端使用同源相对路径请求 `/api/auth/*` 与 `/api/gen/*`，但静态服务器不会代理 API，导致登录请求表现为“网络错误”。仅启动本地认证服务也不能满足需求，因为本地没有测试服务器的账号、点数、模型密钥和第三方 API 配置。

本方案让前端文件继续从本地加载，同时把 API 请求代理到测试服务器。这样可以实时验证本地页面修改，并复用测试服务器上的真实账号、点数和图片/视频生成能力，而不把服务器密钥或数据库复制到开发电脑。

## 目标

- `http://127.0.0.1:8097/workbench/*.html` 始终读取本地 `site/` 文件。
- 同源 `/api/*` 请求转发到显式配置的测试服务器上游。
- 登录 Cookie 能在本机 HTTP 回环地址下正常保存和发送。
- 使用测试服务器的真实账号、点数、任务、资产和第三方 API 配置。
- 代理仅监听 `127.0.0.1`，且不记录密码、Cookie、Authorization 或请求正文。
- 启动信息明确提示：生成操作会消耗测试服务器的真实点数和第三方 API 额度。

## 非目标

- 不复制服务器的 `*.env`、数据库、Cookie、API Key 或用户数据到本地。
- 不在本地复刻完整生产/测试后端服务集群。
- 不绕过登录、点数扣减、权限、限流或内容安全检查。
- 不自动触发图片、视频等付费生成任务。
- 不修改测试服务器配置或部署文件。

## 方案比较

### 方案 A：本地同源开发代理（采用）

同一个本地端口同时提供静态文件和 API 代理。浏览器看到的所有请求均为同源请求，测试服务器继续负责账号、点数与生成任务。

优点：密钥不离开服务器；前端本地修改即时生效；登录和生成链路接近测试环境。缺点：真实操作会修改测试服务器数据并消耗额度；开发时依赖网络与测试服务器可用性。

### 方案 B：复制服务器配置并在本地运行全部服务（拒绝）

需要复制密钥、数据库和大量运行依赖，存在泄密、数据漂移和误操作风险，且难以保持与服务器一致。

### 方案 C：浏览器直接跨域调用测试服务器（拒绝）

需要修改前端 API 基址，并处理 CORS、Cookie Domain、Secure 和 SameSite 等问题；容易产生只在开发环境存在的分支逻辑。

## 架构与数据流

```text
浏览器 http://127.0.0.1:8097
  ├─ /workbench/*、/assets/*、其他静态路径
  │    └─ 本地仓库 site/
  └─ /api/*
       └─ 测试服务器上游
            ├─ /api/auth/*：登录、Cookie、账号、点数
            └─ /api/gen/*：任务、资产、图片和视频生成
```

代理上游必须通过启动参数或环境变量显式指定，不把密钥写入仓库。开发代理设置正确的上游 `Host`，转发请求方法、查询参数、正文和必要请求头，并过滤 `Connection`、`Transfer-Encoding` 等逐跳头。响应状态码、正文和业务响应头原样返回。

## Cookie 处理

测试服务器的认证 Cookie 面向服务器域名及 HTTPS。代理返回给本地浏览器时：

- 删除上游 `Domain` 属性，使 Cookie 绑定到 `127.0.0.1`。
- 仅在回环地址的 HTTP 开发模式下删除 `Secure` 属性。
- 保留 `HttpOnly`、`SameSite`、`Path`、有效期和其他安全属性。
- 不在日志中输出 `Set-Cookie`、`Cookie` 或认证令牌。

该转换只发生在本地代理响应中，不修改服务器 Cookie 或认证实现。

## 安全边界

- 服务只绑定 `127.0.0.1`，禁止绑定 `0.0.0.0`。
- 上游只接受启动时配置的固定 `http://` 或 `https://` 地址，浏览器请求不能动态指定上游，避免开放代理和 SSRF。
- 静态文件路径必须限制在本地 `site/` 根目录，拒绝目录穿越。
- 日志只记录方法、脱敏后的路径、状态码和耗时，不记录查询参数中的敏感值、请求正文或认证头。
- 页面上的生成、充值、改密、删除等操作都是真实测试服务器操作；代理不提供任何模拟或绕过。

## 错误处理

- 上游不可达或超时时返回明确的 `502`/`504` JSON，不伪装成业务登录失败。
- 本地静态文件不存在时返回 `404`。
- 长轮询和生成任务查询使用高于普通 API 的读取超时，避免代理提前中断正常任务。
- 客户端断开时终止对应转发，不影响代理继续服务其他请求。
- 启动时若上游未配置、格式非法或端口已占用，立即退出并给出可操作错误。

## 验证标准

自动化测试覆盖：

- 静态页面从指定本地目录返回。
- `/api/auth/*` 和 `/api/gen/*` 路由到固定上游，方法、查询参数和正文保持不变。
- Cookie 转换仅删除本地 HTTP 不兼容的 `Domain`/`Secure`，保留 `HttpOnly`、`SameSite` 和 `Path`。
- 逐跳头被过滤，敏感字段不进入日志。
- 目录穿越、非法上游和上游失败返回预期错误。

集成验证不触发付费生成：

1. 本地工作台页面返回 HTTP 200。
2. 经本地代理访问 `/api/auth/health` 返回测试服务器认证服务健康响应。
3. 用户在浏览器手动登录后，`/api/auth/me` 返回真实 `qilin` 账号与点数。
4. 图片和视频页面能读取服务器配置、套餐和历史任务。
5. 是否实际发起一次生成由用户手动决定，因为该操作会消耗真实点数和第三方额度。

## 运行与停止

开发启动命令应同时给出本地地址、上游地址和真实额度警告。停止命令只终止本地代理，不停止或重启任何服务器服务。代理产生的临时日志和 PID 信息不进入 Git。
