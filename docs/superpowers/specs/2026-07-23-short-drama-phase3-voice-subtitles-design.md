# 短剧第三阶段：配音字幕工作台 PRD 与设计规格

## 1. 文档信息

- 版本：1.0
- 日期：2026-07-23
- 对应阶段：`voice_review`
- 前置阶段：短剧第二阶段关键帧工作区
- 后续阶段：`video_review`
- 推荐方案：逐句音频资产 + 逐镜字幕编排

## 2. 背景

短剧第二阶段已经实现关键帧候选生成、版本管理、锁定和
`stills_review -> voice_review`。当前系统只有“配音字幕”阶段枚举和跳转入口，进入后仍显示
只读的关键帧工作区；短剧专用配音生成、字幕时间轴、锁定验收及
`voice_review -> video_review` 尚未实现。

系统现有通用配音能力能够提供公共音色、个人音色、TTS 生成、异步任务、点数扣减和音频资产，
视频模块也有最终烧录字幕的能力。本阶段复用这些底层能力，但单独建立短剧逐句资产和逐镜时间轴，
不把短剧业务规则写入通用音频模块。

## 3. 已确认的产品决策

1. 每条角色台词或旁白独立生成音频。
2. 自动生成句级字幕时间码，用户可以编辑字幕文本及起止时间。
3. 按镜头连续试听当前音频版本，并同步高亮字幕。
4. 短剧工作台只选择和试听现有公共/个人音色，不新增声音克隆入口。
5. 本阶段只处理角色台词和旁白，不包含背景音乐、环境音、音效或最终混音。
6. 全部镜头配音字幕锁定后，才能进入 `video_review`。

## 4. 目标与成功标准

### 4.1 产品目标

让已经完成关键帧确认的短剧项目，在同一短剧工作台内完成角色音色分配、逐句配音、字幕校准、
逐镜试听和锁定验收，为后续视频生成提供稳定、版本化且可恢复的输入资产。

### 4.2 成功标准

- 能从 `stills_review` 正确进入可操作的配音字幕工作台。
- 能根据已确认的角色、剧本和分镜建立稳定的台词快照。
- 能选择已有音色，逐句生成真实配音并记录实际时长。
- 每次付费生成都经过服务端报价和用户确认。
- 单句失败、重试和换版不影响其他句子。
- 字幕文本和句级时间码可编辑，并由服务端权威校验。
- 能按镜头连续试听，并根据播放进度高亮字幕。
- 刷新页面或服务重启后可以恢复任务、版本和退款状态。
- 全部镜头锁定前不能进入视频阶段；全部锁定后只能推进一次。
- 关键帧工作区、通用配音页面和现有音色功能无回归。

## 5. 用户流程

```text
关键帧全部锁定
-> 进入配音字幕
-> 检查角色默认音色
-> 编辑发音文本或单句参数
-> 获取报价并确认
-> 逐句/逐镜/全剧生成
-> 试听、重试或选择历史版本
-> 自动生成并编辑字幕时间码
-> 按镜头连续试听
-> 锁定镜头
-> 全部镜头锁定
-> 确认进入视频生成
```

## 6. 功能需求

### 6.1 台词快照

进入 `voice_review` 时，系统根据当前已确认的剧本版本和分镜关系建立配音快照：

- 台词保持对原 `dialogue_line_id` 的引用。
- 每句记录所属项目、镜头、角色和镜头内顺序。
- 支持 `dialogue` 与 `narration` 两种句子类型。现有剧本结构要求每句都引用角色，因此首版将
  `character_key=narrator` 作为明确的旁白角色约定；配音阶段不临时新增原剧本之外的旁白句。
- 没有台词的镜头允许保持静音。
- 原剧本文本同时成为默认发音文本和默认字幕文本。
- 进入配音阶段后，不直接修改原剧本；所有调整只写入配音快照。

每句维护三类文本：

- `source_text`：进入阶段时的原文快照，不可编辑。
- `speech_text`：提供给 TTS 的发音文本，可为数字、英文和人名调整读法。
- `subtitle_text`：最终展示文本，可以与发音文本不同。

### 6.2 音色分配

- 默认读取角色的 `voice_key` 和 `voice_settings`。
- 音色来源只包括已有公共音色和当前用户个人音色。
- 支持试听音色样音。
- 支持为角色统一更换默认音色。
- 支持单句覆盖角色默认音色。
- 本阶段不提供上传样音和声音克隆。
- 已锁定镜头不能修改音色，必须先解锁。

### 6.3 配音参数

角色默认参数和单句覆盖参数均包括：

- 音色 `voice_key`。
- 语速 `speed`，范围沿用通用音频模块的 `0.5-2.0`。
- 音调 `pitch`，范围沿用通用音频模块的 `-12-12`。
- 音量 `volume`，范围沿用通用音频模块的 `-50-100`。

所有参数必须由服务端重新规范化和校验，不能信任前端提交值。

### 6.4 配音生成

工作台提供：

- 生成当前句。
- 生成当前镜头所有未完成句子。
- 批量生成全剧所有未完成句子。

付费提交顺序固定为：

```text
校验请求 -> 内容安全 -> 服务端实时报价 -> 用户确认 -> 幂等检查
-> 项目预算与用户点数检查 -> 建立扣点尝试 -> 创建任务 -> 关联句子
-> 入队 -> 轮询/恢复 -> 保存版本 -> 结算或退款
```

批量操作在产品层面只确认一次，但后端仍以单句为独立任务。每句使用独立报价令牌、幂等键、
任务关联和退款状态，允许部分成功并支持单句重试。

### 6.5 音频版本

每句支持：

- 查看当前版本和全部历史版本。
- 试听任意成功版本。
- 将匹配当前输入的历史版本设为当前版本。
- 重新生成并追加新版本。
- 查看版本的发音文本、音色、参数、时长、费用、状态和失败原因。

发音文本、音色、语速、音调或音量共同形成 `input_hash`。这些字段变化后，如果当前版本的
`input_hash` 不再匹配，该版本立即标记为过期，镜头自动解锁且不能重新锁定。只修改字幕文本或
字幕时间码不会使音频版本过期。

选择版本、编辑字幕、锁定和解锁不扣点，只有真实生成音频扣点。

### 6.6 音频实际时长

- TTS 成功后由服务端使用 `ffprobe` 获取权威时长。
- 数据库存储整数毫秒，不能使用浏览器上报时长。
- 探测暂时失败时标记 `metadata_pending` 并自动重试。
- 未取得权威时长的版本不能锁定，但不盲目重新生成或重复扣费。

### 6.7 自动字幕时间码

首版采用一句配音对应一条字幕，不提供逐字卡拉 OK 时间码。

首次获得有效音频时长后按以下规则排布：

```text
第一句 start_ms = 0
每句 end_ms = start_ms + duration_ms
下一句 start_ms = 上一句 end_ms + 150ms
```

如果最终结束时间超过镜头时长：

- 保留所有已生成音频和初始时间码。
- 镜头显示“时长冲突”。
- 不自动截断、压缩或调速。
- 用户通过修改发音文本、语速、版本或时间轴解决。

### 6.8 字幕编辑

每条字幕允许修改：

- 字幕文本。
- 开始时间。
- 结束时间。
- 是否显示。
- 在同一镜头内的排序。

服务端校验：

- `start_ms >= 0`。
- `end_ms > start_ms`。
- `end_ms` 不超过镜头时长。
- 同一镜头字幕按排序单调前进，不允许重叠。
- 隐藏字幕可以为空，但对应配音仍可保留。
- 修改字幕不触发重新配音。

### 6.9 镜头试听

- 按时间轴播放当前镜头的所有当前音频版本。
- 播放时高亮当前字幕。
- 支持播放、暂停、重新开始和拖动进度。
- 总进度以镜头时长为准。
- 切换镜头或关闭工作台时停止全部音频和计时器。
- 首版由浏览器调度多条音频，不生成新的镜头混音文件。

### 6.10 镜头锁定与解锁

有台词的镜头只有满足全部条件才允许锁定：

- 每条需要配音的句子都有成功的当前版本。
- 当前版本的 `input_hash` 与当前发音输入一致。
- 每个当前版本都有权威 `duration_ms`。
- 字幕时间轴通过服务端校验。
- 配音和字幕没有超过镜头时长。
- 不存在执行中或退款待确认的关联任务。

没有台词的静音镜头可以直接锁定。锁定后禁止修改文本、音色、参数、版本和时间轴，但允许试听和
查看历史版本。用户可以主动解锁，解锁不扣点。

### 6.11 阶段确认

只有所有镜头均已锁定，服务端才允许：

```text
voice_review -> video_review
```

确认阶段时服务端重新校验项目、revision、全部句子、当前版本、字幕时间轴、镜头锁定状态和执行中
任务。确认不扣点，只允许成功一次；阶段推进后配音字幕资产只读，供视频阶段引用。

## 7. 页面模块

沿用关键帧工作区的三栏布局。

### 7.1 左侧镜头栏

显示镜头序号、时长、角色、台词数量、生成进度、字幕状态和异常。状态包括：静音、待生成、
生成中、待调整、失败、可锁定和已锁定。支持筛选异常、未完成和已锁定镜头。

### 7.2 中间台词与字幕区

显示当前镜头的台词列表、角色、音色、发音文本、字幕文本、语音参数、当前音频、历史版本、
字幕起止时间、单句试听、重新生成和选版。底部显示镜头时间轴、播放进度和字幕高亮。

### 7.3 右侧生成控制台

显示实时价格、项目预算、累计已用、任务预留、任务进度、失败和退款状态。提供生成当前句、
生成当前镜头、批量生成全剧未完成句子、保存时间轴、锁定/解锁镜头和确认进入视频阶段。

## 8. 非目标

- 在短剧工作台内克隆声音。
- 背景音乐、环境音、音效和最终混音。
- 自动情绪导演或 AI 表演控制。
- 逐字级字幕、卡拉 OK、字幕字体、动画和成片烧录。
- 视频片段生成。
- FFmpeg 最终合成和正式导出。
- 修改已经确认的原剧本和分镜。
- 与配音字幕无关的画布或公共服务重构。

## 9. 方案比较与选择

### 9.1 方案 A：逐句资产 + 逐镜编排（采用）

优点是支持多角色、单句重试、独立换音色、精确字幕、历史版本和失败隔离；也能给后续视频阶段
提供稳定的逐句素材。代价是数据表和工作区状态比整段生成更多。

### 9.2 方案 B：每镜头一次生成整段配音（不采用）

接口和任务数量较少，但多角色切换、单句返工、字幕对齐和失败恢复较弱。

### 9.3 方案 C：整部短剧总音轨（不采用）

整体试听连贯，但局部修改、并发、重试、版本管理和多角色控制复杂，不适合作为当前阶段的最小
可靠交付。

## 10. 总体技术架构

```text
canvas-short-drama.js（阶段路由）
        |
        v
canvas-short-drama-voice.js（配音字幕工作区）
        |
        v
short_drama_voice.py（领域规则、快照、版本、时间轴、锁定）
        |
        +--> audio.py（音色、TTS、音频时长）
        +--> core.py / jobs_store（异步任务、幂等、扣点、退款）
        +--> SQLite（短剧配音专用表）
```

模块原则：

- `canvas-short-drama-production.js` 继续只负责关键帧。
- `canvas-short-drama-voice.js` 不直接操作全局画布状态。
- `short_drama_voice.py` 不实现具体 TTS 提供商逻辑。
- `audio.py` 不感知短剧项目。
- `core.py` 只负责 HTTP、通用任务和扣点编排，不承载字幕业务规则。

## 11. 数据设计

使用配音专用表，不扩展当前只支持 `still` 的关键帧资产表，避免重建 SQLite CHECK 约束和破坏
已经稳定的关键帧任务路径。

### 11.1 `short_drama_voice_shots`

- `shot_id TEXT PRIMARY KEY`
- `project_id TEXT NOT NULL`
- `locked INTEGER NOT NULL DEFAULT 0 CHECK (locked IN (0,1))`
- `timeline_revision INTEGER NOT NULL DEFAULT 1`
- `created_at INTEGER NOT NULL`
- `updated_at INTEGER NOT NULL`

外键和触发器必须保证镜头属于对应项目。

### 11.2 `short_drama_voice_lines`

- `id TEXT PRIMARY KEY`
- `project_id TEXT NOT NULL`
- `shot_id TEXT NOT NULL`
- `dialogue_line_id TEXT`
- `line_type TEXT NOT NULL CHECK (line_type IN ('dialogue','narration'))`
- `sort_order INTEGER NOT NULL`
- `character_key TEXT NOT NULL DEFAULT ''`
- `source_text TEXT NOT NULL`
- `speech_text TEXT NOT NULL`
- `subtitle_text TEXT NOT NULL`
- `subtitle_visible INTEGER NOT NULL DEFAULT 1 CHECK (subtitle_visible IN (0,1))`
- `voice_key TEXT NOT NULL`
- `speed REAL NOT NULL DEFAULT 1.0`
- `pitch INTEGER NOT NULL DEFAULT 0`
- `volume INTEGER NOT NULL DEFAULT 0`
- `current_version INTEGER`
- `start_ms INTEGER`
- `end_ms INTEGER`
- `input_hash TEXT NOT NULL`
- `created_at INTEGER NOT NULL`
- `updated_at INTEGER NOT NULL`
- `UNIQUE(project_id, shot_id, sort_order)`

### 11.3 `short_drama_voice_versions`

- `id TEXT PRIMARY KEY`
- `voice_line_id TEXT NOT NULL`
- `version INTEGER NOT NULL`
- `job_id INTEGER NOT NULL UNIQUE`
- `audio_file TEXT NOT NULL DEFAULT ''`
- `audio_url TEXT NOT NULL DEFAULT ''`
- `duration_ms INTEGER`
- `speech_text TEXT NOT NULL`
- `voice_key TEXT NOT NULL`
- `settings_json TEXT NOT NULL`
- `input_hash TEXT NOT NULL`
- `cost INTEGER NOT NULL DEFAULT 0 CHECK (cost >= 0)`
- `status TEXT NOT NULL CHECK (status IN ('metadata_pending','done','failed'))`
- `error TEXT NOT NULL DEFAULT ''`
- `created_at INTEGER NOT NULL`
- `UNIQUE(voice_line_id, version)`

### 11.4 `short_drama_voice_jobs`

保存用户、项目、镜头、句子、通用 `job_id`、幂等键、报价、状态、错误、退款状态和时间。每个通用
任务只能关联一个配音句子；`UNIQUE(username, idempotency_key)` 防止重复提交。

### 11.5 `short_drama_voice_quotes`

保存报价令牌、用户、项目、句子、请求摘要、费用、过期时间、消费幂等键和关联任务。报价有效期
固定为 300 秒；提交时请求摘要必须与报价完全一致。

### 11.6 `short_drama_voice_charge_attempts`

保存付费提交的恢复状态：

```text
accepted -> charged -> linked -> done
                   \-> refund_pending -> refunded
```

它用于恢复扣点后进程退出、入队失败、关联失败和服务重启，避免出现扣点成功但短剧工作区找不到
任务的情况。

## 12. 工作区初始化与兼容

正常路径在 `stills_review -> voice_review` 的事务中建立配音快照。为兼容在本功能发布前已经处于
`voice_review` 的项目，首次读取时允许在事务中执行一次幂等补建。

补建规则：

- 已存在任意配音工作数据时不重新覆盖。
- 每个镜头只创建一个 `voice_shots` 行。
- 每个有效台词引用只创建一条 `voice_lines`。
- 没有台词的镜头不创建空句子。
- 后续读取不根据原剧本重新同步，防止覆盖用户已经调整的配音快照。

## 13. API 设计

### 13.1 获取工作区

`GET /api/gen/short-drama/voice?project_id=...`

返回项目阶段、revision、预算、镜头、逐句文本、音色参数、当前版本、历史版本、字幕时间码、任务、
退款状态以及每个镜头不能锁定的具体原因。

### 13.2 获取音色

复用 `GET /api/gen/audio/voices`，短剧模块不复制音色管理接口。

### 13.3 保存单句内容与参数

`POST /api/gen/short-drama/save-voice-line`

请求包含 `project_id`、`revision`、`line_id`、发音文本、字幕文本、字幕显示状态、音色和语音参数。
服务端检测发音输入变化，更新 `input_hash` 并自动解锁镜头。

### 13.4 批量更新角色音色

`POST /api/gen/short-drama/apply-character-voice`

请求包含项目、revision、`character_key`、音色和语音参数。服务端在一个事务内更新该角色所有未锁定
句子的有效参数、重算 `input_hash` 并解锁受影响镜头；存在锁定镜头时不修改锁定数据，并在响应中
明确返回被跳过的镜头。

### 13.5 保存镜头时间轴

`POST /api/gen/short-drama/save-voice-timeline`

一次提交当前镜头全部句子的排序、`start_ms`、`end_ms` 和显示状态。服务端以一个事务重新校验和
保存，避免逐条写入产生不可见的中间冲突。

### 13.6 配音报价

`POST /api/gen/short-drama/voice-quote`

接受一个或多个 `line_id`，返回每句规范化参数、费用、报价令牌、合计点数、用户点数、项目预算、
可提交项和跳过原因。

### 13.7 提交单句配音

`POST /api/gen/short-drama/generate-voice`，必须提供 `Idempotency-Key`。

一次只生成一句。镜头和全剧批量由前端根据聚合报价，在用户一次确认后受控并发提交多个独立请求。

### 13.8 选择历史版本

`POST /api/gen/short-drama/select-voice-version`

只能选择当前用户项目中的成功版本，且版本 `input_hash` 必须匹配当前发音输入。

### 13.9 锁定或解锁镜头

`POST /api/gen/short-drama/set-voice-shot-lock`

锁定条件由服务端重新计算，不接受前端传入的完成状态。

### 13.10 阶段确认

沿用 `POST /api/gen/short-drama/confirm-stage`。当当前阶段为 `voice_review` 时委托配音领域模块检查
并推进到 `video_review`。

## 14. 前端状态与播放

句子状态：

## 16. 权限、安全与并发

每个写接口必须校验：登录状态、初始密码状态、画布访问、项目和关联对象归属、revision、当前阶段、
精确字段白名单、文本长度、音色与参数范围、报价令牌、请求摘要、幂等键、项目预算、用户点数和
内容安全。

无权访问和不存在的项目返回相同外部信息，避免泄露项目存在性。字幕、台词和错误信息统一转义，
不能拼接为未转义 HTML。多标签页使用项目 revision 乐观锁；发生冲突后前端冻结写操作并要求刷新。

用户主动保存单句、批量应用角色音色、保存时间轴、选版、锁定和解锁时都必须比较并递增项目
revision。异步任务从 `pending` 进入终态及元数据补全不递增项目 revision，避免后台轮询持续制造编辑
冲突；这些变化通过工作区快照中的任务/版本状态刷新。阶段确认仍以最新项目 revision 和服务端生产
状态共同判断。

批量生成使用受控并发，并继续受通用用户活跃任务上限约束。服务关闭期间不接收新付费任务，只允许
终态、退款和已关联任务恢复。

## 17. 错误处理

- `401`：登录失效，停止提交。
- `403`：无编辑权限或必须修改初始密码。
- `404`：项目不存在或无权访问。
- `409 revision_conflict`：冻结写操作并要求刷新。
- `409 idempotency_conflict`：相同幂等键用于不同请求。
- `402`：用户点数或项目预算不足。
- `400`：时间轴、音色、文本或配音参数不合法。
- `429`：超过用户并发任务限制。
- `503`：音频服务、内容安全服务不可用或系统关闭中。

网络超时后保留原幂等键，先查询工作区和原任务，不直接创建新请求。

## 18. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 配音超过镜头时长 | 保留结果并标记冲突，禁止锁定，不自动截断 |
| 修改文本后误用旧音频 | 使用 `input_hash` 判断过期并自动解锁 |
| 批量生成部分失败 | 每句独立任务、幂等键和退款状态 |
| 扣点后进程退出 | charge attempt 状态机和启动恢复 |
| `ffprobe` 暂时失败 | `metadata_pending` 自动重试，不重复生成 |
| 音色被删除或不可用 | 保存参数快照，提交前重新校验并要求重选 |
| 多标签页同时编辑 | revision 乐观锁和冲突冻结 |
| 音频跨域播放失败 | 发布前验证 COS CORS，必要时使用鉴权文件代理 |
| 时间轴浮点误差 | 接口和数据库统一使用整数毫秒 |
| 字幕内容注入 | 服务端长度限制，前端统一转义 |
| 新功能破坏关键帧 | 独立模块、独立表和关键帧回归测试 |
| 历史项目没有快照 | 首次读取事务内幂等补建 |
| 页面关闭后轮询泄漏 | 销毁工作区时取消轮询、计时器和音频 |
| 同时生成任务过多 | 前端受控并发，后端沿用用户任务上限 |

## 20. 分阶段 PR 顺序

### PR 3-0：PRD 与实施计划

只交付确认后的设计规格、实施计划、数据结构和接口契约，不修改业务代码。验收要求是范围无歧义、
没有占位内容，并且后续每个 PR 都有独立验收门槛。

### PR 3-A：数据与只读工作区

交付配音专用表、台词快照、历史项目补建、获取工作区接口、阶段路由、前端只读三栏骨架和现有音色
列表接入。暂不包含付费生成、时间轴拖动和阶段推进。

验收：`voice_review` 项目可以打开；镜头、台词、角色和音色映射正确；刷新后数据一致；关键帧无回归。

### PR 3-B：单句配音与版本

交付音频实际时长、单句报价、幂等提交、预算和点数检查、任务恢复、退款状态、单句试听、重试和
历史版本选择。

验收：一条台词可以完成报价、确认、生成、试听和换版；双击及网络重试不重复扣点；服务重启后可恢复；
修改发音输入后旧版本正确过期。

### PR 3-C：镜头与全剧批量

交付当前镜头生成、全剧未完成句子批量生成、受控并发、镜头和全剧进度以及单句失败隔离。

验收：多角色镜头可以连续完成；部分失败不破坏成功版本；取消确认不提交；预算和任务上限正确执行。

### PR 3-D：字幕时间轴与试听

交付自动时间码、字幕编辑、服务端时间轴校验、镜头连续试听、字幕高亮、进度拖动和时长冲突提示。

验收：字幕时间码使用实际音频时长；越界和重叠不能保存或锁定；播放、暂停、拖动和镜头切换正确；
不生成最终混音文件。

### PR 3-E：锁定、阶段推进与加固

交付镜头锁定/解锁、全部镜头检查、`voice_review -> video_review`、只读模式、并发/关闭/恢复/退款
边界测试和测试环境真实冒烟。

验收：未完成项目无法推进；全部锁定后只能推进一次；推进后资产只读；全部 CI 与回归通过。

## 21. 完成定义

本阶段只有同时满足以下条件才算完成：

- 用户能够为每条台词选择已有音色并生成真实配音。
- 配音支持单句重试、历史版本、刷新和服务重启恢复。
- 字幕文本和句级时间码可编辑并通过服务端校验。
- 每个镜头可以连续试听并同步高亮字幕。
- 报价、预算、点数、幂等、失败和退款链路可核对。
- 所有镜头可以独立锁定和解锁。
- 全部镜头锁定后能够安全进入 `video_review`。
- 关键帧、通用配音和音色功能无回归。
