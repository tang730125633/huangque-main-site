# 工单 · 运营后台「近日报表」改为用户调用日志（ADMIN-5）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：admin（`server/admin_api.py`、`site/admin/index.html`）** —— 抢 `lock/admin`。
> 来自 kongli：后台"近日报表"（现在是按日期/状态汇总）改成**逐条用户调用日志**。

## 现状
运营后台接口管理页有「近日报表」区（前端 `trendBox`，约 348 行；后端 `job_stats` 返回 `trend` 按 日期/类型/状态/数量 **汇总**）。kongli 要改成**逐条调用日志**，看每一次用户调用的明细。

## 目标：逐条用户调用日志
把「近日报表」区替换为**用户调用日志**表格，**每行是一次调用**，按调用时间倒序，列：

| 列 | 数据源（`content_jobs.db` · jobs 表）| 说明 |
|---|---|---|
| **调用时间** | `created_at` | 格式化到分钟 `YYYY-MM-DD HH:mm` |
| **用户** | `username` | 哪个账号调用的 |
| **调用功能** | `kind` → 中文功能名 | 作图/配音/视频/换装/采集/获客/下载/文案 等（映射表）|
| **响应时间(耗时)** | `updated_at − created_at` | 人类可读（如 `1分30秒`/`45秒`），至少精确到分钟粒度 |
| **完成状态** | `status` → 中文 | 成功(done)/失败(error)/进行中(running)，配颜色（绿/红/灰）|
| **点数消耗** | `cost` | 该次调用扣的点数 |

## 改动
### 后端（`server/admin_api.py`）
- 新增（或改造）端点返回**逐条日志列表**，如 `GET /api/admin/call-logs?days=7&limit=200`：
  - 从 `content_jobs.db` 读 jobs：`SELECT username, kind, cost, status, created_at, updated_at FROM jobs WHERE created_at >= ? ORDER BY id DESC LIMIT ?`。
  - 每条算出**耗时** = `updated_at - created_at`（秒），一并返回。
  - `role=admin` 校验（复用 `_admin()`）；支持 days（近N天）和 limit（默认 200、上限如 500）。
  - 可保留原 `job_stats` 的汇总供「调用统计」区用，本单只替换「近日报表」区的数据来源。
- 若 overview 里也要带，扩 overview 返回或前端单独拉该端点均可。

### 前端（`site/admin/index.html`）
- 「近日报表」区标题改为「用户调用日志」，说明改为"每次调用的时间、功能、耗时、状态与点数消耗"。
- 表格渲染上面 6 列；耗时格式化（分/秒）、时间到分钟、状态中文+颜色、点数右对齐。
- 宽表加 `table-wrap`(overflow-x:auto) 保证窄屏可滚（沿用现有可读性风格）。
- 近 7 天 / 近 30 天 切换沿用现有 `days` 逻辑。

## 边界与安全
- 只改「近日报表」区 → 用户调用日志；「调用统计」（按能力成功/失败率汇总）保留不动。
- `role=admin` 门控；只读 jobs（不改任何数据）；不显密钥。
- 数据量大时靠 limit + 倒序，避免全表拉。

## 验收标准
1. 后台该区显示**逐条调用日志**：调用时间(到分钟)、用户、调用功能(中文)、响应时间(耗时)、完成状态(中文+色)、点数消耗。
2. 按调用时间倒序，近7/30天切换有效，limit 生效不卡。
3. 耗时正确（完成时间−调用时间）、状态中文+颜色、点数正确。
4. `role=admin` 才能看；非 admin 403。`py_compile` 通过、admin health 正常。

- 实测：管理员进后台看到用户调用日志逐条明细，各列正确。
