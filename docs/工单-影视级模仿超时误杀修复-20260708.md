# 工单 · 影视级模仿(motion)清道夫超时误杀修复

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》。
> **冲突组：A（`server/content_domains/**`）** —— 锁 `lock/A`。

## 背景
#405/#410给数字人口播/影视级模仿加了"直连HeyGen真身优先，失败回退泽龙中转"的逻辑，同时把motion的清道夫超时定为10分钟(kongli当时认为直连快)。

上线后实测数据(以#410部署时刻16:00:24为分界)：
- 直连前(relay-only历史24h)：34个任务，成功16个(47%)，平均耗时905秒
- 直连后(到当前)：27个任务，成功8个(30%)，平均耗时476秒

排查发现：
1. **直连HeyGen真身当前对motion几乎100%失败**（24h内14次尝试全部回退泽龙），换mihomo代理里3个可用节点实测全部超时——判断是HeyGen侧对代理/自动化流量的API请求做了限流或拦截，且观察到当天从"能连通"逐渐劣化到"频繁超时"，疑似请求量触发了HeyGen风控，而非节点本身问题
2. **泽龙中转本身正常完成motion任务，历史数据显示经常需要20-37分钟**（relay-only时期大量成功任务耗时1700-2200+秒）
3. **10分钟的清道夫超时完全不够**——大量原本会靠泽龙兜底成功的任务，被清道夫在还没跑完时就误判超时、标记失败、退点

kongli拍板：暂不改变路由优先级(继续直连优先+泽龙兜底)，但超时阈值必须修正以匹配泽龙真实完成时间。

## 改动
`server/content_domains/core.py`：`reaper()`函数里motion的超时阈值从600秒(10分钟)改为2400秒(40分钟)，与`tryon`使用相同的40分钟余量。

## 已验证
- `python3 -m unittest discover -s tests` 48/48通过
- `python3 -m py_compile` 通过

## 验收标准
1. 影视级模仿任务在直连失败→泽龙中转耗时20-37分钟内正常完成的，不再被清道夫误杀
2. 数字人口播(非motion)、其余kind的超时阈值不受影响

## 后续
- 直连HeyGen对motion的实际有效性建议持续观察，若长期0成功率，可考虑跳过直连直接走泽龙，省掉每次白等的时间（本次kongli决定暂不改路由优先级，只修超时）
