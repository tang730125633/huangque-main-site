# 工单 · 前端 XSS 面加固（#194 P1·安全）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：多前端页（`site/workbench/**`）+ F（nginx CSP）+ D（若 token 迁 httpOnly 动 auth）** —— 跨页大工程，**分阶段**、逐页抢对应 `lock/E-<页>`。
> ⚠️ 采集页渲染第三方(抖音/小红书)内容，是最高危 sink，优先。

## 问题（#194）
`hq_token` 存 localStorage(JS 可读)；`workbench/*.html` 有 **137 处 `innerHTML=`**，转义器多套(`esc/escHtml/escapeHtml`)、部分只转义引号；采集页把第三方**标题/作者/评论/URL** 直接拼进 HTML。任一处漏转义(尤其攻击者可控的采集内容)→ 注入脚本读 localStorage 偷 token → 账号(含 admin)接管。

## 目标：让第三方/用户内容无法注入脚本
### 阶段1（最高危先做）：采集页 + 统一转义器
- 抽一个**健壮 HTML 转义器**(转 `& < > " ' /`)，全站统一，废弃多套散落实现。
- 采集页(`collect.html`)所有渲染第三方内容处：**能 `textContent` 就不 `innerHTML`**；必须拼 HTML 的先过统一转义器。重点：标题/作者名/评论文本/URL/口播文案。
- 审计每个 `innerHTML=` sink：数据来源是否可控 → 可控必转义或改 textContent。

### 阶段2：CSP
- nginx 加 **Content-Security-Policy** 响应头。⚠️ 站点大量内联 `<style>`/`<script>`/`onclick`——严格 CSP 会全破。需先评估：要么允许 `'unsafe-inline'`(收益有限但先挡外部脚本源)，要么逐步把内联迁出(大工程)。至少限制 `script-src` 到自身+必要 CDN(fonts)、禁 `object-src`、设 `base-uri 'self'`。分步收紧，别一次上线打崩页面。

### 阶段3（可选/评估）：token 迁 httpOnly Cookie
- `hq_token` 从 localStorage 迁 **httpOnly Cookie**(JS 读不到、XSS 偷不走)。涉及 auth 下发 Set-Cookie + 各页请求改带 cookie + CSRF 防护。工作量大、影响面广，**单独评估**，前两阶段已大幅降风险。

## 验收标准
1. 采集第三方内容(构造含 `<script>`/`<img onerror>` 的标题/评论)渲染**无法执行脚本**。
2. 全站统一到一个转义器；关键 sink 审计通过、能 textContent 的不用 innerHTML。
3. CSP 生效且不破坏现有页面功能(灰度验证)。
4. (若做阶段3)token 不再 JS 可读。

## 部署与验证
- 前端各页→webroot；nginx CSP 改 sites-enabled(注意备份不放 sites-enabled/ 内)。分阶段部署、每阶段实测注入用例 + 页面功能。

> 本工单只做规划，未改动任何文件。分阶段做，阶段1(采集页+转义器)优先。
