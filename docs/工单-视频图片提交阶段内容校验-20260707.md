# 工单 · 视频接口图片提交阶段内容校验（Issue #60 反馈 · LU-003 2026-07-06）

> **冲突组：A（`server/content_domains/video.py`）** —— 抢 `lock/A`。**后端为主**，不动前端、不动数据库。
> 相关：FB6（视频接口校验+成本#194 已上线）、今日视频失败日志里的 HeyGen「No face detected」。

## 现象（#60 最后一条待处理反馈）
`POST /api/gen/video` 提交"格式像图片 dataURL、但内容不是有效图片"的请求，例如：
```json
{"mode":"text","image_data":"data:image/png;base64,AAAA","text":"测试","voice":"dapeng"}
```
**提交阶段没拦住** → 返回 200 + job_id → **先扣点** → 后台调 HeyGen 失败(如「No face detected」) → 任务 error/failed → 退点。副作用：假"创建成功"提示、白跑一次上游、脏失败资产记录、错误太技术化。

## 根因（已定位 2026-07-07）
`video.py:68 _is_valid_data_url(value, allowed_mimes)` 只校验：① `data:` 前缀 ② `;base64` ③ mime 在 `VALID_IMAGE_MIMES`(jpeg/jpg/png/webp) ④ base64 可解码。
**但不校验解码后字节是否真是图片**（无魔数/文件头检查）。`data:image/png;base64,AAAA` → mime 合法 + "AAAA" 可解码 → 误判为有效。
（`_ensure_heygen_image_jpg` 会真正解码，但在**建 job 之后**、HeyGen 调用时，太晚。）

## 待做（改 `video.py`，提交阶段前移校验）
1. **加图片内容魔数校验**：新增 helper（如 `_image_bytes_look_valid(raw)`），对 base64 解码后的字节检查文件头：
   - PNG：以 `\x89PNG\r\n\x1a\n`（`89 50 4E 47`）开头
   - JPEG：以 `\xff\xd8\xff` 开头
   - WebP：字节 0-3 `RIFF` 且 8-11 `WEBP`
   - 任一命中即视为有效图片；都不命中 → 无效。
2. **接入现有校验**：在 `_is_valid_data_url`（或调用点 line 95）解码成功后再过魔数校验；不过 → 返回 False → 沿用现有 `raise ValueError("image_data 不是有效的人物形象图片")` → **提交阶段 400、不建 job、不扣点、不进后台、不调上游**。
   - ⚠️ 确认这段校验在**扣点(deduct)之前**执行（现在的 ValueError 走的就是提交阶段 400，保持）。
3. **（可选，更稳）** 若服务器有 PIL/Pillow，可 `Image.open(BytesIO(raw)).verify()` 做更强校验；没有则魔数校验即够，**不新增重依赖**。
4. **（可选）参考视频/音频同类加固**：`reference_video_data`(line 112)、`audio_data`(line 106) 也只查格式，可顺带加魔数（视频 `ftyp`/mp4、音频 mp3 `ID3`/`\xff\xfb`）——**非本单必须，量力而为，别越界扩太多**。
5. **前端友好错误**（可选，若改前端另抢 lock/B）：video.html 收到 400 展示"人物图片无法识别，请重新上传清晰的 PNG/JPG/WebP 图片"。**本单后端为主，前端可另评估**。
6. **（可选，#60反馈点6）** 视频资产列表默认隐藏"提交阶段可识别的失败记录"或单独筛选——**属资产页(C组)，另评估，不在本单**。

## 验收标准
1. 提交 `data:image/png;base64,AAAA`（假内容）→ **HTTP 400** `{"detail":"image_data 不是有效的人物形象图片"}`，**不建 job、不扣点、不调 HeyGen**。
2. 真实 PNG/JPG/WebP 图片正常通过、能生成。
3. 提交阶段 400 不产生失败资产记录、不污染视频资产列表。
4. 不误伤合法图片（尤其 WebP，魔数要按 RIFF+WEBP 双段判）。
5. 不影响口播/动作模仿正常流程、不回退 FB6 等近期加固。
