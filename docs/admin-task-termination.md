# 实时任务的管理员终止

当前支持未绑定托管渠道的普通 `matrix_template_video`（排队及执行中）。
时间线合成、托管渠道及其他任务类型尚未接入，接口拒绝终止，页面显示不支持。

管理员在实时任务卡片点击“终止任务”，填写原因并确认。后台根据实际任务能力返回
`can_terminate`，前端不靠功能名称猜测。已结束任务不可终止。

## 状态与证据

- `admin_task_terminations` 在任务数据库中保存操作者、原因、原状态、请求时间、
  本地执行退出时间及供应商工单。终止记录只创建一次，重试不能改写原操作者和原因。
- `platform_state=stopping` 表示请求已记录，执行线程尚未确认退出；`stopped` 表示排队任务
  已阻止认领，或原执行线程已完成清理。进行中的网络请求可能需要等待原超时边界。
- `remote_state=not_submitted` 仅用于没有提交恢复记录的新排队任务；其余为 `unconfirmed`。
  当前供应商没有已验证的取消接口，因此不声称远端停止，也不保证免除供应商费用。
- `refund_state` 分为 `pending`、`refunded`、`not_needed`。原任务点数使用既有 Auth 幂等
  退款事务，失败由现有 reaper 重试。该状态不代表供应商账单已退还。
- 兼容现有客户接口，底层任务置为 `error`，管理员终止原因可见；后台卡片另外显示终止状态。
  现有“失败”筛选和统计仍包含管理员终止。历史链路证据保留，不伪造交付成功。

## 执行与并发

`POST /api/admin/tasks/terminate` 转发管理员凭据到
`POST /api/gen/admin/tasks/terminate`；内容服务再次验证管理员权限。
请求仅含 `job_id`、`reason`，操作者来自认证信息。

SQLite `BEGIN IMMEDIATE` 将终止账本、任务终态和退款意图放在同一事务。
完成先取得终态则拒绝终止；终止先取得终态则原有 CAS 拒绝迟到的完成结果。
已取消任务不进入恢复重排。供应商刚返回的工单号即使遇到取消竞争也会被保留。

模板渲染轮询、下载和预算检查响应停止请求；ffmpeg/ffprobe 只停止当前任务启动的子进程。
不会杀掉共享服务或其他任务。执行线程的 finally 确认本地停止，不以收到 HTTP 200 作为
停止证据。若执行进程崩溃，或停止回报写库失败，记录保留“终止中”，需要核对进程；
不会通过超时自动假定已停止。退款意图已持久化，不依赖该执行线程存活。

## 验证

隔离测试覆盖权限、原因校验、幂等、并发终止、完成竞争、退款重试、迟到供应商回执、
阻止后续下载、清理自有子进程，以及前端重复提交与失败保留输入。
本地预览使用独立示例数据库，不运行生产任务，不调用真实供应商，不产生真实扣点。
