# 工单 · F2 参考动作库（Motion 预设）

> 供其他 agent 独立执行。开工前先读《工单-其他agent实施-20260703》§0 公共上下文
> （仓库/分支PR/ship/DESIGN.md/漂移哨兵/**禁止服务器直改**）。

## 目标与价值
动作模仿目前必须用户**自备参考动作视频**，非技术用户门槛高。内置一批**预设参考动作**（口播手势/转场/展示/走位等），一键选用即可出片。

## 现状（已核实）
- 前端 `site/workbench/video.html` 动作模仿页：用户上传参考视频 → `reference_video_data`（base64）→ 提交 `/api/gen/video`（mode=motion）。
- 后端 `generate_heygen_motion_video` 把 `reference_video_data` 存文件 → 上传 HeyGen asset → 驱动生成。**后端已能处理任意参考视频，无需为 F2 改核心逻辑。**

## 方案（前端 + 静态预设 + **清单驱动**，零后端改动）
1. **素材目录 + 清单**：预设素材放 `site/workbench/assets/motions/`，每个一段短 mp4 + 一张缩略图（`.jpg`）；再建一个清单文件 `site/workbench/assets/motions/index.json`，形如：
   ```json
   [ { "file": "gesture-01.mp4", "thumb": "gesture-01.jpg", "name": "打招呼" } ]
   ```
   - **本期只有 1 个素材**（由用户提供），清单先放这 1 条。**以后加素材只需往目录丢文件 + 往 index.json 加一条，不用再改代码**——这是本工单要求"清单驱动"的原因。
   - 素材来源合规由用户负责。
2. **前端预设选择器（读清单渲染）**：动作模仿页"参考动作"区加**预设动作网格**，**从 `index.json` 动态读取**渲染（缩略图 + name），不要把预设写死在 JS 里；保留"上传自有视频"入口。
   - 选中预设 → 前端 `fetch` 对应 mp4 → 转 base64 → 作为 `reference_video_data` 按现有流程提交（后端无感知差异）。
   - 清单为空/加载失败时优雅降级：只显示"上传自有视频"，不报错。
3. **风格**：先读 `DESIGN.md`，复用 `cloud-shell.js?v=15` 外壳与现有上传区样式。

> 备选（本工单不做，列为后续优化）：后端支持 `reference_preset` key，直接读服务器预置文件，免"下载→base64→再上传"往返、更省带宽。若预设视频较大导致提交慢，可改走此路。

## 边界与注意
- **只加前端 + 静态素材**，不改后端生成逻辑；口播/上传自有视频路径行为不变。
- 预设视频**体积控制**：base64 走 JSON 提交，过大可能慢/超限，单个建议控制在合理大小（数 MB 内）。
- 选预设时"上传自有视频"区应互斥（避免同时提交两个来源）。
- 素材版权合规由提交者确认。

## 验收标准
1. 动作模仿页出现"预设动作"网格（从 index.json 读，本期显示那 1 个预设的缩略图+名称）+ "上传自有视频"入口。
2. 选那个预设 + 一张人物照片（或 F1 已存形象）→ 能成功生成动作模仿视频。
3. **验证清单驱动**：往 index.json 再加一条（可临时测试）→ 网格自动多出一项，无需改 JS。
4. 上传自有视频路径行为不变；口播不受影响；视频页无控制台报错。

## 部署与验证
- 前端 + 素材：`./ship "F2 参考动作库(预设动作)" site/workbench/video.html site/workbench/assets/motions/`
  （`ship` 的 `site/*` 映射会把整个 motions 目录 rsync 到 webroot 对应位置）
- 上线后实测预设能出片；确认漂移哨兵无新增告警。

## 素材交接（重要）
- **本期 1 个参考动作素材由用户提供**（短 mp4）。agent 拿到后：放进 `site/workbench/assets/motions/`、生成/裁一张缩略图 `.jpg`、在 `index.json` 里加对应条目。
- 若开工时暂未拿到素材，可**先用一个占位短片把链路做通**，等真实素材替换即可（清单驱动，替换零改码）。
