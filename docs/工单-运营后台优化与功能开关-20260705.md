# 工单 · 运营后台可读性优化 + 平台功能开关（ADMIN-4）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《开发手册》+《任务看板》领取流程 + `DESIGN.md`。
> **冲突组：admin（`server/admin_api.py`、`site/admin/**`）+ A（`server/content_domains/**`）+ imggen（`server/imggen_api.py`）** —— 抢 `lock/admin` + `lock/A` + `lock/imggen`。
> 来自 kongli：运营后台可读性增强 + 新增"平台自有功能开关"。

## 背景
运营后台（`/admin-console/`，服务 `huangque-admin` :8098）现有三块：接口管理(ADMIN-1，管上游 AI 渠道) / 用户管理(ADMIN-2) / 充值审批(ADMIN-3)。本单两件事：**① 整体可读性优化**；**② 新增"平台功能开关"模块**（管黄雀自己的功能模块启停）。

---

## 一、可读性优化（`site/admin/index.html`，组 admin）
四项都做：
1. **布局分区更清晰**：接口管理 / 功能开关 / 用户管理 / 充值审批 分成明确的区块/tab，卡片和标题层级分明、模块间留白，一眼分清在哪个模块。
2. **状态颜色 + 图标**：在线/离线、已配/未配、待审/已处理、启用/禁用——用颜色（绿=正常/在线/启用、红=离线/禁用、灰=未配、金=待处理）+ 小图标区分，一眼看出状态。
3. **数据表可读性**：用户列表 / 审计流水 / 调用统计的表格——列对齐、点数千分位、时间格式化（YYYY-MM-DD HH:mm）、长内容截断+悬停、必要时分页或滚动容器（宽表 `overflow-x:auto`）。
4. **中文化 + 说明**：英文字段/术语中文化；关键操作（加减点、批准、启停功能）加一句提示说明，降低上手难度。
- 严守 `DESIGN.md` 配色/字体（金 `#e7b24c` / 文字 `#94a4bb` 等），后台可用更朴素的管理风但沿用设计令牌。

## 二、平台功能开关（新模块）
管理黄雀**自有功能模块**的启用/禁用 + 在线状态。

### 功能清单（从后端能力枚举，别写死漏项）
平台功能对应各 `/api/gen/*` 能力，建议覆盖：**作图(image + banana)、配音(audio)、视频口播/动作模仿(video)、换装换背景(tryon)、采集(collect)、获客(leads)、下载(dl)、文案(copy)** 等（以 content `HANDLERS` + imggen + dl 实际能力为准）。

### 后端：功能开关存储 + 拦截（组 A + imggen + admin）
1. **共享功能开关存储**：新建一张功能开关表（`feature`, `enabled`, `updated_by`, `updated_at`），放在 content/imggen 都能读的位置（如 content 侧 db 或独立 `feature_flags.db`）。admin 写、content/imggen 读。
2. **提交入口拦截**：`content_domains/core.py` 的 `/api/gen/<kind>` 处理入口（及 `imggen_api.py` 的 banana、`dl_service.py` 的下载如纳入），在处理前查该功能是否启用——**禁用则返回 503 `{"detail":"该功能维护中，暂不可用"}`**，不建 job、不扣点。读取要轻量（可加短 TTL 缓存，避免每请求都读库）。
3. **admin 侧接口**（`admin_api.py`）：`GET /api/admin/features`（列功能+启用状态+在线健康）、`POST /api/admin/features/toggle`（启用/禁用某功能，写开关表 + `admin_audit` 留痕，role=admin 校验）。改动**即时生效**（content/imggen 下次请求读到新状态）。

### 前端：功能开关 UI（`site/admin/index.html`，组 admin）
- 新"功能开关"区：列出每个平台功能 + **在线状态** + **启用/禁用开关**（点击切换调 `/api/admin/features/toggle`）。
- 禁用后该功能在后台显示"已禁用"，前端用户用该功能会收到 503（可后续再做前端友好提示，本单不强制改用户前端）。

## 边界与安全
- 全部 admin 接口强制 `role=admin`（复用现有 `_admin()`）；开关变更写审计。
- 功能拦截**只加"禁用则 503"这一层**，不动各功能的生成核心逻辑。
- 默认所有功能**启用**（开关表无记录=启用），避免上线即全关。
- 不显任何密钥真值。

## 验收标准
1. 后台四模块分区清晰、状态有颜色/图标、数据表可读、中文化到位（对照 `DESIGN.md`）。
2. 功能开关：管理员能看到各平台功能的在线状态，能启用/禁用；**禁用后该功能提交返回 503、不扣点/不建 job；启用后恢复正常**；变更即时生效 + 有审计。
3. 默认全启用，未配置开关表时行为与现在一致。
4. 非 admin 访问全部 403；`py_compile` 通过、各服务 health 200。

## 部署与验证
- 涉及多服务：`admin_api.py`→huangque-admin、`content_domains/**`→huangque-content、`imggen_api.py`→huangque-imggen-api、`site/admin/index.html`→webroot（可能还有 dl_service）。审核方按改动文件逐个部署重启。
- 实测：禁用"作图"→作图提交 503 且不扣点→启用→恢复；后台可读性对照验收。完成后可在相关 issue/反馈台知会。
