# 工单 · 下载代理按真实类型命名 + 修批量下载只下一张

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》领取流程。
> **冲突组：`server/dl_service.py`（独立）+ `server/content_domains/core.py`（A）+ `site/workbench/collect.html`（E-collect）** —— 抢 `lock/A` + `lock/E-collect`。

## 问题（DL-IMGS #125 后暴露的两个 bug）
1. **图片下载成 .mp4**：采集图文点「下载全部图」走 `/api/gen/dl` 代理，但该代理**给视频写死了 `Content-Type: video/mp4` 和 `filename=xxx.mp4`**（`dl_service.py` 约 101-103 行），导致图片被命名成 `img_1.mp4`（内容其实是 JPEG）。
2. **只下第一张**：前端 `collect.html` 批量下载用 `<a target="_blank">` 逐张触发 → 浏览器**把多个 _blank 当弹窗拦截，只放行第一个**。

## 改动
### 1. 后端下载代理按真实类型命名（`server/dl_service.py`，主路径；`server/content_domains/core.py` 的 `/api/gen/dl` 同款一并改）
下载时**从上游响应的 `Content-Type` 推断扩展名**，别再写死 mp4：
- 拉取上游后读它的 `Content-Type`；映射：`image/jpeg`→`.jpg`、`image/png`→`.png`、`image/webp`→`.webp`、`image/gif`→`.gif`、`video/mp4`→`.mp4`、`video/quicktime`→`.mov`；拿不到就回退 `.mp4`（保持视频旧行为）。
- `Content-Type` 用上游真实类型（拿不到回退 `application/octet-stream` 或 `video/mp4`）。
- `Content-Disposition` 的 `filename` 用 `name` 参数 + **推断出的扩展名**（如 `img_1.jpg`）。
- ⚠️ 视频下载（现有）行为不能变：视频上游是 video/mp4 → 仍 `.mp4`。解密流那条（`_stream_decrypt`）是视频专用，保持 mp4 不动。

### 2. 前端去掉 target=_blank（`site/workbench/collect.html`，galDownloadBtn）
```js
// 删掉 a.target='_blank'（attachment 下载不跳转、不需新标签；_blank 会被弹窗拦截）
a.href = '/api/gen/dl?url=' + encodeURIComponent(u) + '&name=' + encodeURIComponent('img_' + (i+1));
a.rel = 'noopener';
// 保留 setTimeout(i*260) 逐张间隔
```
> 若去掉 _blank 后个别浏览器仍只下一张，改用「fetch→blob→a.download 同源 blob 链接」逐张下载兜底（可选，实测决定）。

## 无需改的
- 图片 CDN 域名已在 dl 白名单（#116/#120），不用动白名单。

## 验收标准
1. 采集抖音图集/小红书图文 → 「下载全部图」→ **每张都下到本地、且是 `.jpg/.png` 正确图片文件**（不是 .mp4）、能正常打开。
2. 张数多时**全部下载**，不再只下第一张。
3. **视频「下载无水印视频」仍下成 .mp4、正常播放**（回归不能破）。
4. `py_compile` 通过、health 200。

## 部署与验证
- `./ship "下载代理按类型命名+修批量下载" server/dl_service.py server/content_domains/core.py site/workbench/collect.html`（dl_service→huangque-dl 重启；core→huangque-content 重启；collect.html→webroot）
- 实测：图集下载得到 .jpg 全部图；视频下载仍 .mp4 正常。
