# 开发方案 · F1 数字人形象库（Avatar 复用）

> 本方案供**其他 agent 独立开发**。开工前先读《工单-其他agent实施-20260703》§0 公共上下文（仓库/分支PR/ship/DESIGN.md/漂移哨兵/禁止服务器直改）。
> 本文只做**方案设计**，不含实现代码；执行者按「技术设计」落地、按「验收标准」自测、按「部署与验证」上线。

---

## 1. 目标与价值
动作模仿每次生成都要 `_heygen_create_photo_avatar` 建数字人 + 轮询等待（数分钟、消耗 HeyGen 配额）。**把生成过的数字人形象持久化、可命名、可复用**，二次生成同一形象时**跳过建 avatar 步骤**，直接进入生成视频阶段 → 显著提速、省配额、降成本。

## 2. 现状（执行者须知，均已核实）
- 文件：后端 `server/content_api.py`，前端 `site/workbench/video.html`。
- **口播**（`_heygen_create_video`）直接用 `image_asset_id`，**不建 avatar** → F1 **不影响口播**。
- **动作模仿**（`generate_heygen_motion_video`，约 L1584）流程：上传图/参考视频 asset → `_heygen_create_photo_avatar(image_asset_id)` 得 `avatar_item_id/avatar_group_id` → `_heygen_wait_photo_avatar` 等待就绪 → `_heygen_create_cinematic_video(avatar_item_id, reference_asset_id, ...)` → 轮询 → 下载。
- 现有表 `video_assets`（在 AUDIO_DB，`init_audio_db` 内建）**已存** `provider_avatar_id`、`provider_avatar_group_id` 字段——即每条视频已经记录了用的 avatar。
- 建表/迁移写法：`init_audio_db()` 里 `CREATE TABLE IF NOT EXISTS ...` + `_ensure_column(c, 表, 列, 定义)`。
- 路由：`class H` 的 `do_GET/do_POST` 里 `if p == "/api/gen/..."` 分发；鉴权用 `verify(token)` 拿 `username`；已有先例 `/api/gen/audio/voices`（列表）、`/api/gen/audio/voice-name`（改名）。

## 3. 范围
- **In scope**：动作模仿的 photo-avatar 持久化 + 复用；形象库的列表/命名/删除；前端"我的形象"选择器。
- **Out of scope**：口播路径改造；HeyGen 计费改动；批量生成（属 F5）。

## 4. 技术设计

### 4.1 数据模型（AUDIO_DB 新增表，`init_audio_db` 内建）
```
avatars(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  name TEXT NOT NULL,                 -- 用户可改，默认「形象 N」或按时间
  image_file TEXT NOT NULL,           -- 源照片(OUT_DIR 相对路径)，用于缩略图 + 失效重建
  provider_avatar_id TEXT NOT NULL,   -- HeyGen avatar_item_id
  provider_avatar_group_id TEXT,      -- HeyGen avatar_group_id
  status TEXT NOT NULL DEFAULT 'ready',
  created_at INTEGER, updated_at INTEGER
)
```
> 建表用 `CREATE TABLE IF NOT EXISTS`；后续如加列一律走 `_ensure_column`，不要改动已有表结构。

### 4.2 后端改动（`content_api.py`）
1. **建表**：`init_audio_db()` 里加 `avatars` 表。
2. **自动入库**：动作模仿生成成功后（`generate_heygen_motion_video` 返回含 `avatar_item_id/group_id`，或在 `record_video_asset` 落库处），**自动创建一条 avatar 记录**（默认名），使其立即可复用。避免重复：同 `username + provider_avatar_id` 已存在则不重复插。
3. **复用**：`gen_video`（motion 分支）接受可选 `avatar_id`：
   - 传了 `avatar_id` → 校验属于当前用户 → 读出 `provider_avatar_id/group_id`，**跳过** `_heygen_create_photo_avatar` 与 `_heygen_wait_photo_avatar`，直接 `_heygen_create_cinematic_video(...)`。
   - 未传 → 保持现流程（建 avatar），成功后按第 2 点入库。
   - **失效回退**：复用时若 `_heygen_create_cinematic_video` 报 avatar 不存在/失效，则用该记录的 `image_file` 重新走建 avatar 流程并更新记录（保证不因 HeyGen 端过期而彻底失败）。
4. **接口**（沿用现有路由风格，全部 `verify(token)` 鉴权、按 username 隔离）：
   - `GET  /api/gen/video/avatars` → 返回本人形象列表（id/name/缩略图 url/created_at）。
   - `POST /api/gen/video/avatar-name` → 改名（body: id, name；仅限本人）。
   - `POST /api/gen/video/avatar-delete` → 删除本地记录（body: id；仅删本库记录，不强求删 HeyGen 端）。

### 4.3 前端改动（`video.html`，先读 `DESIGN.md` 对齐风格）
- 动作模仿标签页的"人物形象"区加 **"我的形象"选择器**：
  - 进页拉 `GET /api/gen/video/avatars` 渲染缩略图网格 + "上传新照片"入口。
  - 选中已存形象 → 提交时带 `avatar_id`、**免上传照片**（参考动作视频仍按现流程/或用 F2 预设）。
  - 选"上传新照片" → 保持现有上传流程；生成成功后该形象自动出现在库里。
- 形象管理：每个形象可**改名**（调 avatar-name）、**删除**（调 avatar-delete，二次确认）。
- 复用现有 `cloud-shell.js?v=15` 外壳与轮询/进度逻辑，不改口播路径。

## 5. 边界与注意
- **用户隔离**：所有查询/改名/删除/复用都必须校验 `username` 归属，防越权。
- **并发**：入库发生在任务完成路径，注意与现有 `record_video_asset` 写库一致的连接/事务方式，避免锁冲突。
- **缩略图**：用 `image_file` 经 `/api/gen/file/...` 出图，无需另存。
- **计费**：本期不改点数模型；如需"复用更便宜"另立需求。
- **不回退**：改 `content_api.py` 必须基于**当前 main**（已含动作模仿后端），别用旧版覆盖。

## 6. 验收标准
1. 首次动作模仿生成成功后，"我的形象"里出现该形象（有缩略图、默认名）。
2. 选已存形象再次生成：后端日志/phase **不再出现建 avatar 与等待阶段**，直接进入创建视频；端到端耗时明显下降。
3. 改名、删除生效且仅作用于本人形象；他人无法访问。
4. 复用时若 HeyGen avatar 失效，能自动用源照片重建并成功产出（不整体失败）。
5. 口播功能**行为不变**。
6. `python -m py_compile server/content_api.py` 通过；`/api/gen/health` 200；视频页无控制台报错。

## 7. 部署与验证
- 后端：`./ship "F1 数字人形象库(avatar 复用)后端" server/content_api.py`
- 前端：`./ship "F1 数字人形象库前端" site/workbench/video.html`
- 上线后：health 200；实测"生成→入库→复用→改名→删除"全链路；确认漂移哨兵无新增告警（ship 会自动 `--bless`）。
- DB 变更是**新增表 + IF NOT EXISTS**，对存量无破坏；上线即自动建表。
