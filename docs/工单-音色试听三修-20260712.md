# 工单 · 音色试听三修（#602 / #604 / #610）

> 供其他 agent 独立执行。开工前先读团队 Git 协作规矩 + §0 公共上下文（仓库/分支PR/ship/DESIGN.md/漂移哨兵/**禁止服务器直改**）。
> 三个 issue 同属音色模块、根因相邻，一次修完。关联 #602 / #604 / #610。

## 目标与价值
音色模块现在三个体验/正确性问题，都卡在「个人复刻音色的试听」上：
- **#602**：CosyVoice 复刻成功后**没有试听音频**——复刻当刻生成 preview 不可靠（就绪窗口竞态）。
- **#604**：删掉没用的 alloy 占位音色，**过一阵又自己回来了**——每次配音后自动重建。
- **#610**：数字人口播模块选个人音色处**缺试听入口**。

## 现状（已核实）

### #602 CosyVoice 复刻无试听（就绪窗口竞态）
- `server/content_domains/audio.py::_clone_via_cosyvoice`：`create_voice` 后立即 `voice_status` + 仅当 ready 时 `_cosy_clone_preview(voice_id)` 合成一句试听。
- 两条竞态叠加，任一即无试听：① 新 voice 可能还没进阿里 `list_voice` → status 返「训练中」→ preview 被 `if slot_status=='ready'` 整个跳过（CosyVoice 无后续轮询补生成）；② 即便 OK，音色模型未即时就绪，紧接着 `cosyvoice.synth` 失败，异常被 `_cosy_clone_preview` 的 `except: return None,None` 吞掉。
- 结果：**每条新复刻系统性无试听**。稍后（如几十秒后）synth 就正常——纯就绪窗口问题。本会话手动回填过两条验证过 voice_id 有效、synth OK。

### #604 alloy 占位音色删了又回来
- `server/content_domains/audio.py::record_audio_asset`（**每次配音出结果都跑**）拿本次 `voice_key` 调 `ensure_audio_voice`，遗留 key（`dapeng`/`zelong`/`personal` 等）没对应行就现建一条 `scope=personal`、`provider_voice` 回落 `alloy` 的占位。
- 于是：用遗留音色配一次音，占位行就凭空出现；删了下次配音又回来。前端已不再列 dapeng/zelong，来源是历史默认音色设置 / 老任务 payload。

### #610 口播缺试听入口
- 音频页有试听（读 `preview_url`），但**数字人口播页**选个人音色的地方没有把 `preview_url` 接出来做试听按钮。属纯前端接线（后端已返 `preview_url`）。

## 方案

### A. #602 —— preview 生成对就绪窗口有韧性（`audio.py`）
- `_cosy_clone_preview`：对 `cosyvoice.synth` 做**短重试轮询**（如最多 5 次、每次 2~3s，直到拿到 ≥1KB 音频或超时）。
- 放宽生成入口：不再靠 `if slot_status=='ready'`——只要 `create_voice` 拿到 voice_id 就尝试（synth 本身能出声即代表就绪，比 list 的 status 更权威）。
- 保持「preview 失败不阻断复刻」现有语义（音色本体仍可用，只是暂无试听）。

### B. #604 —— 别再为 alloy 占位自动建行（`audio.py`）
- `ensure_audio_voice`：只有**真实复刻音色**（cosyvoice `provider_voice` 前缀 `cosyvoice-`，或豆包真有 provider 侧音色）才落 `audio_voices` 行；解析成 alloy 占位时**不 INSERT**，直接返回 alloy 供合成用（合成不需要 DB 行）。
- `record_audio_asset`：`audio_assets.voice_id` 允许 NULL / 存原始 voice_key 字符串，别为了拿 voice_id 逼着建个人音色行。
- 启动迁移里把遗留占位（dapeng/zelong/personal 且 pv=alloy）一次性清掉（幂等），并确保默认音色设置不再指向它们。真 CosyVoice/豆包复刻不受影响。

### C. #610 —— 口播页补试听入口（`site/workbench/video.html`，纯前端）
- 口播模式选个人音色的列表项，读该音色的 `preview_url`，加一个试听按钮/播放控件（复用音频页已有的试听播放逻辑与样式，先读 DESIGN.md）。
- 无 `preview_url` 的音色（如尚未回填的、或 alloy）不显示试听按钮，别报错。

## 边界与注意
- 别打印任何明文凭据（查 env 只看键名，见 #512 教训）。
- CosyVoice 相关走 `cosyvoice.enabled()`（= 有 DASHSCOPE_API_KEY）；无 key 时 gracefully 跳过，别报错。
- A/B 改 `content_domains/audio.py` → **content_domains 被四个服务共用**（content/imggen-api/admin/leadgen-api），部署后**四个都要重启**（见部署记忆）。
- C 是纯前端，改 `site/workbench/video.html` → `/var/www`，不重启。

## 验收标准
1. #602：新复刻一个 CosyVoice 音色，完成后 `audio_voices.preview_url` 非空、前端出现试听、点击能播；synth 前几次失败仍能重试成功（单测：mock synth 前 N 次抛错第 N+1 次成功，断言 preview 落库）；断网/synth 一直失败时复刻仍成功、只是暂无试听、不报错。
2. #604：用 alloy/遗留 key 配一次音，能正常出声但**个人音色列表不新增 alloy 占位行**；已删占位不复活；真复刻音色正常在列表可试听（单测：mock voice_key=personal 无真复刻的 record_audio_asset，断言无新增 personal 行）。
3. #610：口播页选个人音色处能看到并播放试听；无 preview 的音色不报错。
4. 四服务重启后 `/api/gen/health` 200；音频/口播/复刻全链路无报错。
