# 本地开发 & 反漂移工作流

## 为什么（背景）
同事直接在**服务器上改代码**，导致：
- git 与生产错位（fakeui 层、改动不在库里）→ PR 里冒出一堆"别人的改动"；
- 服务器编辑器把文件存成 **CRLF**，git 一 diff **满屏 phantom 变更**，PR 极乱。

## 三条规矩（照做就不乱）
1. **不在服务器上改代码。** 一律本地改 → 提 PR → 合并 → 用 `./ship` 或 `deploy_site.sh` 部署。
2. **行尾统一 LF。** 仓库已加 `.gitattributes`（源码 `eol=lf`，二进制 `binary`）。CRLF 提交会自动归一，不再有 phantom diff。
3. **在建功能开 feature 分支**，别散在 main（如 `feat/new-video-channels`）。

## 本地怎么跑
```bash
bash scripts/dev_local.sh
#  API   → http://127.0.0.1:8096   (content_api.py，零第三方依赖，标准库即可启动)
#  静态站 → http://127.0.0.1:8097/workbench/
```
- 不配密钥也能启动：AI 类接口返回"未配置"，开发页面/路由/非 AI 逻辑无影响。
- 要联调 AI：把 `server/content.env` 拷成 `server/secret.local.env`（已 gitignore），出站指向法兰克福中转。

## 服务器被人热改了怎么办（找回真相）
```bash
# 前端：把生产真实状态同步回仓库（排除 .bak / 源码目录）
rsync -a --checksum --exclude '_cloud_src/' --exclude '_preview/' --exclude '*.bak*' \
  --rsync-path="sudo rsync" dapeng-server:/var/www/huangquechuanmei/ site/
# 后端：逐文件 md5 比对 server/*.py 与 /home/ubuntu/content-api/，差异多半只是 CRLF
```
服务器上有 `hq-drift/drift_sentinel.py` 漂移哨兵，`./ship` 会自动 bless 基线；绕过 ship 的热改会被它记录。
