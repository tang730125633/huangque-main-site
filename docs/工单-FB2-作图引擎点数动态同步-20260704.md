## 问题（反馈原文）
作图页 `/workbench/banana` 的引擎卡片点数是**固定文案**（Nano Banana 2 = 10点、Pro = 18点、gpt-image-2 = 12点、泽龙 = 8点），但底部「立即生成」/「本次预计消耗」会随**清晰度(标准/高清)**和**数量**变化——例如高清 1 张时 nb2 实际 14 点、Pro 实际 26 点。**卡片与实际对不上，误导用户。**

## 现状（已核实，关键：前端已有正确成本模型）
- `banana.html` JS 里已有：
  ```js
  var COSTBASE={nb2:{std:10,hd:14}, pro:{std:18,hd:26}, gpt:{std:8,hd:12}, zelong:{std:8,hd:12}};
  function costFor(){ var t=COSTBASE[engine]||COSTBASE.nb2; return (t[quality]||t.hd)*count; }
  function updateCost(){ ... 本次预计消耗 costFor() ... }   // 引擎/清晰度/数量变化时都会调
  ```
  「立即生成」按钮和「本次预计消耗」**已经动态、正确**。
- **唯一问题**：4 个引擎卡片的点数是**写死在 HTML** 里的（`· 10点`、`· 18点`、`· 12点`、`· 8点`），不更新。

## 方案（动态同步，纯前端）
- 让**每个引擎卡片的点数**显示为**该引擎在当前清晰度+数量下的实际点数** = `COSTBASE[该引擎][quality] * count`，并在**切换清晰度/数量/引擎时实时更新**。
  - 例：高清 + 1 张 → nb2 卡片显示 14、Pro 显示 26、gpt 显示 12、泽龙 显示 12；数量变 2 张则翻倍。
- 实现：给 4 个卡片的点数处加可定位的元素（如 `data-engine-cost="nb2"` 的 span），在 `updateCost()` 里一并刷新每张卡的点数（用 `COSTBASE[eng][quality]*count`）。
- 保留卡片原有说明文字和 `✦推荐` 标记，只把"· N点"部分变成动态值。
- 这样**卡片点数、底部「本次预计消耗」、「立即生成（N点）」三处永远一致**。

## 边界与注意
- **只改前端** `banana.html`，**不碰后端**、不改 COSTBASE 的值、不改扣点逻辑。
- 数量上限随引擎不同（`ENGINE_MAXN`），卡片按当前生效的 count 算即可。
- 其它作图功能（生成/局部改/历史）不受影响。

## 验收标准
1. 切换**清晰度/数量**时，4 个引擎卡片的点数**实时更新**为各自实际点数。
2. 任一时刻：某引擎卡片点数 == 选中该引擎时底部「本次预计消耗」== 「立即生成（N点）」。
3. 例：高清+1张 → nb2=14 / pro=26 / gpt=12 / 泽龙=12；标准+1张 → nb2=10 / pro=18 / gpt=8 / 泽龙=8。
4. 生成/历史等不受影响；无控制台报错。
