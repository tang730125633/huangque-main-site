> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：shell（`site/workbench/cloud-shell.js`）** ⚠️ **排他大组** —— 抢 `lock/shell`。
> ⚠️ 改 cloud-shell.js 会触发 `stamp_assets.py` bump **全部 workbench/*.html 的 `?v=`**，与**任何**前端页(B/C/E/admin)任务冲突；占 shell 期间禁止一切前端页任务并行，有前端页任务在做时 shell 也不能领。
> 来源：Issue #413（yuelei-dev, bug）。

## 背景
顶部栏右侧的**通知铃铛**图标带红点提示，但**点击无任何反应**，是纯装饰元素，误导用户以为有未读通知。

## 改动（`site/workbench/cloud-shell.js`）
- 给铃铛图标绑 `onclick`：**先做最小可用**——点击跳转到获客/资产页查看最新结果（yuelei 建议跳获客页）。
- **红点默认隐藏**（改为待后续接真实通知信号再点亮），避免"永远有红点却点不动"的误导。
- 保持 DESIGN.md 的视觉规范；div/span 若改成可点击元素，加 `role/aria-label`+键盘可达（对齐 GROW-FRONTEND #203 可访问性基线）。

## 后续（本工单先不做，列为路线）
- 接真实通知：新采集结果完成/任务失败时点亮红点。
- 点铃铛弹通知下拉（最近 5 条）。

## 验收标准
1. 铃铛可点击、有反馈（跳转或后续的下拉），不再是死控件。
2. 红点不再默认常亮（无真实未读时不显示）。
3. 键盘可 focus + 回车触发，有 aria-label。
4. 不动其它 shell 功能（左侧栏/导航/点数等不回归）。
