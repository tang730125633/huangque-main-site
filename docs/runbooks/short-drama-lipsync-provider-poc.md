# 短剧真实口型 Provider PoC 运行手册

## 1. 目标与范围

阶段 0-B 的目标是用同一批私有短剧样本，对比 Sync Labs 与 fal.ai LatentSync，验证：

1. 无声人物画面能否按项目主音轨生成真实口型；
2. 输出能否安全移除供应商音轨，交还后续统一装配；
3. 异步任务能否查询、恢复、取消或重拉；
4. 质量、耗时、价格和失败率是否达到进入生产化设计的门槛；
5. 异常、超时和响应丢失时是否能明确费用归属。

本阶段不修改生产 API、画布流程、项目扣点和服务器部署，也不把真实媒体或密钥提交到仓库。

## 2. 候选与合同

| 候选 | 输入 | 查询/重拉 | 取消 | 当前结论 |
|---|---|---|---|---|
| Sync Labs | 本地视频 + 本地音频 multipart | 支持 | 公开合同未提供运行中取消 | 可进入真实冒烟 |
| fal.ai LatentSync | 视频/音频 data URI，队列提交 | 支持 | 支持队列取消 | 可进入真实冒烟 |

两个 Adapter 均实现统一 `LipsyncProvider` 接口。任何供应商字段、状态和异常必须在 Adapter 内归一化，不能泄漏到生产域模型。

## 3. 开发完成项

- 两个真实 Provider Adapter 和环境变量配置；
- HTTPS JSON/multipart 请求、受限下载和原子文件替换；
- Job ID 落盘、状态恢复、结果重拉和取消能力声明；
- Provider 状态统一为 queued/running/succeeded/failed/canceled/unknown；
- Provider 输出自动去音轨，并用 FFprobe 验证零音轨；
- 成功与失败报告记录估算成本、费用核对状态和恢复能力；
- 双 Provider 目录隔离，避免相互覆盖；
- 人工盲评字段和 Go / Conditional Go / No-Go 汇总器；
- 缺失密钥时在发起网络请求前失败；
- 单元测试不访问真实 Provider，也不产生费用。

## 4. 真实评测前置条件

1. 在仓库外准备 20～30 条、5～15 秒的授权样本；
2. 覆盖正脸、侧脸、遮挡、不同语速、情绪、多人画面、旁白和无人物；
3. 视频为无声画面，音频为已经锁定的项目主音轨；
4. 清单使用脱敏 `sample_id`，不含姓名、手机号、账号或公开下载链接；
5. 配置 API Key 和单位秒成本环境变量；
6. 为两家 Provider 设置独立预算上限并记录开始余额；
7. 确认本机 FFmpeg、FFprobe 可用。

## 5. 执行顺序

### 5.1 离线预检

- 执行 `--validate-only`；
- 执行全部 `test_lipsync_poc_*` 测试；
- 用 `mock` 验证清单、状态、报告和静音合同。

### 5.2 小流量冒烟

- 每家先跑 5 条；
- 每次提交后确认状态文件已经持久化真实 Job ID；
- 抽查供应商后台任务与本地 Job ID 一致；
- 确认输出为零音轨，且报告没有密钥和带查询参数 URL；
- 核对账单金额与估算成本。

任一条件不满足，停止扩大样本。

### 5.3 全量对比

- 固定同一份清单与输入哈希；
- 两家分别运行全部样本；
- 不覆盖另一家媒体、报告或人工评分；
- 完成人工双盲评分；
- 生成 `evaluation-summary.json`。

## 6. 中断、超时和费用处置

- 已有本地状态：普通运行必须拒绝，避免重复创建收费任务。
- 有 Job ID 且处于 queued/running/unknown：使用 `--resume`。
- 已成功且 Provider 支持结果重拉：使用 `--refetch`。
- failed/canceled：默认禁止恢复和重拉，除非 Provider 明确声明能力。
- 创建请求无响应且没有 Job ID：标记 `requires_reconciliation`，先到供应商后台按时间、输入和输出名核对，不得自动重提。
- 超时且支持取消：调用取消并再次查询最终状态。
- 超时且不支持取消：保留 Job ID 与费用待核对状态，继续人工跟踪。

## 7. 验收门槛

- 有效样本成功率 ≥ 95%；
- 人工可用率 ≥ 85%；
- 明显整句错位率 < 5%；
- AV 偏移 P95 ≤ 120ms；
- 身份保持平均分 ≥ 4/5；
- 所有成功结果均为零音轨；
- 所有报告均填写成本配置；
- 没有 `requires_reconciliation` 的费用悬案；
- 人工评分覆盖全部成功样本；
- 恢复、结果重拉和可取消 Provider 的取消路径实测通过。

资金、隐私、恢复或静音合同任一项失败，均不得给出 Go。

## 8. Go / No-Go 输出

- `go`：全部门槛通过，可确定默认候选并进入生产化架构阶段。
- `conditional_go`：质量可能合格，但人工评分、成本或非硬性证据不完整；不得接入生产扣点。
- `no_go`：成功率不足、音轨未移除、费用存在悬案或硬性安全门槛失败。

评测汇总只会从 `go` 候选中选择默认 Provider。若没有 `go`，`default_provider` 必须为空。

## 9. 下载安全与 fal 成本口径

- Provider 结果下载只允许 HTTPS。域名只解析一次，所有候选地址都必须是公网 IP。
- 下载连接必须直连本次已校验的 IP；原域名仅用于 HTTP `Host`、TLS SNI 和证书域名校验，禁止在连接阶段再次解析域名。
- 建立连接后必须核对实际对端 IP 与固定 IP 一致，阻断 DNS Rebinding。
- 当前禁止自动跟随 30x 重定向；如未来需要支持 CDN 重定向，每一跳都必须重新解析、校验并固定连接 IP。
- [fal.ai LatentSync 官方模型页](https://fal.ai/models/fal-ai/latentsync)价格口径为：输出视频不超过 40 秒时每条 `$0.20`，超过 40 秒时按输出时长 `$0.005/秒`。
- 成本统一按 `max(最低收费, 输出秒数 × 每秒费率)` 估算。默认最低收费为 `$0.20`、费率为 `$0.005/秒`。
- `FAL_LIPSYNC_COST_PER_SECOND_USD` 和 `FAL_LIPSYNC_MINIMUM_CHARGE_USD` 仅用于明确的价格覆盖；未设置时采用上述官方默认口径。
- 报告必须记录每秒费率、最低收费、按时长计算的金额、最终估算金额与价格来源。官方价格变化后应先更新测试和运行手册，再更新默认值。
