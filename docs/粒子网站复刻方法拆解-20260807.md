## 视频中的两段核心提示词

### 视觉生成

参考 GitHub 粒子变形项目的思路，使用 Three.js 将项目中的 `水母.glb` 模型表面转换为发光的粒子点云。搭建一个拥有深海美学、视觉效果惊艳的网页 Hero Section；粒子带有微弱、自然的呼吸与漂浮动画。

### 鼠标交互

为粒子点云增加鼠标交互：鼠标悬浮并靠近模型时，光标周围的粒子平滑向外扩散，形成排斥圈；鼠标移开后，粒子自然凝聚并重组为原来的结构。

## 真实技术原理

视频不是把 AI 视频塞进网页，而是使用一只真实的 GLB 网格作为粒子目标：

1. 读取 GLB 的顶点位置，整理成 `Float32Array`。
2. 把三维坐标写进浮点 `DataTexture`，每个纹理像素代表一个粒子的目标位置。
3. 使用 FBO（离屏浮点纹理）保存约 256×256，即 65,536 个粒子的实时位置。
4. 顶点着色器从位置纹理取坐标，`THREE.Points` 负责画粒子。
5. 片元着色器使用圆形衰减与加法混合制造发光点。
6. 鼠标位置通过 Raycaster 投射到 3D 空间；模拟着色器计算距离，在半径内施加排斥力。
7. 鼠标离开后，用弹簧回弹/阻尼让当前位置逐渐回到 GLB 表面的目标位置。

视频参考仓库本身实现的是“多个模型之间随滚动变形”，并没有完整的鼠标粒子排斥；鼠标排斥是视频后半段让 Antigravity 额外生成的功能。

## 对黄雀最有价值的结论

这条路线解决了我们此前最大的错误：不再让 Three.js 程序化拼一只鸟，也不依赖 AI 视频假装三维。

正确分工应该是：

- 3D 生成工具负责得到轮廓正确的飞鸟 GLB；
- Three.js/GPU 粒子系统负责质感、呼吸、漂浮、散开和重组；
- 页面设计负责字体、留白、叙事和按钮；
- AI 参考图只约束视觉风格，不承担网页动画本体。

## 最小复刻路线

1. 新建独立 `particle-bird-hero` 原型，不覆盖现有液态飞鸟和正式首页。
2. 使用 Three.js `MeshSurfaceSampler` 均匀采样模型表面，避免直接使用原始顶点造成翅膀粒子稀疏。
3. 首版不使用 FBO：一个顶点着色器即可完成 32k–65k 粒子、呼吸漂浮、鼠标排斥与平滑回位。
4. 只有需要粒子惯性、复杂流体或多个模型互相变形时，才升级为位置/速度双缓冲 FBO。
5. 只做一个 Hero 首屏；桌面端通过后再做手机降级。
6. 手机端把粒子数降为 16k–32k，并关闭昂贵的 Bloom 或降低 DPR。
7. 视觉通过后，再把这套粒子引擎抽成可换 GLB 的通用组件。
