## 目标与价值
`site/workbench/settings.html` 目前是"敬请期待"stub，但它是侧栏一级入口。用户在此**找不到改密码、退出登录、账号信息**——这些是设置页的基本诉求。把它做成可用页面。

## 现状（已核实）
- `settings.html` 是占位 stub（`data-active="settings"`），只有一句"敬请期待"。
- **auth 后端接口已现成，改密码/退出无需改后端**（`server/auth_server.py`，nginx 走 `/api/auth/`，均需 `Authorization: Bearer <token>`）：
  | 方法 · 路径 | 入参 | 返回 |
  |---|---|---|
  | `GET /api/auth/me` | — | 当前用户信息（username / 显示名 / points / role / must_change 等）|
  | `POST /api/auth/change_password` | JSON `{new_password}`（**≥6 位**）| `{ok:true}`；401 未登录 / 400 太短 |
  | `POST /api/auth/logout` | — | 注销当前 token |
- ⚠️ 注意：`change_password` **只需新密码、不校验旧密码**（靠登录 token 授权）。前端做"新密码 + 确认新密码"即可。
- 无团队成员接口 → 团队区先做**只读占位/示例**，不要臆造接口。

## 范围
- **纯前端**，只改 `settings.html`（复用现成 auth 接口）。**不改后端。**
- 若产品上确实要"改密码需验证旧密码"，那才需要后端加校验——本工单**不做**，保持用现有接口。

## 前端任务（`settings.html`，先读 `DESIGN.md`，风格对齐其它工作台页）
用左侧小分区或卡片式布局，包含：
1. **账号资料**：进页 `GET /api/auth/me` 展示用户名、显示名、角色、剩余点数（点数可链到 `recharge.html`）。
2. **修改密码**：两个输入框（新密码 / 确认新密码）→ 校验一致且 ≥6 位 → `POST /api/auth/change_password {new_password}` → 成功 toast。
3. **退出登录**：按钮 → `POST /api/auth/logout` → 清本地 token → 跳 `../login.html`。
4. **团队成员**：只读区，展示占位/示例（或"即将开放"），**不调不存在的接口**。
5. **计费/充值**：入口链到 `recharge.html`。
- 复用 `cloud-shell.js?v=15` 外壳、`data-active="settings"`；401 统一跳登录。

## 边界与注意
- **只改前端**；其它页面/后端不动。
- `change_password` 不需要旧密码——UI 别放"旧密码"输入框误导（或放了也不传给后端）。
- 未登录进设置页应跳登录。

## 验收标准
1. 设置页不再是"敬请期待"，能看到账号资料（来自 /api/auth/me）。
2. 改密码端到端生效：改完用新密码能登录、旧密码失效。
3. 退出登录清 token 并跳登录页。
4. 团队/计费区展示合理（团队只读占位，计费能跳 recharge）。
5. 无控制台报错；其它页面不受影响。
