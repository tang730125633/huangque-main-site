# 端口暴露审计说明

`RESIL` 工单里的端口收敛涉及服务器上多个非黄雀系统，例如 dify、xiaotan、zhipu-proxy、cups、openclaw。按工单约束，这些端口不能由开发 agent 擅自关闭或改防火墙，必须先识别归属并由负责人确认。

本次只新增只读审计工具：`scripts/port_exposure_audit.py`。它读取 `ss -lntp` 的监听端口输出，标记黄雀内部端口是否误绑到公网，并把需要人工确认的非黄雀端口列为 `REVIEW`。

## 使用方式

在服务器上只读执行：

```bash
python3 scripts/port_exposure_audit.py
```

需要保存或复核时：

```bash
ss -lntp > /tmp/listeners.txt
python3 scripts/port_exposure_audit.py --input /tmp/listeners.txt
python3 scripts/port_exposure_audit.py --input /tmp/listeners.txt --json
```

脚本不会修改 systemd、nginx、ufw、iptables 或任何运行中进程。退出码含义：

- `0`：没有发现 `WARN` 或 `REVIEW`。
- `1`：读取或解析命令失败。
- `2`：存在需要处理或确认的暴露端口。

## 判定规则

应对公网开放：

- `80`
- `443`

黄雀内部端口应只监听 `127.0.0.1` 或 `::1`：

- `8090`：legacy leadgen
- `8091`：leadgen-A
- `8092`：leadgen-B
- `8095`：auth
- `8096`：content
- `8097`：download
- `8098`：admin
- `8100`：leadgen-api
- `8101`：imggen-api

需要负责人确认后才能收敛的端口：

- `631`：cups
- `3001`：wechat decrypt
- `3002`、`5002`、`5003`：dify
- `8099`、`8102`：zhipu-proxy
- `8501`：xiaotan
- `1890-1893`、`18789`：openclaw

## 后续收敛流程

1. 先运行审计脚本，保存输出。
2. 对每个 `REVIEW` 端口确认服务归属、是否仍在使用、是否需要公网访问。
3. 对确认无需公网访问的端口，另开工单做防火墙或监听地址收敛。
4. 收敛必须走 PR、审核和 `ship`，禁止直接 SSH 热改服务器。
5. 收敛后再次运行审计脚本，并确认漂移哨兵无新增告警。
