# 工单 · F5 视频批量生成

> 供其他 agent 独立执行。开工前先读《工单-其他agent实施-20260703》§0 公共上下文 + 《任务看板》领取流程。
> **冲突组：A（后端核心 content_api/content_domains）+ B（video.html）** —— 认领需同时抢到 `lock/A` 和 `lock/B`。

## 目标与价值
现在视频一条一条生成。加**批量**：一次提交多条（如"一个文案 × 多个数字人形象"，或"多条文案"），排队产出。内容工厂效率。

## 现状（已核实）
- 前端 `site/workbench/video.html`：`submitVideo`/`submitMotionVideo` → POST `/api/gen/video`，每次一条 → 返回 job_id → 轮询 `/api/gen/job/<id>`。
- 后端：HTTP 层在 `content_domains/core.py`，`gen_video` 在 `content_domains/video.py`；任务模型是**每提交起一个线程 `run_job`（并发）**、点数预扣失败退。
- 视频走 HeyGen（贵、有配额/速率）。

## 技术设计
### 后端（**关键：并发上限，防 HeyGen 429**）
- 给**视频任务**加并发信号量（类似 F4 whisper 的 `BoundedSemaphore`）：`VIDEO_MAX_CONCURRENCY`（env，默认 2）。`run_job`/`gen_video` 里视频生成前 acquire、完成 release，超出的**排队**而非并发打满。
- 位置：并发控制放 `core.py`（调度层）或 `video.py`（gen_video 入口），就近实现；**不改单条生成逻辑、不改点数语义**（每条仍各自预扣/失败退）。
- 批量提交仍是"前端多次 POST /api/gen/video"，后端**不需要新批量接口**——靠并发信号量把节奏压住即可。若要更好，可加一个可选 `/api/gen/video/batch`（一次收多条、内部逐条入队），但非必需。

### 前端（`video.html`）
- 加**批量模式**：让用户一次配多条任务。最小可行：
  - "一个文案 × 多形象"：选文案/参数 + 勾选多个「我的形象」→ 一键提交 N 条；或
  - "多条文案"：多行文案，每行一条。
- 提交 = 循环 POST `/api/gen/video`（复用现有 submit 逻辑），收集 job_id；**批进度聚合展示**（N 条各自状态，复用现有 job 轮询 + F3 进度）。
- 批量下载可复用资产页/F7 思路，或提供"全部完成后打包"。
- 成本提示：批量前显示"共 N 条 × 单条点数 = 总点数"，让用户确认，避免误扣一大笔。

## 边界与注意
- **并发上限务必生效**（默认 2）——这是 F5 的安全底线，别让 10 条视频同时打 HeyGen。
- 点数：每条独立预扣/退，语义不变；批量前给总点数确认。
- 不改口播/动作模仿单条流程；不勾批量时行为与现状一致。
- 改后端基于 T8 后的 `content_domains` 结构。

## 验收标准
1. 能一次提交多条视频任务（多形象或多文案），各自产出。
2. **同时运行的视频生成数 ≤ 上限（默认 2），其余排队**；不触发 HeyGen 429。
3. 批进度能看到每条状态；批量前有总点数确认。
4. 单条生成、口播、动作模仿均不受影响；`py_compile` 通过、health 200、无控制台报错。

## 部署与验证
- `./ship "F5 视频批量生成(并发上限)" server/content_domains/core.py server/content_domains/video.py site/workbench/video.html`
  （ship 已支持 content_domains 目录同步）
- 上线后实测：批量 3–5 条 → 并发受控、逐条完成；确认漂移哨兵无新增告警。
