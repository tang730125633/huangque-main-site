# 工单 · 资产删除功能（用户自助管理资产）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 + 《开发手册》+《任务看板》领取流程。
> **冲突组：A（`server/content_domains/**`）+ C（`site/workbench/assets.html`）** —— 抢 `lock/A` 和 `lock/C` 两个锁（跨组，两个都抢到才能开工）。

## 目标
资产库页让用户能**删除自己的资产**（图片 / 音频 / 视频 作品），自助管理。**形象(avatar) 已有删除**（`/api/gen/video/avatar-delete`），本工单不动它，只加 图片/音频/视频 三类。

## 现状（已调研，照此实现）
资产页三类数据源：
- **图片** → `GET /api/gen/history?kind=image`（**jobs 表**，`core.py` 682 行）
- **音频** → `GET /api/gen/audio/assets`（**audio_assets 表**，`audio.py:654`）
- **视频** → `GET /api/gen/video/assets`（**video_assets 表**，`video.py:94`）

现成可复用的模板/助手：
- **软删模板**：`video.py:185 delete_video_avatar()`（`status='deleted'` + `WHERE ... AND username=?` owner 限定）。
- **加列迁移**：`core.py` 里的 `_ensure_column(c, 表, 列, 类型)`（幂等加列，见 223 行用法）。
- **删除路由模板**：`core.py:545` 的 avatar 删除；**前端删除模板**：`assets.html:576` 的 `avatar-delete` fetch。

## 要做

### 一、后端（`server/content_domains/`）—— 统一软删接口
新增**统一端点** `POST /api/gen/asset/delete`，body `{kind, id}`（`kind` ∈ `image|audio|video`），风格对齐已有 `/api/gen/asset/favorite`：
1. `verify` 鉴权，未登录 → 401。
2. 校验 `kind` 合法、`id` 存在，否则 400。
3. 按 kind 分派**软删**（全部 owner 限定 `WHERE ... AND username=?`，删的不是自己的 → 返回 **404**「资产不存在或不属于当前账号」，不泄露存在性）：
   - **video**：`video_assets` 有 `status` 列 → `UPDATE video_assets SET status='deleted' WHERE id=? AND username=?`。
   - **audio**：`audio_assets` **无 status 列** → 先用 `_ensure_column(c,"audio_assets","deleted","INTEGER DEFAULT 0")` 加列，再 `UPDATE ... SET deleted=1 WHERE id=? AND username=?`。
   - **image**：作品在 **jobs 表** → 用 `_ensure_column(c,"jobs","deleted","INTEGER DEFAULT 0")` 加列，`UPDATE jobs SET deleted=1 WHERE id=? AND username=? AND kind='image'`。
4. **列表接口同步过滤已删**（关键，否则删了还显示）：
   - `list_video_assets`：SQL 加 `AND status!='deleted'`（当前没过滤，务必补）。
   - `list_audio_assets`：加 `AND a.deleted=0`（用 `COALESCE(a.deleted,0)=0` 防旧行 NULL）。
   - `/api/gen/history`（image）：加 `AND COALESCE(deleted,0)=0`。
5. 顺带清理该资产的收藏/标签标记（可选，若容易做就做；用 `assetKey` 对应的 mark key）。
- **软删不删磁盘文件**（保持可逆、避免误删断链；物理清理留作以后的独立清道夫，不在本工单）。
- **不扣点、不加 must_change 拦截**（删除是自助清理，非生成/消费）。

### 二、前端（`site/workbench/assets.html`）
1. 每个资产卡片（图片/音频/视频三类）加一个**「删除」按钮**（`.asset-action` 风格，可用醒目色区分）。
2. 点击 → **二次确认**（如 `confirm('确定删除该资产？删除后将从资产库移除')`）。
3. 确认后 `POST /api/gen/asset/delete {kind, id}`（模板见 576 行 avatar-delete fetch）：
   - 成功 → 从网格移除该卡片 + `toast('已删除')`；空了则回到空态。
   - 失败 → toast 报错。
4. `id` 取值：video/audio 用资产的 `id`，image 用 job 的 `id`（`x.id||x.job_id`，与列表返回字段对齐，实测确认）。

## 边界
- 只加 图片/音频/视频 删除；不动 avatar 删除、不动生成主流程。基于 T8 后 content_domains 结构 + MARK 后的 assets.html。
- 保持 `DESIGN.md` 视觉规范（删除按钮样式与现有 `.asset-action` 一致）。

## 验收标准
1. 三类资产各能删自己的：删后**立即从资产库消失**，刷新后仍不在（列表已过滤）。
2. 删别人的 / 不存在的 id → 404，**不影响任何数据**。
3. 未登录 → 401。
4. 删除后对应作品在「重生成」「收藏」等其它入口也不再出现（列表统一过滤生效）。
5. avatar 删除、生成、收藏/标签等原功能不受影响；`py_compile` 通过、health 200。
6. 磁盘文件保留（软删），可逆。
