# AI 创作助手 V1 设计与并行边界

## 产品目标

主站新增独立标签页「AI 创作助手」，页面标题为「黄雀创作 Agent」。
用户在同一个持续对话中完成独立个人画像建档、选题与文案创作，以及模板视频制作。
Creator Agent 直接调用 DeepSeek V4 Flash，不运行时调用、不读写同事的 IP12 服务。

首版只支持：

- 独立模块 1-4 画像建档、候选方案确认与版本化存档；
- 独立内容策划生成选题计划与最终文案；
- 抖音、小红书、视频号的模板视频制作；
- 查看当前进度、内容成果、视频任务及历史版本。

不包含公众号、B 站、自动分发、图片生成、配音、数字人口播或其他生成工具。

## 用户旅程

### 进入页面

- 未登录：跳转登录，成功后返回 AI 创作助手。
- 没有独立画像：自动创建「我的个人画像」，直接从模块 1 开始引导。
- 有未完成画像：自动恢复上次未完成步骤。
- 有完整画像：直接显示「开始制作视频」「生成选题计划」「修改我的画像」。
- 有两个画像项目：顶部画像按钮显示当前项目，点击后选择或切换；每个项目独立保存对话、偏好、成果和任务。
- 每个画像只有一条持续对话，不提供新对话或历史会话列表。

### 画像建档

1. 模块 1-4 只定义画像字段目标与顺序；实际问题、回答参考和小范围选项均由 DeepSeek
   根据已知答案动态生成，Agent 每次只问一个自然问题。
2. 每次自由输入、选项、跳过或“下一题”都先由 DeepSeek 理解并生成完整回复；后端只执行
   `answer / skip / clarify` 结构化动作，不能用关键词规则代替模型理解。
3. 每个模块完成后先展示结构化总结，用户在左侧对话确认或修改后再继续。
4. 模块 4 完成后生成独立个人画像存档，确认后才开放内容与视频创作。
5. 用户可随时在对话中修改画像；历史作品不变，后续作品使用最新版画像。

Creator SQLite 是本功能的画像正本。画像修改作为版本化补充保存，后续创作优先读取最新版，
不访问、不回写同事的 IP12 Agent 内核，也不改变历史作品。

### 生成选题计划

- 快捷入口「生成选题计划」调用独立 DeepSeek 内容策划流程。
- 没有明确选题时生成完整的至少 15 个选题计划，再生成文案。
- 已有明确选题时允许缩短模块 5，直接围绕选题完成模块 6。
- 结果止于最终文案并保存到 Creator 自己的内容成果，不调用视频、不报价、不扣点。
- 用户可继续通过对话修改或重新生成文案。

### 制作模板视频

1. 用户说明选题或核心观点。
2. 首次选择抖音、小红书、视频号，可多选；之后默认最近使用的平台，生成前可调整。
3. 未说明内容目标时，Agent 根据画像与本次内容自动判断，不追加无必要问题。
4. Agent 为每个平台分别生成方案卡：顶部标题、底部行动文案、推荐模板、推荐理由和素材包。
5. 当前模板服务只接受平台素材库，因此 V1 自动选择抖音、小红书或视频号的平台素材库。
   用户自建素材包与未来公共素材库保留为后续合同；在上游支持素材输入前不得伪装成已使用用户素材。
6. 用户可通过对话逐个平台修改或重新生成，全部确认后才统一询价。
7. 展示各平台价格明细和总价，左侧仅提供一个真实确认按钮。
8. 后端按平台创建独立任务；单个任务失败只退该任务点数，不影响其他平台任务。
9. 成功视频可在右侧预览、播放、下载和查看版本。成功后再次生成必须重新报价、确认和扣点。

## 双栏交互

### 左侧：Agent 对话

- 所有提问、选项、自由输入、画像确认、方案修改、报价确认都在左侧完成。
- 所有用户消息都经过独立 DeepSeek：自由文本由 DeepSeek 识别意图并提取主题/平台，后端完成
  受控状态或工具操作后，再由 DeepSeek 生成最终回复。显式按钮操作也必须经过 DeepSeek 回复。
- 快捷入口只负责发起意图，不绕过 Agent 流程。
- 普通聊天不能触发扣点；模型不能代替用户确认付费。

### 右侧：展示窗口

右侧只展示，不放决策按钮，包含三个标签：

- 当前进度：画像模块、当前创作阶段和待处理事项；
- 内容成果：独立个人画像、模块候选、选题计划、文案及其版本；
- 视频任务：分平台状态、失败退款、视频预览、播放和下载。

## 偏好记忆

- 偏好独立写入 `template_video_preferences`，不修改已确认画像的核心事实。
- 同时保存全局偏好和抖音、小红书、视频号的平台偏好；平台偏好优先。
- 只有「以后」「我喜欢」「不要再」等明显长期表达自动写入；本次指令只影响当前任务。
- 不询问是否保存。用户可在对话中查看、修改或清空偏好。

## 计费与安全

- 画像建档、画像修改、普通对话、选题计划和文案生成免费。
- 只有模板视频正式生成扣点。
- 报价令牌、任务 ID、内部令牌和幂等键不能返回浏览器。
- 报价后参数变化必须作废旧报价并重新询价。
- Auth 报价返回签名凭证中的绝对 `expires_at`；Creator Agent 在 batch/job 同时保存最早到期时间、
  费用和输入摘要。报价过期或剩余时间不足时原子清理旧报价并重新询价。
- 确认扣点前必须为全部平台保留覆盖顺序提交和中断恢复租约的安全余量；余量不足时不改变 batch/job 状态、
  不调用 Provider，并在对话中重新展示报价。浏览器持续显示报价倒计时。
- 确认请求绑定用户实际看到的绝对到期时间；自动重报后，旧确认不能用于新报价。
- 网络结果不确定时只能查询原任务，禁止换幂等键重复提交。
- 内容服务在扣点前持久化不可变 submission attempt，冻结账号、endpoint、child idempotency key、
  输入摘要、规范化输入、价格以及 charge/refund transaction key。状态按
  `prepared → charging → charged → linked` 推进，建任务失败则进入
  `refund_pending → refunded`；启动恢复与 30 秒扫描器会接管 stale lease，且只能复用原
  transaction key。每次接管先查询 Auth 点数流水，再决定是否扣点、建 job 或确认退款。
- 任务写入、attempt `linked` 和可回放 `job_id` 在同一 SQLite 事务提交。响应丢失后由
  Creator Agent 走受控 reconcile 通道查询或恢复既有 attempt；缺少 attempt 时不能扣点或建任务。
- 批次编辑、报价、确认和刷新使用 SQLite `BEGIN IMMEDIATE`、plan revision/hash 与条件更新；
  确认后 Provider 只能读取已冻结的提交快照。
- 浏览器在请求前持久化完整 body、request ID 和 confirmation ID；网络错误或 5xx 后使用原请求恢复，
  明确 4xx 或终态后才清理 pending。
- 所有 DeepSeek 调用在 Provider 前经过 SQLite 持久资源闸：账号 20 次/分钟、IP 30 次/分钟、
  单用户并发 2、全局并发 8；用户/全站每日请求、预估 token 与微美元预算分别持久累计，
  服务重启或切换画像项目不能清零。连续 Provider 失败会打开 60 秒熔断。
- 金额预算按 `deepseek-v4-flash` 峰值 cache-miss 价格保守预留：输入 $0.44/百万 token、
  输出 $1.32/百万 token。价格版本和每百万 token 的微美元整数值写入环境配置及调用记录；
  运行时配置只能提高默认峰值，不能通过调低价格绕过金额上限。历史无版本记录按较高的输出价重估。
  业务输入按 UTF-8 字节数作为 token 上界，并额外预留 8192 token 覆盖固定系统提示和请求封装；
  该预留也只能调高。价格基线以 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/) 为准。
- nginx 对 `/api/creator-agent/messages` 另设 IP 请求与连接上限；任一闸门拒绝均返回 429，
  且不得调用 DeepSeek。Creator 路由由 nginx 覆盖 `X-Real-IP`/`X-Forwarded-For` 为连接源地址，
  服务优先使用 `X-Real-IP`，客户端伪造的转发链不能切换持久 IP 计数桶；`/messages/`
  尾斜杠路径由 nginx 和应用双重拒绝，不能落入未限流的通用路由。
- 画像状态、assistant 消息和 user request 的可回放 turn 在同一 SQLite 事务提交；模型返回后在
  任一写入断点退出，重试同 request ID 都只能推进零次或一次，不会无限 `idempotency_in_progress`。
- 非画像回合的 assistant 与可回放 turn 同样单事务提交。选题成果按来源消息 ID 固定键保存；
  新视频批次和方案修改分别持久化来源/修改消息 ID；报价与确认沿用原有 claim 和 provider 幂等键。
  因此业务副作用落库后进程退出时，同 request ID 会恢复原成果，不会重复建批次、改两次方案或重复扣点。
- DeepSeek 画像候选严格校验 `title`、`one_liner`、`strengths`、`risks` 的类型、数量和长度；
  选题计划严格校验至少15个唯一标题、推荐项引用关系，以及 scripts 的平台和正文结构。
  任一字段不完整都按模型响应失败处理，不写入画像、成果或视频草案。

## 并行开发边界

- 不修改同事的 `server/hermes_ip12/**` Agent 实现、Master Agent、SDK Canary 或 PR #1264。
- Creator 不配置 IP12 URL，不调用 IP12 API/CLI，不读取 IP12 Project 或 PDF。
- Creator Agent 使用独立服务 `huangque-creator-agent`、端口 `8114`、SQLite 和环境文件。
- 模型固定为官方 `deepseek-v4-flash`，Base URL 为 `https://api.deepseek.com`；Key 使用独立
  `CREATOR_AGENT_API_KEY`，缺失或模型名不匹配时 `/health.ready=false`，不得降级为规则回复上线。
  健康检查缓存读取官方 `/models`，Key 无效或模型不可达时同样 `ready=false`。
- 主站账号、点数、任务、退款与资产库仍是业务正本。
- 功能开关 `creator_agent_v1` 默认开启；关闭时隐藏入口并禁用服务接口。

## 发布边界

本分支只开发和本地验证。未经单独授权，不推送 PR、不合并、不部署生产。

正式发布必须先通过主站 ship 同步 `auth_server.py`、完整 `content_domains` 依赖与前端，
再执行 Creator Agent 版本化 release。Creator `/health.ready` 会要求 Auth 已实际探测到
Content 的只读 reconcile 端点；依赖未同步时 release 必须失败并回滚。
