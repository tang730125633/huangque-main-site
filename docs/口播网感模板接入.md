# 口播网感模板（ip-editorial-serif-v1）

## 用户得到什么

上传**已经拍好的、带原声的 9:16 口播视频**，让 Agent 选择“口播网感模板”。
保留原人物和原声，在已确认的剪辑区间上套用已验收的宋体标题、红色关键词、
中英双语字幕和关键词快速推近/缓出。不是照片生成数字人，不调用 HeyGen。
首版成片为 720×1280 / 30 fps / H.264 + AAC，长度 3–180 秒。
横屏不自动裁切；无声原片、缺少英文翻译、无有效词级时间证据的关键词动作拒绝生成。

本 PR 是**后端执行器和 CLI 契约**，不是已完成生产上线。不会自动发布社交平台，
不会自动安装服务器软件，不修改旧的三种模板。现有网页模板选择器尚未增加本模板入口。

## 调用分工

用户 → IP12 主 Agent → 视频剪辑子 Agent → HQ CLI → 鉴权代理 → video-compose 项目
→ 确认 EDL → 固定 HyperFrames 渲染器 → 质检 → 私有作品资产。

- 主 Agent：识别模板名称、接收上传的资产、说明处理范围并取得确认。
- 子 Agent：读转写和候选剪辑区间，生成短句中英文字幕、关键词及时间计划。只能生成数据，不能提交 HTML/JS/命令。
- Skill：解释以上调用顺序与约束；不是视频执行器，也不能代替服务器功能。
- CLI：校验完整 JSON、权限和写入确认，传递 `template_id` 与 `editorial_plan`。
- 后端：绑定当前用户的源资产、transcript_hash、EDL 版本和 revision；执行及保存结果。

**Agent 源码接入缺项**：此前只读核查的生产 hq-ip-agent origin 是服务器本地 bare 仓库，
尚未确认正式 GitHub 源库。本 PR 不修改该目录。正式源码核定后，须增加模板名称到固定 ID 的路由、
调用本文件流程、失败恢复和实际端到端验收；不能宣称仅安装后端就已经打通主 Agent。
公开的 huangque-agent-skill 是通用 HQ 使用说明，不等于生产主/子 Agent 路由源码。

## CLI 顺序（执行前先 describe，不硬编码未知 ID）

```sh
hq describe video-compose-import --json
hq describe video-compose-create --json
hq describe video-compose-analyze --json
hq describe video-compose-review --json
hq describe video-compose-render --json
hq describe video-compose-project --json
# 用户确认上传后：
hq run video-compose-import --file /absolute/path/input.mp4 --confirm --json
hq run video-compose-create --input @create.json --confirm --json
hq run video-compose-analyze --input @analyze.json --confirm --json
hq run video-compose-project --input @project.json --json
hq run video-compose-review --input @review.json --confirm --json
hq run video-compose-project --input @project.json --json
hq run video-compose-render --input @render.json --confirm --json
hq run video-compose-project --input @project.json --json
```

各文件是 UTF-8 JSON。`source_asset_id` 取上传响应的实际资产 ID；`project_id` 取创建响应。
`analyze.json` 是 `{project_id, expected_revision}`，分析调用可能消耗既有 ASR 服务额度，
必须沿用该能力的确认规则；此 PR 的测试不调用外部 ASR。
轮询的是 `project_id`，**不是**通用 `job_id`，CLI 不承诺自动等待渲染完成。

`review.json` 为 `{project_id, expected_revision, decisions: {candidate_id: "keep"|"remove"}}`。
默认保留全部候选；只有用户批准具体删除范围才填 `remove`。必须覆盖全部候选 ID。
若候选列表为空，传 `{}`，仍由后端严格核对，不能跳过确认阶段。
确认后重新 GET，取新的 `revision`、`transcript_hash`、`edit_decision_version` 与 `edl`。

### 时间基准和翻译责任

所有视觉时间单位为秒，基于**剪辑后的成片**。转写 `words` 是原片毫秒时间。
逐个将完全位于一个 `edl.keep_ranges` 内的词映射为 `output_start_ms + 原词时间 - source_start_ms`。
删除区间和跨切口词不可使用。关键词动作须落在真实词起点 ±80ms，不能按句长猜时间。
ASR `provider_word` 或人工校正 `user_supplied` 可以使用；`segment_interpolated` 仅为估算，
不可冒充词级对齐。没有合格词级数据时先校正转写，或征得用户同意取消关键词推近，不能静默退化。

Agent 负责按原意译出英文、按实际转写制作短句、检查内容和画面安全区。
服务不自行调用翻译模型，也不能仅凭 JSON 校验判断英文语义准确；需 Agent 复核。
标题两行，每行最多 12 个中宽单位；中文短句最多 10.5 中宽单位，英文每行最多 58 字符。
人物始终为主画面，但景别推近会裁掉原片外围；人脸贴边素材应先调整构图，不承诺人脸自动追踪。

### 失败和幂等

- 新模板或未知参数不能静默降级为旧模板。
- 同一项目在渲染中/已完成时，相同计划重复请求返回原任务；不同计划或不匹配 revision 返回 409。
- 渲染失败后读取最新 revision 再重试；原任务没有完成前不能盲目新建多次消耗算力。
- 进程重启恢复沿用现有 interrupted-render 标记，失败项目可使用最新 revision 重试。
- 新模板最多两个已接收渲染请求，共用单个 worker；队列满明确失败，不永久 rendering。
- 字体哈希、格式、画幅、时长或现有媒体质检失败，不登记为成功资产。输出先暂存后原子替换。
- 输出沿用用户鉴权下载；本 PR 不新增公开分享地址、扣点、数据库结构或自动发布行为。

## 运行条件与部署前置检查

该模板使用独立锁定的 HyperFrames **0.8.33**，不替换旧模板的运行时：

1. Node 22+；FFmpeg/FFprobe（libx264、AAC、loudnorm 等功能）；可执行的 Chromium 浏览器及 Linux 系统依赖。
2. 通过 `tools/hyperframes/ip-editorial-serif-v1/package-lock.json` 安装独立 runtime。
   默认包目录 `/opt/huangque/editorial-hyperframes-0.8.33/node_modules/hyperframes`。
3. 管理员显式配置 `VIDEO_COMPOSE_EDITORIAL_RUNTIME`（可选覆盖）、`VIDEO_COMPOSE_EDITORIAL_NODE`（可选）
   和 `VIDEO_COMPOSE_EDITORIAL_BROWSER`（必需、绝对可执行文件路径）。请求中不可指定这些路径。
4. 打包 `site/assets/one-click/templates/ip-editorial-serif-v1/` 全目录。
   中文 Source Han Serif SC Heavy、英文 Noto Sans SC、对应 OFL 文件和 GSAP 均为本地资源，
   代码固定哈希不从用户计划或可改写 lock 文件读取。
5. 运行身份必须能够读取代码/字体/runtime 并在现有 content 输出目录写入私有临时目录。
   不需要 GPU；实际耗时、CPU 和峰值内存需发布前目标服务器压测，不作实时生成承诺。
6. Linux 必须同时发布 `server/content_domains/editorial_process_supervisor.py`，使用与 content
   相同的 Python 运行，需可用的 `/proc/self/task/<pid>/children` 和
   `prctl(PR_SET_CHILD_SUBREAPER)`；普通非 root 身份即可，不需要 sudo、全局 pkill 或修改 systemd。
   监督器在启动 Node 前设置任务专属 subreaper，Puppeteer detached Chrome 与双重 fork 子孙
   都属于该次任务；正常/失败退出同样回收残留。超时先给 Node 1 秒 SIGTERM 退出机会，
   再逐层终止被收养的直属子进程并 waitpid，必须到 ECHILD 才返回。
   若超过请求超时加 15 秒仍不能完成清理，content 保留监督器继续回收并记录 CRITICAL，
   熔断当前进程的新 editorial 渲染；不可自动重试、杀掉监督器后假定清理成功。
   运维须根据日志中的精确 supervisor PID 排查/确认所属进程已退出，再按授权流程重启 content
   解除熔断。监督器异常死亡同样熔断。Windows 仍使用原 taskkill `/PID /T /F` 路径。

先执行只读前置检查：

```sh
python scripts/check_editorial_runtime.py
```

该命令不安装软件、不启动生产生成、不写文件。带 `--output-dir` 才会生成完全合成的 5 秒测试片，
输出目录必须尚不存在。它会校验真实渲染的编码、单音轨、30fps、时长和媒体质检：

```sh
python scripts/check_editorial_runtime.py --output-dir /approved/private/new-smoke-directory
```

**生产上执行后一个命令属于写操作，必须事先授权。** CI 只在 GitHub 临时 runner 上做 smoke。
本 PR 没有安装生产插件、修改 systemd、重启服务或变更环境变量。

Linux CI 额外以非 root 身份运行以下真实故障回归（严格核验完整 lock 的
Puppeteer 25.10.0 / browsers 3.2.2，使用真实 Chrome、FFmpeg 和普通/分离子进程）：

```sh
python scripts/check_editorial_process_cleanup.py --output-dir /approved/private/new-cleanup-evidence
```

回归覆盖优雅与强制超时、连续超时、双重 fork、成功/失败后的残留回收、无关哨兵隔离及
随后新任务可用性，保存实际 PID/启动时间/进程组、耗时和零残留断言。此命令同样不应在
未授权的生产环境执行。

## 发布和回滚

PR 精确 Head 的 Linux/Windows CI、独立审核、CLI 配套版本及目标服务器 readiness 全部通过后，
另行申请一次具体生产发布确认。主站 auth 的 `hq_cli_api.py` 也导入共享 `editorial_contract`，
因此 content 与 auth 代码依赖必须完整发布，不能只拷贝 renderer 文件。
公共 CLI 与主站随附 CLI 的既有版本不同，不能覆盖已发布 wheel；正式 release 需独立版本、
锁定 wheel SHA 和 installer，同步通用 Agent Skill 的兼容性清单。

发布前备份本次精确文件与原权限；保持旧模板调用不变。回滚时停止新模板提交、等待本次 worker 退出，
恢复备份代码/runtime 配置并按授权流程重启必要服务。无数据库迁移；已有作品和用户原片保留，
不回滚/删除数据库。验证原模板、health 200、未登录接口 401、不同用户不能读取作品。

## 来源与验收证据

视觉编译器由用户已确认的本地双语关键词推近版移植，保持字体、标题、字幕位置和动作参数。
唯一可读性补丁是英文行后增加随文字宽度的窄幅半透明深底，避免白字在亮背景消失；不遮挡整块画面。
不提交用户原视频、头像、转写、生产日志或凭据。测试使用合成内容。
单元测试覆盖客户端/鉴权代理/内容服务契约、所有权、版本、重复请求、资源漂移、错误/并发/恢复。
单元测试和合成渲染不能代替最后的真实用户样片及主/子 Agent 端到端验收。
