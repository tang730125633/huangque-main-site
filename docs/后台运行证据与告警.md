# 后台运行证据与告警

目前仅接入麦克视频 MiniMax-H3：提交、供应商接单、查询、生成及下载。恢复任务单独记录恢复阶段，不推测原始提交。每阶段保留首次时间及最近一次状态、耗时，不是逐次 HTTP 请求日志。

记录中的 recorded 仅代表该调用返回，不代表成品验收通过。提交超时或缺少供应商编号是 unknown，不能认定没有创建供应商工单。成品核验与账务仍使用既有证据检查器；本模块不把下载完成当作用户已收到作品。

实际证据存放在独立私有 SQLite 文件，默认 server/runtime_observability.db，可由 HQ_OBSERVABILITY_DB 配置绝对路径。服务账号需要读写权限，内容服务与后台服务必须指向同一文件。该文件不进入 Git，不变更共享 jobs/users 数据库结构。

后台实时任务详情显示实际执行记录；旧任务或采集失败时不生成推测记录。记录只允许供应商、模型、目标主机名、直连标志、供应商工单号及异常类型，不记录密钥、提示词、作品 URL 或原始异常文本。

## 告警

默认关闭。HQ_ALERT_ENABLED=1 且 HQ_ALERT_WEBHOOK_URL 有效时，基础服务巡检会发送已确认异常和恢复事件。接收端需接受 JSON POST，并以 Idempotency-Key 去重。该接口是通用 webhook，不直接假定兼容飞书或其他机器人协议。

仅发送 event、service、occurred_at。HTTPS 为正式接收端协议；本地测试允许 loopback HTTP。不跟随重定向，不使用环境代理。收到 HTTP 2xx 仅表示接收端接受，不保证开发者已阅读。

异常仍由既有连续失败阈值确认；仅状态转换入队，避免每次巡检重复告警。未发送事件持久保存，按退避策略重试，最多 5 次，每轮最多 5 条。多实例部署需指定单一通知发送实例；当前未实现跨进程领取锁。

启用后会补发队列中此前未发送的事件，接收端应按 occurred_at 判断时效。后台总览显示未启用、待发和发送失败数量；队列满 5 次失败后须由运维排查接收端并处理失败记录。

## 当前边界

- 本地测试仅使用模拟供应商和本机通知接收端，不触发真实付费生成或外部消息。
- 尚未接入其他生成渠道的任务级代理、路由和耗时证据。
- 这里只通知基础服务巡检状态变化，功能 E2E 失败和单个客户任务失败尚未接入告警。
- 媒体可解码不等于用户实际收到；不能据此宣称完整用户旅程已验收。
- 未部署；生产启用前需确定实际通知接收端、单实例职责、文件权限与保留周期。
