# 工单 · 小程序专属登录/注册接口

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》。
> **冲突组：D（`server/auth_server.py`）** —— 锁 `lock/D`。

## 背景
黄雀AI小程序上线（kongli 最高优先级任务），小程序前端(另由 Claude Cowork 在沙箱开发)需要登录态，但存在两个限制：
1. 小程序 `wx.request()` 不像浏览器那样自动带 httpOnly cookie，无法复用网站现有 `/api/auth/login` 的 cookie-only 鉴权。
2. 微信原生手机号登录(`getPhoneNumber`)需要后端管理 AppID/AppSecret + access_token，且现有 `users` 表无手机号字段无法跟老账号自动匹配——范围较大，本工单不做，留作后续独立阶段。

第一阶段方案：小程序内走"用户名+密码"登录/注册（复用现有账号体系），新增两个专属接口在响应体里返回 token 供小程序自行存储、后续走 `Authorization: Bearer` 请求头。**网站现有 `/api/auth/login`/`register` 完全不动**，仍只走 httpOnly cookie（SEC-XSS-P3-CLEANUP #363 的安全加固不受影响）。

## 改动
`server/auth_server.py` 新增两个 handler：
- `POST /api/auth/miniprogram-login`：同现有 login 校验逻辑(含登录失败限流)，成功返回 `{"token":..., "user":{...}}`。
- `POST /api/auth/miniprogram-register`：同现有 register 校验逻辑(含注册限流/字段校验)，成功返回 `{"token":..., "user":{...}}`。

`tests/test_auth_points.py` 新增2个测试：
- `test_miniprogram_login_returns_token_usable_as_bearer`：验证登录返回token，且能用作`Authorization: Bearer`访问`/api/auth/me`。
- `test_miniprogram_register_returns_token_and_creates_user`：验证注册返回token+建号成功。

## 已验证
- `python3 -m unittest discover -s tests`：47/47 通过（含既有的"网站登录仍无token"回归保护测试，未受影响）。
- `python3 -m py_compile server/auth_server.py` 通过。

## 验收标准
1. 小程序用现有网站账号(用户名密码)能登录/注册，拿到token。
2. 网站原有登录/注册行为完全不变(仍只走cookie，响应体无token)。
3. 拿到的token能正常用于其他现有接口的 `Authorization: Bearer` 鉴权(作图/视频等)，无需改动其他接口。
