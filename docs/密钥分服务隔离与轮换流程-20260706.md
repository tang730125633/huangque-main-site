# 密钥分服务隔离与轮换流程

> 对应 `RESIL` 工单中“密钥分服务隔离 + 可轮换”子项。本文只写流程和模板，不包含任何真实密钥；所有真实文件只存在服务器本地。

## 目标

- 把单一 `/home/ubuntu/content-api/content.env` 中的多渠道密钥拆成按服务/供应商分组的 `EnvironmentFile`。
- 每个 systemd 服务只读取自己需要的文件，降低单服务泄露后的爆炸半径。
- 建立可回滚、可验证的轮换流程，避免一次性改动导致线上生成链路中断。

## 推荐文件

真实文件统一放在 `/etc/huangque/`，权限建议：

```bash
sudo install -d -m 700 -o root -g root /etc/huangque
sudo install -m 600 -o root -g root /dev/null /etc/huangque/content-core.env
```

模板见 [deploy/huangque-secrets.env.example](../deploy/huangque-secrets.env.example)。

| 文件 | 主要变量 | 读取服务 |
|---|---|---|
| `/etc/huangque/auth.env` | `HQ_INTERNAL_TOKEN`、认证限流配置 | `huangque-auth`、需要内部 token 的服务 |
| `/etc/huangque/content-core.env` | `CONTENT_API_PORT`、`AUTH_BASE`、`CONTENT_OUT`、代理 | `huangque-content` |
| `/etc/huangque/providers-openai.env` | `OPENAI_*`、`XAI_*`、`OPENROUTER_*`、转写/文案模型 | `huangque-content` |
| `/etc/huangque/providers-cosyvoice.env` | `DASHSCOPE_API_KEY`、CosyVoice 模型/前缀 | `huangque-content` |
| `/etc/huangque/providers-heygen.env` | `HEYGEN_API_KEY`、HeyGen 超时/轮询 | `huangque-content` |
| `/etc/huangque/providers-cos.env` | `COS_*`、`COS_COLLECT` | `huangque-content`、`huangque-imggen-api`、必要时 `huangque-leadgen-api` |
| `/etc/huangque/imggen.env` | `GEMINI_API_KEY`、`ZELONG*`、反推配置 | `huangque-imggen-api` |
| `/etc/huangque/leadgen.env` | `TIKHUB_KEY`、视频号解密地址、获客 API 配置 | `huangque-leadgen-api` |
| `/etc/leadgen-secrets.env` | 获客 worker 口令/令牌 | `leadgen-A`、`leadgen-B` |

## 灰度切换步骤

1. **盘点现状**

   ```bash
   sudo systemctl cat huangque-content huangque-imggen-api huangque-leadgen-api huangque-auth
   sudo ls -l /home/ubuntu/content-api/content.env /home/ubuntu/auth-service/auth.env /etc/leadgen-secrets.env
   ```

2. **创建拆分文件**

   从 `deploy/huangque-secrets.env.example` 拷贝对应段落到服务器真实文件。不要把真实文件下载或提交到 git。

3. **先追加可选 drop-in，不删除旧 `content.env`**

   例：`/etc/systemd/system/huangque-content.service.d/secrets-split.conf`

   ```ini
   [Service]
   EnvironmentFile=-/etc/huangque/auth.env
   EnvironmentFile=-/etc/huangque/content-core.env
   EnvironmentFile=-/etc/huangque/providers-openai.env
   EnvironmentFile=-/etc/huangque/providers-cosyvoice.env
   EnvironmentFile=-/etc/huangque/providers-heygen.env
   EnvironmentFile=-/etc/huangque/providers-cos.env
   ```

   `-` 前缀表示文件缺失时不阻塞启动，适合灰度。systemd 后加载的同名变量会覆盖前面文件中的值。

4. **单服务验证**

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart huangque-content
   curl -fsS https://huangquechuanmei.com/api/gen/health
   sudo journalctl -u huangque-content -n 80 --no-pager
   ```

5. **逐服务迁移**

   先迁 `huangque-content`，再迁 `huangque-imggen-api`、`huangque-leadgen-api`、`huangque-admin`。每迁一个服务只重启一个服务，验证通过后再继续。

6. **收敛旧文件**

   所有服务都稳定读取拆分文件后，再把旧 `content.env` 降为最小兼容文件，或只保留非密钥公共配置。不要立刻删除，先观察 24 小时。

## 轮换流程

1. 在供应商后台生成新 key，旧 key 暂不禁用。
2. 修改对应 `/etc/huangque/*.env`，保留变量名不变。
3. `sudo systemctl restart <service>`，只重启读取该 key 的服务。
4. 运行功能级验证：

   | key | 验证 |
   |---|---|
   | `OPENAI_API_KEY` | 文案/转写提交，任务完成 |
   | `XAI_API_KEY` / `OPENROUTER_API_KEY` | 果肉视频主渠道正常；主渠道确认无额度时可切到备用渠道 |
   | `DASHSCOPE_API_KEY` | CosyVoice 音色列表鉴权、试听及短文本配音 |
   | `HEYGEN_API_KEY` | 视频任务能拿到明确接口状态 |
   | `COS_SECRET_*` | 新产物 URL 为 COS 地址且可访问 |
   | `GEMINI_API_KEY` | 作图/提示词反推可完成 |
   | `TIKHUB_KEY` | 采集搜索或详情解析可返回 |

5. 验证通过后，在供应商后台禁用旧 key。
6. 记录轮换时间、服务、操作人、验证结果；不记录 key 真值。

## 回滚

- 如果新 key 失败，恢复上一个服务器本地 env 文件备份，重启对应服务。
- 如果拆分文件加载异常，删除该服务 drop-in 或注释新增 `EnvironmentFile`，保留旧 `content.env` 即可恢复。
- 回滚后必须检查 `journalctl` 和 `/api/gen/health`。

## 不能在本工单擅动的事项

- 不关闭任何 0.0.0.0 端口；端口收敛需 kongli 确认用途和来源地址。
- 不修改 `image.py`/作图号池代码；泽龙2 多账号轮询需要备用账号后再做。
- 不把真实 `.env`、`.db`、cookie、供应商 key、个人账号信息写入 git。
