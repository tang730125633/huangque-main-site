## 0. 三条铁律（先记这个）

1. **🚫 绝不直接在服务器上改代码。** 所有改动先进 git（本地改 → PR → 合并），再从 git 部署到服务器。GitHub `main` 是唯一"正本"，服务器只是"跑正本的地方"。
2. **⚠️ 动手前先 `git pull`。** 没 pull 就改 = 用旧版盖别人的新活。
3. **✅ 三处永远一致：GitHub `main` = 服务器代码 = 线上。** 有个**每日漂移哨兵**（08:30）自动比对，谁绕过流程直改服务器，当天飞书告警。

> 教训：历史上服务器堆过几十个 `content_api.py.bak`、git 与线上分叉多次。现在靠"只走 git + 哨兵监控"根治。

## 1. 仓库结构

| 目录 | 是什么 |
|---|---|
| `site/` | **前端**（纯静态 HTML，无构建）。主体在 `site/workbench/`（工作台各页面）|
| `server/` | **后端**（每个是单文件 Python + systemd 服务）|
| `scripts/` | 运维/工具脚本（爬取、导出、CI 校验、漂移哨兵等）|
| `worker/` | 抖音获客 worker（跑在服务器/Mac 上领任务爬取）|
| `deploy/` | 生产配置（systemd 单元、nginx、还原手册）|
| `docs/` | 方案、手册、开发文档 |
| `ship` | **一键上线脚本**（见 §4）|

## 3. 开发工作流（每次改动都照这个走）

```
1. git fetch origin --prune && git checkout main && git pull   # 先同步
2. git checkout -b <你的分支>                                   # 开分支（main 受保护，不能直推）
3. 改代码（前端改 site/**，后端改 server/**）
4. 本地自测：python -m py_compile server/xxx.py（后端）；页面本地打开看无报错（前端）
5. git commit + push，开 PR 到 main
6. 🚫 **开完 PR 就停——绝不自己合并**（合并/部署/上线由审核方统一把关；自己合会绕过审核、且不部署上线、造成 git 与线上分叉）。等审核方过 CI + 审核 + 合并（squash）
7. 从 main 部署：./ship "说明" <改的文件...>   （见 §4，由审核方执行）
8. 验证：health 200 + 打开对应页面；确认漂移哨兵无告警
```

- **提交署名**用真实开发者账号（如 `kongli <kong74007@gmail.com>`），别署成仓库主 tang。
- **一个功能 = 一个 PR**，别把多个功能塞一个 PR（审查/回滚都乱）。
- 改同一文件的任务**串行做**；改不同文件的才**并行**（否则合并撞车）。

## 4. 部署：`ship` 脚本

仓库根目录 `./ship "提交说明" 文件1 [文件2 ...]` 会自动：
**pull → commit → push → rsync 到服务器对应路径 → 重启相关服务 → 健康检查 → 刷新漂移基线**。

```bash
./ship "改采集页文案" site/workbench/collect.html          # 纯前端，不重启
./ship "修获客超时" server/leadgen_api.py                  # 后端，自动重启对应服务
./ship "联调" server/content_api.py site/workbench/video.html  # 多个一起
```

- ship 认识 §2 映射表里的路径；不认识的会跳过并提示。
- 部署后 ship 会调 `drift_sentinel.py --bless` 刷新基线——**合法部署不会触发告警，只有绕过 ship 的热改才会**。

> **手动部署到 webroot 必须用 sudo**（`site/**` 属主是 www-data）：`scp 到 /tmp → sudo cp 到 /var/www/...`。ship 已用 `sudo rsync` 处理；只有你手动 scp 时才需注意。后端 `/home/ubuntu/**` 是 ubuntu 属主，普通 scp 即可。

## 5. 各系统现状（要动之前先了解）

**前端**（`site/workbench/`）：所有页面共用 `cloud-shell.js`（注入侧栏+顶栏外壳）。页面用 `data-active="<key>"` 标当前导航。缓存刷新靠 `cloud-shell.js?v=<hash>`（见 §7 缓存戳）。

**认证**（huangque-auth, 8095）：`/api/auth/` register/login/logout/me/change_password。前端带 `Authorization: Bearer <token>`。后端 `verify(token)` 校验。

**内容生成**（huangque-content, 8096，主力约 2000 行）：`/api/gen/` 下 image/copy/collect/leads/audio/video 等能力；异步任务模型（提交→job_id→轮询 `/api/gen/job/<id>`）；点数预扣、失败退点。
- 主要接口：`/api/gen/{health,history,job/,file/,collect/search}`、audio（voices/assets/slots/clone-vip…）、video（assets/avatars/avatar-name/avatar-delete）。
- **视频**走 HeyGen：口播（图+音频→数字人）、动作模仿（照片→建数字人→参考视频驱动）。有 `phase` 阶段跟踪（前端 F3 进度条读它）。
- **数字人形象库**：`avatars` 表持久化，`avatar_id` 复用跳过建 avatar。
- **字幕**（F4）：口播视频可选自动字幕，`faster-whisper` 出时间轴 + `ffmpeg`(libass, Noto Sans SC) 烧录。用已缓存的 `small` 模型（配置见 `deploy/systemd/huangque-content.service.d/whisper.conf`）。

**作图**（huangque-imggen-api, 8101）、**获客采集**（huangque-leadgen-api, 8100）、**下载代理**（huangque-dl, 8097）、**抖音获客蓝绿槽**（leadgen-A/B, 8091/8092）。

## 6. 护栏（碰到会拦你，别绕）

- **main 分支保护**：必须 PR + CI 通过才能合。
- **CI**（`.github/workflows/ci.yml`）：`ci_validate.py`（查敏感文件/坏链接）+ `py_compile`（全后端语法编译）。语法错会红。
- **漂移哨兵**（`scripts/drift_sentinel.py`，cron 每天 08:30）：比对线上与 git，绕过 ship 的热改会飞书告警。手动排查：`python3 ~/hq-drift/drift_sentinel.py --print`。
- **DESIGN.md**：任何 UI/视觉改动**先读**，配色/字体/间距/密度以它为准。
- **密钥永不进 git**：走服务器 `EnvironmentFile`（如 `/etc/leadgen-secrets.env`）；代码里只 `os.environ.get(...)`、缺省空串。`data/`（含 PII）、`browser_data/`（cookie）永不进 git。

## 7. 踩坑清单（前人流的血）

- **`.html` 会 301 到无扩展名 URL**：验证页面用干净 URL `/workbench/video`，不是 `video.html`（后者拿到的是 301 空响应）。
- **webroot 手动部署要 sudo**（见 §4），否则 scp 静默失败、看着成功其实没写进去。
- **缓存戳漏页**：改了 `cloud-shell.js` 要更新所有页面的 `?v=`。已用 `scripts/stamp_assets.py`（按内容 hash 自动生成）+ CI 强制校验根治，别再手动逐页 sed。
- **PR 落后 main 合不了**：分支保护要求 up-to-date，用 GitHub "Update branch"（或 API `update-branch`）更新后再合。
- **whisper/HF 联网**：服务器连不上 huggingface，字幕模型用**已缓存的 small + `HF_HUB_OFFLINE=1`**，别指望线上现下模型。
- **中文文件名**：git 默认转义显示，用 `git -c core.quotepath=false ls-files` 看正常中文名。

## 8. 常见任务怎么做（配方）

**加/改一个工作台页面**：改 `site/workbench/xxx.html`（复用 `cloud-shell.js?v=<hash>` 外壳、`data-active`）；先读 DESIGN.md；`./ship "..." site/workbench/xxx.html`。

**加一个后端接口**（以 content 为例）：在 `server/content_api.py` 的 `class H` 里 `do_GET/do_POST` 加 `if p == "/api/gen/xxx":`，`verify(token)` 拿 username；需建表用 `init_*_db` 的 `CREATE TABLE IF NOT EXISTS` + `_ensure_column` 迁移；`./ship "..." server/content_api.py`（自动重启 huangque-content）。

**改样式**：先读 `DESIGN.md`；字体已自托管（别再引 Google Fonts）。
