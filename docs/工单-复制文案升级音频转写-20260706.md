## 现状
采集页 `collect.html` 已有**转写能力**：`#transcriptExtractBtn`「提取文案」（约6点、20-40秒）→ ASR 转写 → 结果显示在 `#transcriptBlock`/`#transcriptText`「口播文案」区。
但底部「复制文案」`#actCopy`（约 187 行）**只复制 `currentResult.copy.title/desc/tags`**——对视频口播不是用户真正要的口播稿。

## 目标（Issue #169）
让点「复制文案」智能化：
1. **已有转写** → 直接复制口播文案（transcript）。
2. **无转写但视频可提取音频** → 自动触发转写（复用 `#transcriptExtractBtn` 那套提交/轮询逻辑），按钮进 loading「提取并复制中…」。
3. 完成后：口播文案区展示转写结果 + **自动复制到剪贴板** + toast「文案已提取并复制」。
4. **失败兜底**：无音频/无法下载/接口失败/点数不足 → 明确错误提示，按钮恢复。

## 改动（`site/workbench/collect.html`）
- 改 `#actCopy.onclick`：
  - 若 `#transcriptText` 已有转写文本 → 复制它 + toast。
  - 否则复用现有「提取文案」的提交+轮询流程（`currentUrl` 已在提交时保存，供按需转写）；完成回填口播文案区后自动复制。
  - 纯图文（无视频/无音频）时可回退旧行为（复制 title/desc/tags）或明确提示"该内容无口播可提取"。
- loading/禁用态、错误提示、点数不足提示都要有。
- 保留 `#transcriptExtractBtn` 原按钮（两条入口都能提取，不冲突）。

## 可选（后端 ASR 模型升级，非必须，可另单）
Issue 提到把 ASR 从 `whisper-1`/本地 whisper 升级/可配置为 OpenAI `gpt-4o-mini-transcribe`（实测转中文口播效果好）。**本单不强制**——若只做前端接线即可满足"复制文案=转写并复制"；模型升级可作为后端单独增强（走 env 可配、走代理、注意成本），另行评估。

## 验收标准
1. 采集一个视频 → 点「复制文案」→ 有转写则直接复制；无则自动提取、loading、完成后展示+自动复制+toast。
2. 各错误场景（无音频/下载失败/接口失败/点数不足）有明确提示、按钮可恢复。
3. 纯图文内容行为合理（回退或提示），不报错。
4. 不影响现有「提取文案」按钮、采集主流程。
