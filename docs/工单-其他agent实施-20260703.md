## §0 公共上下文（每个 agent 必读）

### 仓库与工作流
- GitHub 私有仓库：`https://github.com/tang730125633/huangque-main-site`
- **main 受保护，所有改动必须走分支 + PR**，PR 需过 CI（`代码与安全门禁` = `scripts/ci_validate.py`）才能合并。
- 🚫🚫 **绝不自己合并 PR！** 开完 PR 就停下等审——合并、部署、上线一律由**审核 AI**统一把关。自己合会绕过审核、且不会被部署到线上，只会造成 git 与线上分叉。
- 提交署名用真实开发者账号（`kongli <kong74007@gmail.com>`），**不要**署成 tang。
- UI/视觉改动**先读仓库 `DESIGN.md`**，不得擅自偏离配色/字体/间距/密度。

### 部署方式（唯一入口：`ship`，禁止服务器直改）
仓库根有 `ship` 脚本：`./ship "提交说明" 文件1 [文件2 ...]` → 自动 commit→push→rsync 到服务器→重启对应服务→健康检查→刷新漂移基线。
> ⚠️ **绝对禁止**直接 SSH 上服务器改 `/var/www/...` 或 `/home/ubuntu/...` 的文件——历史上双轨修改已造成多次 git/线上分叉。有漂移哨兵每天 08:30 巡检，绕过 ship 的热改会飞书告警。

### git 路径 ↔ 服务器路径映射（ship 已内置）
| git 路径 | 服务器路径 | 服务 |
|---|---|---|
| `site/**` | `/var/www/huangquechuanmei/**` | 静态（无需重启）|
| `server/content_api.py` | `/home/ubuntu/content-api/content_api.py` | huangque-content :8096 |
| `server/imggen_api.py` | `/home/ubuntu/content-api/imggen_api.py` | huangque-imggen-api :8101 |
| `server/leadgen_api.py` | `/home/ubuntu/content-api/leadgen_api.py` | huangque-leadgen-api :8100 |
| `server/auth_server.py` | `/home/ubuntu/auth-service/auth_server.py` | huangque-auth :8095 |
| `server/dl_service.py` | `/home/ubuntu/dl-service/dl_service.py` | huangque-dl :8097 |

### 后端约定
- 纯 Python 标准库 + `ThreadingHTTPServer`，无框架（content/auth/dl）；app.py(leadgen) 用 FastAPI。
- 密钥**永不进 git**：走服务器 `EnvironmentFile`（`/etc/leadgen-secrets.env` 等），代码里只 `os.environ.get(...)` 且默认空串。
- 登录态：前端带 `Authorization: Bearer <token>`；后端 `verify(token)` 调 auth 的 `/api/auth/me`。

### 验证与验收（每张工单收尾都要做）
1. 本地 `python -m py_compile <改动的.py>` 通过。
2. 走 ship 部署后，`curl -s -o /dev/null -w "%{http_code}" https://huangquechuanmei.com/api/gen/health` 应为 200。
3. 涉及页面的，实际打开对应页面确认无报错（浏览器控制台无红字）。
4. 部署后确认漂移哨兵无新增告警（ship 会自动 `--bless`）。

## T1 · 回收动作模仿后端到 git（P0，最先做）
**目标**：`content_api.py` 的动作模仿后端（`mode='motion'` + `generate_heygen_motion_video()` + `reference_video_data`）目前只在线上服务器、git main 没有。把线上版完整回收进 git，使 `main == 线上`，防止后续 git 部署把它覆盖删除。
**背景/依据**：前端 `site/workbench/video.html` 已有动作模仿标签页（提交 `mode:'motion'`），但 git 的 `server/content_api.py` 会拒绝 `mode='motion'`。线上 content_api 领先。
**步骤**：
1. 先确认线上 `content_api.py` 此刻稳定（无正在进行的 Codex 会话在写；对比两次 md5 间隔 30s 不变）。
2. 抓线上 `/home/ubuntu/content-api/content_api.py`，与 git `server/content_api.py` 逐行对比，确认差异**仅为**动作模仿相关新增（无夹带意外改动/密钥）。
3. 覆盖 git 的 `server/content_api.py`，`py_compile` 通过。
4. 开分支 PR，说明"回收线上动作模仿后端"。
**验收**：合并后 `git show main:server/content_api.py` 含 `mode == "motion"` 分支与 `def generate_heygen_motion_video`；线上与 git md5（剔 CRLF）一致；哨兵 `--bless` 后无 content_api 漂移。
**坑**：抓取前务必确认线上不是半成品；此工单**只回收、不改逻辑**。

## T2 · 统一缓存戳 v=15（P1，最简单）
**目标**：`site/workbench/video.html` 引用的 `cloud-shell.js?v=14` 落后于其他 13 个页面的 `v=15`，视频页可能加载旧共享外壳。
**步骤**：把 `video.html` 里 `cloud-shell.js?v=14` 改为 `?v=15`；全站再 grep 一遍确认所有页面 shell 版本一致。
**验收**：`grep -o "cloud-shell.js?v=[0-9]*" site/workbench/*.html` 全部为 v=15；视频页打开正常、导航/登录态正确。
**部署**：`./ship "统一视频页缓存戳 v=15" site/workbench/video.html`

## T3 · 昂贵生成接口加限流（P0，依赖 T1）
**目标**：`server/content_api.py` 的生成接口（image/video/audio-clone）目前只有点数门槛、无频控，泄露 token 或恶意用户可狂刷烧钱烧配额。
**要求**：
- 加**每用户 + 每 IP 滑动窗口频控**（标准库实现，内存字典 + 时间戳即可）；对 `video`(HeyGen) / 语音克隆等高成本接口设更严阈值（如每分钟 2 次、并发 1），普通接口宽松些。
- 超限返回明确错误（如 429 语义 + 中文提示"操作过于频繁，请稍候"），前端 toast 能展示。
- 不影响正常单用户使用节奏。
**验收**：连续快速调用高成本接口会被拦并返回频率提示；正常间隔调用不受影响；`py_compile` 通过、health 200。
**注意**：基于 T1 后的 content_api（含动作模仿）改，别退回旧版。

## T4 · 自托管 Google Fonts（P1）
**目标**：14 个页面引用 `fonts.googleapis.com`/`fonts.gstatic.com`（Noto Sans SC + JetBrains Mono），大陆访问慢/超时导致首屏字体闪烁、白屏。
**要求**：
- 下载所需字重，**中文按常用字子集化**控制体积，放 `site/assets/fonts/`，用 `@font-face` 引用；移除所有页面对 Google Fonts 的 `<link>`。
- 视觉与现状一致（先读 `DESIGN.md` 确认字体族/字重）。
**验收**：断网/墙内环境首屏字体正常、无外部字体请求；各页面视觉不变。

## T5 · 补「设置」页（P1）
**目标**：`site/workbench/settings.html` 目前是"敬请期待"stub，但它是侧栏一级入口，用户在此找不到改密码/团队/退出。
**要求**（先读 `DESIGN.md`，风格对齐其他工作台页）：
- 账号资料、**修改密码**（对接 auth 服务）、团队成员（可先只读展示）、计费/充值入口（链到 recharge）、退出登录。
- 复用 `cloud-shell.js?v=15` 外壳，`data-active="settings"`。
- 后端如需"改密码"接口，在 `server/auth_server.py` 增加并走 ship 部署 auth。
**验收**：设置页可用，改密码端到端生效；无控制台报错；health 200。

## T6 · 点数收敛为 auth 接口（P1）
**目标**：`content_api.py` 直接读写 `/home/ubuntu/auth-service/users.db` 扣/退点，跨进程并发写 SQLite 有竞态。
**要求**：在 `auth_server.py` 提供扣点/退点/查点的 HTTP 接口（带鉴权），`content_api.py` 改为调接口，单写者。扣点+受理保持原子语义，失败退点。
**验收**：并发提交多任务不再出现点数错乱；失败仍正确退点；两服务均 health 正常。

## T7 · CI 增加 py_compile 全量编译（P2）
**目标**：CI 仅静态检查，未编译 Python，像"重复定义 gen_image / 语法错"这类问题漏网。
**要求**：在 `.github/workflows/ci.yml` 加一步 `python -m py_compile` 全量编译 `server/**.py`、`scripts/**.py`、`worker/**.py`。
**验收**：CI 新增编译步骤并通过；故意引入语法错时 CI 会失败。

## T8 · content_api 按域拆分（P2，依赖 T1、T3）
**目标**：`content_api.py`（~2000 行）单文件难维护。按域拆成 image / audio / video / leads / points 等模块，主文件只保留路由与 HTTP 层。
**要求**：**纯重构、零行为变化**；每拆一个域就 ship 一次并验证，别一次性大爆改。保持标准库、无新依赖。
**验收**：拆分后各接口行为与拆前完全一致（逐接口回归）；health 200；每步都有可回滚提交。
