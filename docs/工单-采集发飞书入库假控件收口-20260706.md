# 工单 · 采集「发飞书 / 入库」假控件收口（Issue #229）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：E-collect（`site/workbench/collect.html`）** —— 抢 `lock/E-collect`。**纯前端**。
> 相关：#190 FAKE-UI（假控件清理三态收口，同源）、#197（飞书回传闭环，发飞书真实实现的前置依赖）。

## 现状（issue #229 已实测定位）
采集结果操作区其实是**三个独立按钮**，用户把它们当成一个「发飞书入库再爬取」功能，实测各自状态：
- **发飞书** `#actFeishu`（`collect.html:207,949`）：**占位桩**——onclick 只弹「飞书推送即将上线（bot 接入阶段）」，功能未实现。
- **入库** `#actStore`（`collect.html:211,952`）：**空动作**——采集时已自动入库，按钮只弹「采集即自动入库·去资产查看」，本身不执行任何入库。
- **再爬取** `#actRetry`（`collect.html:215,956`）：**实际可用**——重新用当前 url 提交采集（`submitCollect`）。

所以 #229 报的「功能不可用」实为：发飞书是未上线占位、入库是提示型空按钮——看起来可点却无真实动作，属**误导性假控件**，非真报错。

## 目标：三态收口（对齐 #190 FAKE-UI）
让每个控件"状态诚实"，别让用户误以为有功能：
1. **发飞书**：在飞书 bot（#197）落地前，改为**明确的「即将上线」禁用态**——置灰/降透明度 + `cursor:not-allowed` + 角标或提示「即将上线」，点了不再伪装成"操作成功"式的金色提示。（真实推送实现依赖 #197，不在本单。）
2. **入库**：既然采集即自动入库，把它从"看着像动作的按钮"改为**状态展示**——直接常显「✅ 已自动入库 · 去资产查看」链接，或移除独立按钮改为结果区一行状态文案，避免"点了才告诉你其实早入库了"。
3. **再爬取**：保留（可用），确认对 贴链接/关键词/视频下载 三种模式都取对 url（`:957-962` 已按 mode 取 url，回归验证即可）。

## 改动（`site/workbench/collect.html`）
- `#actFeishu`：禁用态样式 + 文案「即将上线」，去掉误导性成功提示。
- `#actStore`：改状态展示（常显已入库）或并入结果区状态行。
- 三态收口后视觉仍需符合 `DESIGN.md`（金调、密度、禁用态对比）。

## 验收标准
1. 发飞书按钮呈明确「即将上线」禁用态，不再弹金色"成功"式提示。
2. 入库状态诚实呈现（已自动入库 + 去资产链接），无"点击才生效"的错觉。
3. 再爬取在三种采集模式下都能正确用当前 url 重采。
4. 不影响采集主流程、转作图、复制文案、视频下载(#254) 等既有功能。
