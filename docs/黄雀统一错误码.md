# 黄雀统一错误码

黄雀接口继续使用标准 HTTP 状态码，同时返回稳定的 `HQ-*` 业务错误码。后台“请求日志”会同时展示两者；排障时以 `request_id` 关联 Nginx 与服务日志。

## 返回格式

```json
{
  "detail": "生成渠道暂时不可用，请稍后再试",
  "hq_code": "HQ-UPSTREAM-001",
  "request_id": "hq_...",
  "retryable": true,
  "error": {
    "code": "HQ-UPSTREAM-001",
    "type": "upstream_error",
    "message": "生成渠道暂时不可用，请稍后再试",
    "retryable": true,
    "request_id": "hq_..."
  }
}
```

响应头同步返回 `X-HQ-Error-Code` 与 `X-HQ-Request-ID`。旧客户端依赖的顶层 `detail` 和 `code` 暂时保留。

## 当前目录

| 错误码 | HTTP | 含义 | 可重试 |
| --- | ---: | --- | --- |
| `HQ-REQUEST-001` | 400 | 请求参数不正确 | 否 |
| `HQ-AUTH-001` | 401 | 登录或授权已过期 | 否 |
| `HQ-BILLING-001` | 402 | 余额或额度不足 | 否 |
| `HQ-AUTH-002` | 403 | 没有操作权限 | 否 |
| `HQ-RESOURCE-001` | 404 | 内容不存在或已失效 | 否 |
| `HQ-CONFLICT-001` | 409 | 内容或幂等状态冲突 | 否 |
| `HQ-ASSET-001` | 413 | 文件或数据过大 | 否 |
| `HQ-RATE-001` | 429 | 请求频率过高 | 是 |
| `HQ-SYSTEM-001` | 500 | 黄雀内部服务异常 | 是 |
| `HQ-UPSTREAM-001` | 502 | 上游渠道返回异常 | 是 |
| `HQ-UPSTREAM-002` | 503 | 上游渠道繁忙或维护 | 是 |
| `HQ-UPSTREAM-003` | 504 | 上游渠道超时 | 是 |

## 维护规则

1. 错误码只新增、不改义、不复用；废弃码保留映射。
2. 上游响应正文、密钥、Token 和内部堆栈不得进入公开响应；只写入脱敏审计摘要。
3. 新增错误码时同步修改 `server/content_domains/error_contract.py` 和本表，并补一条最小回归测试。
4. 后台按 HTTP 状态、黄雀错误码或请求号筛选；运营每月复查高频 `HQ-SYSTEM-*`、`HQ-UPSTREAM-*` 与未知错误。
