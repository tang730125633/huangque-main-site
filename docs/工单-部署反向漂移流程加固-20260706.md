## 背景（已做/未做）
Issue #192 = 仓库 origin/main、服务器 checkout、线上 `/var/www` 三方不一致，根源是有人绕过 ship 直接热改线上。
- ✅ **已做**：漂移源清理（全站体检 40 文件线上==git）；哨兵 cron 从每天 1 次提频到每 30 分钟。
- ⏳ **本单待做**：防止以后再产生漂移的三个流程项。

## 待做项

### 1. 哨兵 bless / detect 解耦（P1）
现状：`ship` 部署后调 `drift_sentinel.py --bless` 刷新基线；但 bless 会把"当前线上"整体设为新基线——若此刻线上已有绕过 ship 的热改，热改也被 bless 进基线、永不告警。
- 改法：区分「**部署 bless**」（只把本次 ship 实际推送的文件纳入基线）与「**巡检 detect**」（比对线上 vs **git origin/main**，而非比对上次基线）。
- 让 detect 直接对 `git show origin/main:<path>` 比对（就是本次体检脚本的做法），这样任何"线上≠git"都能报警，与 bless 无关。

### 2. ship 整树部署 + 部署后校验（P1）
现状：`ship` 按文件清单 rsync，未校验部署后线上与 git 一致。
- 加：部署完对每个推送的文件做一次线上 vs git 内容校验（不一致即告警）。
- 可选：`ship` 结束时跑一次 detect，确认三方一致。

### 3. 服务器 checkout 目录防就地编辑（P2）
现状：`/home/ubuntu/huangque-main-site` 被当编辑场所，曾落后 origin/main 153 commit + 有未提交热改。
- 改法：该 checkout 设**只读**，或加 `pre-commit` 钩子拒绝提交；部署一律走 `ship`（scp→sudo cp），**从不在服务器就地改**。
- 定期 `git fetch && git reset --hard origin/main && git clean -fd` 保持干净。

## 验收标准
1. 绕过 ship 直接热改线上任一文件 → 哨兵能在 30 分钟内告警（即使之前 bless 过）。
2. `ship` 部署后自动校验线上==git，不一致即报错/告警。
3. 服务器 checkout 无法就地编辑（只读或钩子拦截）。
4. 三方（origin/main、服务器 checkout、`/var/www`）一致可复现。
