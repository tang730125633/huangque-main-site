## 一句话结论

这个网站不是单一的 AI 生成器，而是一套「灵感案例 → 创作工具 → 资产库 → 积分账本 → 再创作」的内容生产工作台。它的强项不在单个模型，而在把图片、视频、数字人、文案、音频和资产管理放进同一个网页载体里。

这正是我们未来要把飞书 bot 网页化时需要对标的形态：bot 不应该只是群里的回复者，而应该变成网页上的任务入口、素材入口、结果入口和成本入口。

## 灵感模块

灵感页是首页，也是获客和转化入口。它不是空白创作，而是先给用户看「别人做出来的案例」。

分类包括：

- 全部
- AI 数字人
- 自选场景
- 电商
- 大健康
- 工厂
- 励志演讲
- 探店
- 宠物
- 美发
- Image 2
- 短剧带货
- 变装
- 写实
- 动漫
- 创意
- 跨境
- 设计
- 家具设计
- LOGO
- 服饰
- 美食
- 搞笑
- 修图改图

案例卡片通常包含：

- 使用模型，例如「威尔视频」「香蕉生图」「马克视频」「方舟视频」「索拉视频」
- 标题，例如「居家口播」「金毛直播」「裸眼 3D LED 广告牌」
- 「做同款」按钮
- 热度数字

对我们的启发：客户不一定知道要输入什么。我们应该给客户「美业获客脚本案例」「数字人口播案例」「招商图案例」「门店引流案例」，让客户点一个模板再改。

## 作图模块

实际路由是 `/banana`，不是 `/image`。

> 详细拆解见：`docs/竞品拆解-Timarsky星空-作图页banana-20260625.md`

子入口：

- 图片创作
- 电商主图/详情图
- 照片形象
- 局部修图
- 智能扩图
- 海报设计
- LOGO 创作
- 历史记录
- 作图教程

可选模型：

- 大师版 - NanoPro
- 全能版 - Nano2
- Image2 免费

基础流程：

1. 从「素材库」或「生图作品」选择参考图。
2. 输入图片描述，文本框上限 3000 字。
3. 选择比例，例如 9:16。
4. 选择清晰度，例如普通 1K。
5. 选择生成张数。
6. 点击立即生成。
7. 生成后可以继续改图、局部修图、生成视频、下载、上传至素材库。

观察到的积分口径：

| 功能 | 积分 |
|---|---:|
| 图片创作 | 4 点/张 |
| 电商主图/详情图 | 150 点/5 张 |
| 图片生成失败/退回 | +4 点返还 |

对我们的启发：图片 bot 未来网页化时，不要只做一个聊天框。应该是「参考图上传 + 文案提示词 + 比例 + 张数 + 结果卡片 + 继续生成视频」。

### 燃动全驱

定位：脚本驱动的分段视频/数字人成片工具。

流程：

1. 从素材库或生图作品选择最多 9 张场景/人像。
2. 填写口播文案，文本框上限 3000 字。
3. 可用「文案提取」。
4. 选择比例，例如 9:16。
5. 可开启智能场景拆分。
6. 生成后按场景展示，每个场景可播放、重新修改。
7. 结果可做智能包装、口播创作、擦除字幕、一键高清、下载、上传至素材库。

积分口径：从积分流水和时长反推为 5 点/秒。

证据：

- 94 秒扣 470 点。
- 39 秒扣 195 点。
- 10 秒扣 50 点。

### 赤焰声动

定位：图片/形象 + 文本/音频驱动的口播视频。

流程：

1. 上传清晰真人正面画面，或五官比例接近真人的卡通人物。
2. 文本驱动或音频驱动。
3. 可做文案提取、语气符号、文案润色。
4. 选择声音、情绪、设置。
5. 可填写动作提示词。

积分口径：60 点/分钟，按整分钟结算。

### 妙音口型

定位：数字人口型同步/分身视频。

流程：

1. 选择「我的分身」或「公共分身」。
2. 创建视频或上传视频。
3. 文本驱动或音频驱动。
4. 选择声音、情绪、设置。
5. 生成口型同步视频。

积分口径：1 点/秒。

### 其他视频工具

页面列出了更多模型/工具：

- 索拉创意
- 马克超长
- 威尔高清
- 超级混剪
- 迁移/替换
- 火山方舟
- 快乐小马

这些入口主要覆盖文生视频、图生视频、长视频、高清、混剪、人物/动作迁移和复刻等方向。当前可确认的是：该站用「多个模型名」承接不同视频能力，而不是让用户理解底层 API。

对我们的启发：我们的数字人 bot 未来应该拆成：

- 脚本成片

### 品牌立项

有三类项目：

- 创建人设立项：IP 智能体，秒懂需求，即可上线。

- 创建门店立项：营销助手，助力精准获客。

这本质上是把「客户上下文」产品化。用户先建人设/产品/门店，后续生成文案和视频就有稳定上下文。

### 定制声音

音频训练模型：

| 模型 | 能力 | 积分 |
|---|---|---:|
| 新手体验音频 | 支持 13 国语言 | 免费训练 |
| 超拟真国际版 | 支持 40 国语言，可修改 5 次 | 500 点数 |

上传要求：

- 建议上传 3-5 分钟音频。
- 支持 mp3、m4a、wav。
- 需要填写声音名称。
- 需要勾选使用规范。

### 音色设计

输入：

- 音色提示词，上限 500 字。
- 试听文本，上限 100 字。

内置推荐：

- 开朗博主
- 新闻女主播
- 抱怨老者
- 英勇侠客
- 娇媚少女
- 严厉女教师
- 摇篮曲女生
- 悬疑故事家
- 激情解说
- 年迈智者

### 音频创作

流程：

1. 填写或粘贴台词，上限 10000 字。
2. 可随机生成、AI 帮写、文案润色、添加语气符号。
3. 选择声音、情绪、设置。
4. 可填写音频名称。
5. 生成音频。

积分口径：1 点/5 秒。

### 提取视频音频

输入：

- 视频链接，支持抖音、快手、西瓜视频、TikTok、头条、小红书、火山、新浪等。

积分口径：页面显示免费 3 条。

对我们的启发：我们的数字人链路必须有独立音频层，不应该把声音克隆、TTS、视频口型全塞进一个按钮。

## 我们应该怎么对标

不要一上来复制全部功能。第一版应只做我们业务最短闭环：

1. 客户/项目立项
   - 客户名称
   - 行业
   - 门店/产品/人设
   - 飞书群绑定

2. 资产库
   - 上传图片、音频、视频
   - 引用本地 Seedance 素材
   - 标记素材类型：人物、产品、场景、音色、成品

3. 文案与抓取
   - 粘贴抖音/小红书/视频号链接
   - 抓取文案/评论/标题/指标
   - 二创美业获客脚本
   - 进入文案库

4. 图片生成
   - 参考图 + 提示词 + 比例 + 张数
   - 海报/招商图/人物图模板
   - 结果进入资产库

5. 视频/数字人生成
   - 选择人物图
   - 选择声音/上传音频
   - 输入口播文案
   - 生成任务
   - 结果进入作品/交付区

6. 成本/任务账本
   - 每个任务消耗多少点/多少钱
   - 哪个客户最烧钱
   - 哪个能力失败率最高
   - 和飞书看板打通

## 我们的差异化优势

竞品是一个通用 AI 创作工具站，我们不应该只做通用工具。我们的优势应该是：

- 美业获客垂直场景
- 飞书群里的 AI 员工交付
- 抖音/短视频平台抓取能力
- 客户群会话可观测
- 真实业务素材库
- 能把文案、图片、数字人、客户交付串成闭环

换句话说，竞品卖「工具集合」，我们应该卖「美业获客与内容交付系统」。

## 第一版产品建议

第一版网页不要叫“大而全 AI 平台”，建议叫：

- AI 内容工厂
- 美业获客内容中台
- AI 员工工作台

第一屏不要做营销页，直接进入工作台：

- 左侧：客户项目、文案、图片、视频、资产、任务、成本
- 中间：当前能力的操作面板
- 右侧：最近任务、飞书状态、成本/失败提醒

优先级：

1. P0：资产库 + 文案/抓取 + 图片生成 + 数字人任务 + 任务历史。
2. P1：积分/成本账本 + 飞书群绑定 + 客户项目。
3. P2：灵感案例广场 + 做同款。
4. P3：画布、AI 工具大全、多模型商城。

## 风险提醒

- 不要照抄竞品的功能广度。它太宽，我们人少，应该做垂直闭环。
- 不要先做画布。画布看起来高级，但离成交交付远。
- 不要把素材、作品、交付混在一起。客户需要看结果，AI 需要看素材，运维需要看脚本，这三层要分开。
- 不要隐藏成本。每次生成前都应该显示预计消耗。
- 不要只做网页，忘了飞书。我们的强项是网页 + 飞书 bot + 服务器后台联动。

## 下一步

建议下一步做一个最小可用原型：

```text
客户项目 -> 资产上传 -> 粘贴链接抓取 -> 文案生成 -> 图片生成 -> 数字人口播任务 -> 作品交付 -> 成本/失败复盘
```

这条链路跑通，比复制 20 个 AI 工具更重要。

## 二、Codex 没覆盖的：UI / 视觉组件层（这才是「迁移」的关键）

Codex 把"功能怎么排"扒透了，但"界面长什么样、组件怎么搭、怎么换成我们的皮"没展开。下面是实测提炼的 **8 个可直接搬的 UI 模式**：

**① 三段式工作台外壳（Shell）** — 全站统一骨架
- 最左 **icon 导航轨**(~64px)：图标+小字 label，当前项高亮竖条；底部头像+点数余额常驻。
- 顶部 **页内二级 tab 栏**：该模块子能力横排（图片创作/电商图/照片形象/局部修图/扩图/海报/LOGO）+ 右侧 搜索/历史记录/教程。
- 主区 **左创作面板 + 右实时结果面板** 对半分。
- 底部 **sticky 操作条**：参数下拉 + 主 CTA。
> 这跟我们 `DESIGN.md` 的「left nav + top context + main + right inspector」几乎一模一样，可直接落地。

**② 创作面板五件套** — 每个生成页复用同一套
1. 模型 **segmented 切换**（大师/全能/免费），免费档带「免费」badge 但仍显示原价（价值锚点）。
2. **参考图上传区**：双来源「素材库 或 生图作品」+ 约束提示（≤10MB / ≥300px）+ 占位图标。
3. **Prompt textarea** + 字数计数（0/3000）+ AI 辅助按钮（分镜脚本撰写 / 文案提取）+ 清空。
4. **灵感案例** 内联展开（治"不会写 prompt"）。
5. 免责注脚。

**③ 成本前置 CTA（最该抄）** — 主按钮直接写「立即生成 ⊙ 4点/张」，成本和动作合一。正是 `DESIGN.md` 的 Cost Chip 铁律「每个生成按钮附近必须显示预计消耗」。

**④ 结果即资产卡片** — 一次生成不是终点：结果卡带元数据 tag 串（能力/版本/比例/清晰度/时间/状态）+ 一排后续动作（再生成 / 继续改图 / 局部修图 / 生成视频 / 下载 / 入库）。**我们要加一个他们没有的：推送飞书群。**

**⑤ 实时结果 Inspector** — 右半屏常驻最近一条结果（参考文案+tag+成品+创建时间），生成即出现，不跳页。

**⑥ 灵感广场 + 做同款** — 首页=案例瀑布流（模型 badge + 缩略图 + 标题 + ♥ + 做同款），按行业垂类横向筛选。我们用美业垂类（皮肤管理封面/医美科普/门店活动/新客体验卡/数字人首帧）。

**⑦ 空状态图示引导** — 编导页 4 步插画引导（去平台→复制链接→粘贴→获取）。降低首用门槛。

**⑧ 资产库三层** — 作品/素材/回收站 + 类型 tab + 模型过滤 + 批量操作 + 云存储余量（立即扩容 upsell）。

## 四、不要照搬的三点

1. **24 小时作品即焚 → 不抄**。那是他们压存储成本+逼下载的策略。我们 `DESIGN.md`/架构 doc 明确「资产库第一天就在、要能复用」，**保留资产**是我们做"美业真实素材库"的差异化。可学其「立即扩容/下载」提示，但默认不焚。
2. **功能广度（20+工具/画布/多模型商城）→ 不抄**。一人运营做不动，做美业获客+数字人垂直闭环。
3. **未成熟入口露出（海报/LOGO「开发中」）→ 不抄**。只放真能交付的，内测能力进灰度/找运营代做。

## 五、回答顶部的服务器规模问题（100 用户/月 · 20 在线/时 · 100 请求/秒）

**结论先说：这个量级，1 台服务器（就用现有 dapeng-server 或一台 4C8G）足够起步且有余量。100 请求/秒不是瓶颈，真正的成本和瓶颈是「生成任务的并发 + 模型 API 花费」。**

**为什么 100 req/s 不慌**：这 100 次/秒绝大多数是**轻请求**（页面、轮询任务状态、读列表、静态资源）。一台 nginx + FastAPI（异步）处理轻接口轻松上千 req/s；按你现在 leadgen-server 的 `app×2(8091/8092)` 双实例，100 req/s 用不到三成。

**真正决定规模的是「生成并发」**：20 个在线不会同时点生成，峰值估 5–10 个并发生成任务。图片（gpt-image ~ 几十秒）、视频（Seedance ~ 几分钟）这些是**等外部模型 API 的 I/O 等待，不吃你本机 CPU/GPU**。所以——**不需要买 GPU 服务器**，只要：① 任务队列（Redis）② worker 并发槽（8–16 个）③ 模型 API 的限额与预算。

**分阶段配置**：

| 阶段 | 量级 | 配置 |
|---|---|---|
| **起步（=你现在的题设）** | ≤100 用户/月, 20 在线, 100 req/s | **1 台 4C8G**：nginx + app×2 + worker×4-8 + SQLite/小 DB + **对象存储 COS（放图/视频）** + Redis 队列。够用有余。|
| 成长 | 数百并发 / 重视频 | 拆 **2–3 台**（同地域同 VPC 内网）：①网关+app ②worker 集群（扩生成并发）③数据(DB+Redis+COS)。|
| 规模 | 千级 | app 多副本+CLB；worker 按生成并发线性加；媒体全 COS+CDN；DB 主从。|

**能并联/串联吗？能，两种都用**（接上文我讲的扩展架构）：
- **并联（横向）**：同类机器多份，流量/任务分摊——app、worker 都这么扩，是主力。
- **串联（流水线）**：把「抓取→文案→图→数字人」做成**任务队列各阶段**，不同机器接力——天然支持。
- **物理基础**：同地域同 VPC **内网互通**（免费、低延迟、不暴露公网）；机器之间不直接对话，靠**共享层（DB/Redis/COS）+ 队列**协作。加机器 = 进 VPC→挂进池子，**改配置不改代码**。

**⚠️ 真正的大头不是服务器，是模型 API 花费。** 对标站的积分体系（图 4点/张、视频按秒计费）本质就是**把第三方 API 成本透传+加价**。所以"服务器规模"是便宜的部分，真正要管的是**生成 API 预算 + 每客户成本看板**（这也正是我们相对竞品的差异化：成本/毛利可观测）。
