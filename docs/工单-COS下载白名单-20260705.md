# 工单 · 下载代理白名单放行 COS 域名（修 COS-COLLECT 回归）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》领取流程。
> **冲突组：A（`server/content_domains/core.py`）+ `server/dl_service.py`** —— 抢 `lock/A`。纯白名单常量，最小改动。

## 问题（回归）
COS-COLLECT（PR #113）上线后，采集视频的 `play_url` 变成 **COS 直链**（`https://huangque-media-1435693839.cos.ap-guangzhou.myqcloud.com/huangque/collect/...`）。但下载代理 `/api/gen/dl` 的防 SSRF 白名单 `ALLOW` **只放了抖音系 CDN、没放 COS 域名** → 用户点「无水印下载」传 COS 链接进去 → 返回 **`不支持下载地址`**。

## 根因位置
`/api/gen/dl` 的白名单校验在**两处**（前端下载走 `dl_service.py`:8097，nginx `location = /api/gen/dl` 指向它；`content_domains/core.py` 也有一份同样的 `ALLOW`）：
- `server/dl_service.py` 的 `ALLOW`（约 17 行）
- `server/content_domains/core.py` 的 `do_GET` 里 `/api/gen/dl` 的 `ALLOW`（约 670 行）

两处都是 `host.endswith(h)` 前导点后缀匹配。

## 改动
两处 `ALLOW` 各加**我们自己的 COS 桶域名**（防 SSRF：只放本桶精确域名，别放泛 `.myqcloud.com`）：
```python
    ".cos.ap-guangzhou.myqcloud.com",   # 采集视频转存 COS 后的直链下载(COS-COLLECT #113)
```
> 说明：用 `.cos.ap-guangzhou.myqcloud.com`（我们桶所在地域）做后缀，`host.endswith` 会匹配 `huangque-media-1435693839.cos.ap-guangzhou.myqcloud.com`。比放泛 `.myqcloud.com` 更收敛。若以后配了 `COS_DOMAIN`(CDN 自定义域名)，也要把该域名一并加入。
- 两份 `ALLOW`（dl_service.py + core.py）**保持一致**。

## 边界
- 只加白名单常量，不改下载逻辑、不改 collect/COS 转存逻辑。
- 不动 `app.py`（那是 leadgen 爬虫自己的下载校验，与平台下载无关）。

## 验收标准
1. 采集一条抖音视频（play_url 现在是 COS 直链）→ 点「无水印下载」→ **能下载**，不再"不支持下载地址"。
2. 抖音 CDN 直链、小红书、视频号等原有下载仍正常（白名单只增不减）。
3. 非白名单域名仍被拒（SSRF 防护不破）。
4. `py_compile` 通过、health 200。

## 部署与验证
- `./ship "下载白名单放行COS域名" server/content_domains/core.py server/dl_service.py`（dl_service 部署到 /home/ubuntu/dl-service/，重启 huangque-dl；core.py 重启 huangque-content）
- 实测采集视频 COS 直链能走 `/api/gen/dl` 下载；非法域名仍 400。

> 本工单只做规划，未改动任何文件。
