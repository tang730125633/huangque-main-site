# 工单 · 新用户注册赠送试用点数

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》。
> **冲突组：D（`server/auth_server.py`）** —— 锁 `lock/D`。

## 背景
小程序MVP联调时Cowork反馈：新注册用户`points=0`，注册完直接卡住无法生成任何内容，是"能不能用起来"的关键阻塞点。kongli 拍板：给新用户16点试用额度（约2次标准清晰度作图，8点/次）。

## 改动
`server/auth_server.py`：
- 新增常量 `NEW_USER_TRIAL_POINTS = int(os.environ.get("HQ_AUTH_TRIAL_POINTS", "16"))`
- `/api/auth/register`（网站原生注册）与 `/api/auth/miniprogram-register`（小程序注册）两处注册逻辑的 `INSERT INTO users` 点数字段、以及返回体里 `public_user()` 的 points 参数，都从硬编码 `0` 改为 `NEW_USER_TRIAL_POINTS`。
- 两个注册入口保持一致待遇，不分渠道。
- 管理员CLI建号(`create_user()`)不受影响，默认仍是 `points=0`（管理员建号时可显式指定点数）。

## 已验证
- `tests/test_auth_points.py::test_miniprogram_register_returns_token_and_creates_user` 补充断言 `points == NEW_USER_TRIAL_POINTS`
- `python3 -m unittest discover -s tests` 48/48 通过

## 验收标准
1. 网站/小程序任一渠道新注册用户，`points` 字段为16（而非0）。
2. 老用户点数不受影响（这是INSERT时的默认值，不影响已存在账号）。
3. 管理员CLI建号行为不变。

## 部署与验证
- 改 `server/auth_server.py`(D) → ship，重启 `huangque-auth`。部署后注册一个测试账号确认返回`points:16`，关本工单。
