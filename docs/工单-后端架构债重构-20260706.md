> **冲突组：A（`server/content_domains/**`、`core.py`）** —— 抢 `lock/A`，组内串行、大重构，**分阶段**、每阶段独立可上线。

## 问题（#195）
1. **无界 worker 线程**：每个 job `threading.Thread(daemon=True).start()`，无池无队列无上限——突发提交可无限并发 ffmpeg/whisper/HeyGen/RunningHub，每线程还常驻整段 base64 payload。仅 whisper 有信号量。
2. **`globals().update(getattr(core))`** 贯穿所有域：把 core 全部名字灌进各域命名空间，隐藏耦合、破坏 lint/IDE/静态分析；core 是 942 行上帝模块。
3. **每请求同步鉴权无缓存**：`core.py` `verify()` 每请求都 HTTP 调 auth `/api/auth/me`(6s超时)，前端轮询 `/api/gen/job/{id}` 每拍都触发一次 → 锤爆 auth。
4. list 端点内联同步外部调用(`audio.py` 列表里调豆包 TTS/复刻状态)阻塞请求线程。

## 目标（分阶段，收益从高到低）
### 阶段1（收益最高、风险可控）：鉴权短 TTL 缓存
- `verify()` 加 **token→user 短 TTL 缓存**(如 5-10s，dict + 时间戳，或复用 feature_flags 的缓存范式)。轮询期间同 token 命中缓存、不再每拍锤 auth。注意：改密/封号后缓存要能快速失效(TTL 短即可)。

### 阶段2：有界任务队列 + 固定 worker
- `queue.Queue(maxsize=N)` + 固定 M 个 worker 线程消费(仍纯标准库)。提交满时排队/拒绝而非无限起线程。各类任务的并发上限可分别配(重活如 video/tryon 更低)。
- 配合 reaper/CAS(#187 已做)。worker 从队列取 job_id、读 payload 跑，别把 base64 常驻线程。

### 阶段3：list 端点去同步外部调用
- `audio.py` 等列表端点**只读 DB**，把预览/复刻状态生成改**后台异步**(worker 或缓存)，别在请求线程里同步调豆包/外部。

### 阶段4（收益低、动静大，可缓）：拆 core 上帝模块
- core 暴露**显式最小 API**或拆 `db/http/providers`，各域 `from core import 具体符号`，去掉 `globals().update`。纯重构、零行为变化，但触及所有域，最后做、独立 PR。

## 验收标准
1. 并发有上限(压测突发提交不再无限起线程/爆内存)。
2. auth 调用量显著下降(鉴权缓存生效、轮询不再锤 auth)。
3. 列表端点不被外部依赖拖慢。
4. (阶段4)改 core 名字不再静默打断多个域；`py_compile`/现有测试全过、能力无回归。

## 部署与验证
