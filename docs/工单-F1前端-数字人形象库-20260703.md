## 后端 API 契约（已上线，直接用；均需 `Authorization: Bearer <token>`）
| 方法 · 路径 | 入参 | 返回 |
|---|---|---|
| `GET /api/gen/video/avatars?limit=120` | — | `{"items":[{id,name,image_url,provider_avatar_id,status,created_at,...}]}` |
| `POST /api/gen/video/avatar-name` | JSON `{id, name}` | `{"ok":true,"avatar":{...}}` |
| `POST /api/gen/video/avatar-delete` | JSON `{id}` | `{"ok":true,"avatar":{...}}` |
| `POST /api/gen/video`（生成） | JSON `{mode:'motion', avatar_id:<id>, reference_video_data, resolution, ratio, duration}` | 同现有生成（带 `avatar_id` 时后端**复用**该形象、跳过建 avatar；**不带 `avatar_id` 时须传 `image_data` 走原上传流程**）| 

> 未登录接口返回 `401 {"detail":"未登录"}`；`avatar-name/delete` 仅能操作本人形象。

## 前端任务（`site/workbench/video.html` 动作模仿标签页）
1. **「我的形象」选择器**：进入动作模仿页时 `GET /api/gen/video/avatars`，渲染形象网格（`image_url` 作缩略图 + `name`）。首项或并列提供**「＋ 上传新照片」**入口（保留现有上传照片流程）。
2. **两种提交路径**：
   - 选中**已存形象** → 提交 `{mode:'motion', avatar_id:<选中id>, reference_video_data:..., resolution, ratio, duration}`，**不传 image_data**。
   - 选**上传新照片** → 保持现流程（传 `image_data`）；生成成功后后端会自动存为新形象。
3. **生成成功后刷新列表**：新照片生成完成后重新拉 `avatars`，让新形象出现在网格里（后端已自动入库，前端只需刷新）。
4. **管理操作**：每个形象支持
   - **改名**：输入框 → `POST avatar-name {id,name}` → 成功后刷新。
   - **删除**：二次确认 → `POST avatar-delete {id}` → 成功后从网格移除。
5. 参考动作视频仍按现有方式上传（本工单不涉及 F2 预设动作库）。

## 边界与注意
- **只改前端**，不碰 `content_api.py`；口播标签页**行为不变**。
- 选中已存形象时，人物照片上传区应相应禁用/隐藏（避免同时传 image_data 与 avatar_id）。
- 空状态：无任何形象时，网格显示引导文案（如"生成一次动作模仿后，形象会自动保存在这里"）。
- 错误处理：接口 401 跳登录；改名/删除失败用现有 toast 提示。

## 验收标准
1. 动作模仿页能看到「我的形象」网格（有缩略图+名字），并有「上传新照片」入口。
2. 用**已存形象**生成：提交带 `avatar_id`、不传照片，生成成功；较首次明显更快（后端跳过建 avatar）。
3. 用**新照片**生成成功后，该形象**自动出现**在网格里。
4. 改名、删除生效且仅作用于本人形象。
5. 口播功能行为不变；视频页无控制台报错。
