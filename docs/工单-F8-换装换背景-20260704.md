## 目标
视频页在「数字人口播 / 动作模仿」旁加**第三个功能 tab「换装换背景」**：给真人短视频一键换衣服和/或换背景，保持原人脸/动作/镜头，产出可直发的美业素材。

## 输入与模式（前端自动判定）
用户上传：**换装视频（必选）、衣服图（可选）、背景图（可选）**。按素材自动定模式：
- 只有衣服图 → **只换装**
- 只有背景图 → **只换背景**
- 衣服图 + 背景图 → **换装 + 换背景**
- 只有视频 → **拦截提示**（"请至少上传衣服图或背景图"）

## 后端（新能力，走 RunningHub 两段式）
- **依赖**：`runninghub_sdk`（`from runninghub_sdk import RunningHubClient`）；密钥 `RUNNINGHUB_API_KEY` 走**环境变量**（**严禁硬编码/入库**）。SDK 安装与密钥注入是**部署前置**，由审核方在服务器上准备（见"部署前置"）。
- **客户端**：`RunningHubClient(API_KEY, base_url="https://www.runninghub.cn", timeout=120)`。
- **两段式**（参考 `run_tryon_bg_from_manifest.py`）：
  - **换装** WebApp `1969605116187844610`：`client.upload_file(视频)`/`upload_file(衣服)` → `run_ai_app(id, node_info_list=[...])`，节点：`363.video`=源视频、`373.image`=衣服图、`362.value`=秒数、`358.value`=宽(576)、`359.value`=高(1024)、`372.text`=`Clothes`（**固定用 Clothes，别用长提示词**，否则会保留原衣服/畸变）。
  - **换背景** WebApp `1986353521488523266`：`upload_file(换装输出)`/`upload_file(背景)` → `run_ai_app`，节点：`352.video`=换装输出、`318.image`=背景图、`339.int`=秒数。
  - 三模式：只换装=只跑段1；只换背景=只跑段2（输入=原视频）；都换=段1输出喂段2。
- **轮询**：`client.get_status(task_id)`；`SUCCESS` 成功、`FAILED` 失败；**`RUNNING` 可能持续很多分钟，只有 FAILED 才算失败**。→ 用**长超时**（这类任务慢，别用视频默认 30 分钟就误杀；给足，比如 40–60 分钟，且 reaper 对该 kind 放宽）。
- **接入任务模型**：作为异步能力接入（提交→job_id→轮询 `/api/gen/job/<id>`），复用现有 phase 阶段跟踪（如 `uploading`/`tryon_running`/`bg_running`/`downloading`）。放 `content_domains` 下新模块（如 `tryon.py`）或 `video.py`，在 registry 注册能力（如 kind=`tryon`）。
- **点数**：给该能力定成本（`cost_of`/COST，两段式偏贵，建议明显高于普通出图；数值先占位、上线前和 kongli 确认）。失败退点。
- **长视频边界**（见 `long-video-boundaries.md`）：一次性换背景约 **≤10 秒稳定，15/16 秒会 FAILED**。**MVP：限制/建议输入短视频**（如 ≤10s），或对超长给出提示；**分片换背景+拼接**属进阶，本工单可先不做但要在 UI 提示时长限制。

## 验收标准
1. 视频页出现「换装换背景」tab，三种模式按上传素材正确判定（只视频时拦截）。
2. 只换装 / 只换背景 / 两者，三条链路都能产出视频，保持原人脸动作。
3. 长视频给出时长上限提示；FAILED 正确报错退点、RUNNING 不误杀。
4. 密钥不在 git；`py_compile` 通过、health 200、不影响现有视频功能。
