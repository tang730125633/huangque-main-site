> **冲突组：B（`site/workbench/video.html`）** —— 锁 `lock/B`。

## 背景
生产环境实测发现(真实账号提交，job#1204/#1209均失败)：果肉视频(Grok Image Video模型)当前**只有16:9(1280x720横屏)能生成成功**，其余4个比例(9:16/1:1/4:5/5:4，均为竖屏或方形尺寸)全部返回上游错误：
```
{"code":404,"message":"当前模型暂无支持该视频参数的可用渠道：渠道不支持当前视频尺寸"}
```
直接调用xiaolevideo.cn API复测确认：跟`duration_seconds`无关，就是尺寸本身被供应商侧拒绝(5个比例逐一实测，仅16:9返回200)。**跟今天参考图数量bug无关，是完全独立的问题**——多参考图功能本身实测正常(job#1209请求体正确带了2张reference_images)。

`9:16`是UI默认选中的比例，几乎所有正常用户操作都会撞上这个失败，属于当前对用户体验影响最大的问题。

## 改动(纯前端止血，不改后端)
`site/workbench/video.html`：
- 果肉视频面板画面比例默认选中项从`9:16`改为`16:9`
- 画面比例区域加一行警示文案："上游供应商目前仅16:9(横屏)出图稳定，其余比例暂时大概率生成失败，问题解决前建议优先选16:9"
- 未禁用其他比例按钮(用户仍可选，只是有warning)，因为供应商问题可能随时恢复，不希望硬编码禁用逻辑

## 已验证
- 本地浏览器实测：默认选中16:9、警示文案正确显示
- `python3 -m unittest discover -s tests` 48/48通过

## 验收标准
1. 用户进入果肉视频面板，默认看到16:9被选中、比例区域有警示文案
2. 其余4个比例仍可点击选择(不强制锁死)，只是有风险提示
