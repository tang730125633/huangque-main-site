# 工单 · 全部生成产出走 COS 直链

> 来自 tang：把所有内容的下载都走 COS 直链，不要再用本地方式。冲突组 **A（server/content_domains）**。前端无需改（沿用各 result 里的 url 字段）。
> 依赖 PR #99（COS 成片存储）已上线；本单把那套"入库后上传 COS、返回直链"从换装(tryon)**推广到全部成品产出**。

## 目标
图片(作图)、音频(配音)、视频(口播/动作模仿/字幕)、换装/换背景——**所有生成成品的对外链接都返回 COS 直链**；COS 未配置或上传失败时自动回退本地 `/api/gen/file/`，对现有流程零影响。

## 改动
- `core.py` 新增通用 `public_url(rel, content_type=None)`：COS 已配置且文件存在 → 上传 COS 返回直链；否则/失败 → 回退本地。`qcloud_cos` 经 `cos` 模块懒加载，**只上传不删本地**（部分产出如配音会被口播视频复用，删了会断链；省磁盘由 tryon 自己的 `COS_DELETE_LOCAL` 单独处理）。各域 `globals().update(core)`，直接可调。
- `image.py`：出图结果 `urls` → `public_url(fn, "image/png")`
- `audio.py`：配音输出 `url` → `public_url(fn, "audio/mpeg")`（克隆/预览流不动）
- `video.py`：口播/动作模仿/字幕成片**最终** `video_url` → `public_url(video_file, "video/mp4")`（单点，覆盖字幕与非字幕两条路）
- tryon 换装已走 COS，本单不动。

## 设计要点（为什么这么改）
- **只在"产出入库"一次性点调用 `public_url`**，绝不放进资产列表端点（`list_video_assets` 等直接 SELECT 存的 `video_url`，不重复上传）——避免每次刷新历史都重传。
- 产出的 COS url 由 `record_*_asset` 存进库；列表端返回库里存的 url，自然是 COS。
- 输入预览缩略图（人物图/形象/参考视频/衣服图）仍走本地——它们是用户上传素材的预览，属"上传侧"，不在本单范围。

## 部署前置
无新增。COS 依赖(`cos-python-sdk-v5`)与密钥(`COS_*`)PR #99 已就绪并在线上生效。
