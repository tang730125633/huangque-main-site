# 工单 · 作图页第4引擎换成果肉生图渠道

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：A（`server/content_domains/**`）+ E-banana（`site/workbench/banana.html`）** —— 抢 `lock/A` + `lock/E-banana`。

## 背景
作图页第4个引擎"泽龙AI"（`provider=zelong`，中转站）代码注释自认"实惠·偏不稳"，且历史上专门开过 RESIL-POOL 工单给它做多号池故障切换，稳定性一直是痛点。而果肉/微衣视频用的 `xiaolevideo.cn` 账号下，本身就挂着一个 `gpt-image-2` 图片模型（同一套 `/api/v1/generations` 统一接口，`model_type=image`），实测文生图/图生图（base64 参考图）都稳定出图，闲置未用。用它替换掉"泽龙AI"这个不稳定选项。

## 改动
- `server/content_domains/image.py`：新增 `_gen_image_xiaole(prompt, ratio, quality, count, img)`，复用 `video.py` 的 `XIAOLEVIDEO_API_KEY`/`_xiaole_request`（创建→轮询→落盘，同 `generate_xiaole_video` 模式）。`gen_image()` 里 `provider=='xiaole'` 时提前分流到这个函数，不走原有 openai/zelong 的 multipart 逻辑（请求/响应结构完全不同）。
- `site/workbench/banana.html`：引擎选择第4个卡片 `data-engine="zelong"`（泽龙AI）→ `data-engine="xiaole"`（果肉生图），`COSTBASE`/`ENGINE_MAXN`/提交逻辑同步改名，价格不变（8/12点，纯换渠道不改计费）。`zelong2`（泽龙2生图，稳定专供号池）保留不动。

## 已验证
- 直接调用 `gen_image({'provider':'xiaole',...})`（本地起进程+真实 XIAOLEVIDEO_API_KEY）文生图成功，落盘+返回结构正确。
- 额外用真实 API 单独测过图生图（base64 参考图），出图正常——不是video模型那种参考图only-URL的坑。

## 验收标准
1. 作图页选"果肉生图"，文生图/图生图都能正常出图，扣点正确（8/12点）。
2. 其余4个引擎（nb2/pro/gpt/zelong2）不受影响。
3. `XIAOLEVIDEO_API_KEY` 未配置时给出清晰报错（"果肉生图未配置"），不是裸异常。
