# 工单 · 点数使用明细 / 消费记录（Issue #316）

> 供其他 agent 独立执行。先读《工单-其他agent实施》§0 +《任务看板》+ `DESIGN.md`。
> **冲突组：A（`server/content_api.py` 或新端点）+ shell（`site/workbench/cloud-shell.js` 点数展示处加「明细」入口）** —— 抢 `lock/A` + `lock/shell`（shell 排他，占时不能有其它前端页任务并行）。
> 相关：ADMIN-5/6 调用日志（后台读 jobs）、#294 cookie 鉴权。

## 现象（#316）
用户只看到剩余点数，**没有消费明细**——不知道点数花在哪、每笔多少。反馈「点数为0，不知道花哪了」。

## 关键：消费数据在哪（已排查 2026-07-07）
- ⚠️ **`points_audit` 表只记「管理员调整/充值」**（5 条都是 +50000，`who_admin` 字段），**不含每笔任务消费**。别只查它。
- **每笔任务消费在 `content_jobs.db` 的 `jobs` 表**：`username, kind, cost, status, created_at, refunded`。这才是消费明细的主数据源（后台 ADMIN-5 调用日志读的就是它）。
- 完整账本 = **jobs 表（每笔消费，负向）** + **points_audit（充值/退点，正向）** 合并按时间排序。

## 待做

### 1. 后端：用户消费明细查询接口（组 A）
新增 `GET /api/gen/points/history?days=30&kind=&page=`（或类似），**当前登录用户查自己的**（走 verify 取 username，别让查别人的）：
- 从 `jobs` 表查该用户记录：`时间(created_at)、功能(kind→中文名)、消耗(cost)、状态(status)、任务ID(id)、是否退点(refunded)`。
- （可选）合并 `points_audit` 的充值/退点条目，给完整流水；或分两段返回。
- 支持 `days` 时间范围（默认30）、`kind` 功能筛选、分页（默认最近30天、每页N条）。
- kind→中文映射复用后台 `call_func_name`/看板已有的功能名（video=数字人视频、image=图片生成、collect=链接采集、leads=关键词获客、audio=配音、copy=文案 等）。

### 2. 前端：点数旁「明细」入口 + 弹窗（组 shell）
- `cloud-shell.js` 点数展示处（`hqPointsSide`/`hqPointsTop` 附近）加「明细」按钮/链接。
- 点击弹居中蒙层（可抄 video #302 vidBox 或 assets #300 提示词弹窗范式），列表展示：**时间 · 功能 · 消耗点数 · 状态 · 任务ID**，顶部可显示当前余额。
- 支持时间/功能筛选、分页/滚动加载；空态「暂无消费记录」。
- 请求带鉴权（cookie/`__cookie__`，与全站一致，#294）。
- **XSS**：任务详情/kind 进 DOM 用 `escapeHtml`/`textContent`。
- 金调 UI 按 `DESIGN.md`。

## 验收标准
1. 点数旁有「明细」入口，点击弹出消费记录列表。
2. 列表准确展示每笔任务的时间/功能/消耗/状态/任务ID，与 jobs 实际一致；充值/退点也能体现（若做合并）。
3. 只能查**自己**的记录（换 token/cookie 查不到别人的）。
4. 时间范围/功能筛选、分页可用；空态友好。
5. 鉴权正确（未登录 401）、XSS 安全、不影响 shell 其它功能（导航/点数刷新/登录态）。
