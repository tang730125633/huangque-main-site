> 来源：Issue #60 qilin 对 `/api/gen/banana` 的审计（第 4 条反馈）。

## 背景
作图 `/api/gen/banana` 走独立服务 **imggen_api.py（:8101）**，它**直连 auth 的 users.db 扣点**（`get_points`/`add_points`），没走 T6 已建的原子点数接口。审计发现 4 个问题，本工单一并修（都在 imggen_api.py）。

## 要修的 4 项

### #4 扣点改走 auth 原子接口（防并发超扣）
- 现状：`get_points`(SELECT) + 直连 `UPDATE users` 扣点，"先查后扣"非原子；且与 auth/content 并发写同一 users.db。
- 改：imggen **不再直连 users.db**，扣/退点改调 auth 的原子接口（T6 已建）：
  - 扣：`POST http://127.0.0.1:8095/api/auth/points/deduct`，body `{username, amount}`，头 `X-HQ-Internal-Token: <HQ_INTERNAL_TOKEN>`；返回 402=点数不足。
  - 退：`POST /api/auth/points/refund`（失败退点）。
  - 需 `HQ_INTERNAL_TOKEN` 环境变量（部署前置：给 huangque-imggen-api 注入同一令牌，见"部署前置"）。
- 删掉 imggen 里直连 users.db 的 get_points/add_points（或改为调 auth 查点）。

### #8 生成前拦截 must_change
- 现状：`must_change=true`（强制改密）的用户仍能调 banana 生成、被扣点。
- 改：提交生成前，若当前用户 `must_change` 为真 → 返回明确提示（如 403「请先修改初始密码后再使用」）、**不扣点、不受理**。（用户信息来自 `/api/auth/me`，含 must_change 字段。）

### #3 加 /api/gen/banana/health
- 现状：文档写了 `GET /api/gen/banana/health` 但线上 404。
- 改：给 imggen 加该健康检查路由，返回 200 + 简单 JSON（如 `{"ok":true,"service":"imggen"}`）。（或若不想加，改为从 API 文档移除该路径——**优先加**，便于监控。）

### #6 修 selftest 坏图
- 现状：`imggen_api.py --selftest` 内置 PNG 被 Pillow 判为坏图、自检失败，可能误报。
- 改：换成**合法 PNG**，或运行时**动态生成 1×1 测试图**（`PIL.Image.new` 存内存），保证 selftest 稳定通过。

## 部署前置（审核方准备）
- 给 huangque-imggen-api 注入 `HQ_INTERNAL_TOKEN`（与 auth/content 同一令牌，来自 `/home/ubuntu/auth-service/auth.env`，systemd EnvironmentFile，不进 git）。

## 边界与注意
- **只改 `server/imggen_api.py`**，不动 content_domains、不动 banana 生成核心逻辑（只改扣点通道 + 加健康检查/拦截/修 selftest）。
- 密钥走 env、不入库。#5 频控**不在本工单**（另议）。

## 验收标准
1. 扣点走 auth 原子接口，点数不足返回 402；并发不超扣；imggen 不再直连 users.db。
2. must_change 用户调生成被拦、不扣点。
3. `GET /api/gen/banana/health` 返回 200。
4. `imggen_api.py --selftest` 稳定通过。
5. 作图主流程（生成/参数校验）行为不变；`py_compile` 通过；`/api/gen/banana` 正常。
