# 工单 · F3 生成进度 + ETA

> 供其他 agent 独立执行。开工前先读《工单-其他agent实施-20260703》§0 公共上下文
> （仓库/分支PR/ship/DESIGN.md/漂移哨兵/**禁止服务器直改**）。

## 目标与价值
视频生成是 1–5 分钟的多步长任务，前端目前只显示"生成中"。把后端**已有的 `phase` 阶段**呈现成可读步骤 + 预估进度，长任务体验大幅提升。

## 现状（已核实，含一处需改的后端点）
- 后端 `content_api.py` 用 `update_video_asset_phase(job_id, "<phase>", ...)` 把阶段写入 **`video_assets` 表（AUDIO_DB）**。
- ⚠️ **但前端轮询的 `/api/gen/job/<id>` 只读 `jobs` 表（JOB_DB），返回里没有 `phase`。** 两张表在不同 DB，`jobs` 里不含 phase。
- 因此 **F3 不是纯前端**：需一处**小后端改动**把 phase 暴露给轮询接口，再由前端映射展示。

### 现有 phase 取值（动作模仿全流程）
`queued` → `files_saved` → `motion_parameters_ready` → `uploading_image_asset` → `uploading_reference_asset` →
`creating_photo_avatar`/`reusing_photo_avatar`/`rebuilding_photo_avatar` → `waiting_photo_avatar`/`waiting_rebuilt_photo_avatar`/`waiting_avatar_look` →
`creating_cinematic_video` → `polling_video` → `downloading_video` →（完成 status=done）

## 方案

### A. 后端（小改动）
- 修改 `/api/gen/job/<id>` 处理：当该 job 是 **video** 时，额外用 `adb()` 查 `video_assets` 里该 `job_id` 的 `phase`，塞进返回，如 `d["phase"] = <phase or None>`。
- 不改任何生成逻辑、不改 `jobs` 表结构；只是**读 video_assets 补一个字段**返回。
- `py_compile` 通过；`/api/gen/health` 200。

### B. 前端（`video.html`）
- `pollJob` 读到 `d.phase` 后，映射成**可读步骤条 + 进度**。建议映射：
  | phase | 显示文案 | 阶段 |
  |---|---|---|
  | queued | 排队中 | 1 |
  | files_saved / motion_parameters_ready | 准备素材 | 1 |
  | uploading_image_asset / uploading_reference_asset | 上传素材 | 2 |
  | creating_photo_avatar / reusing_photo_avatar / rebuilding_photo_avatar | 创建数字人 | 3 |
  | waiting_photo_avatar / waiting_rebuilt_photo_avatar / waiting_avatar_look | 数字人生成中（较久）| 3 |
  | creating_cinematic_video | 生成视频 | 4 |
  | polling_video | 视频渲染中（较久）| 4 |
  | downloading_video | 下载成品 | 5 |
  | (status=done) | 完成 | 5 |
- 展示形式：分步进度条 / 步骤点亮 + 当前步骤文案；"较久"的阶段给出"预计还需 1–2 分钟"之类的宽松 ETA（前端本地估算即可，不要求精确）。
- 口播模式（无 motion phase）保持现有"生成中"或按 status 简单展示，别报错。
- 风格先读 `DESIGN.md`，复用现有轮询与外壳。

## 边界与注意
- 后端仅**新增一个只读字段**，向后兼容，不影响老前端。
- `phase` 可能为 `None`（口播/早期）→ 前端要有兜底（退回"生成中"）。
- 不改点数、不改生成核心。

## 验收标准
1. `/api/gen/job/<id>` 对 video 任务返回里含 `phase`。
2. 动作模仿生成过程中，前端能看到**分步进度 + 当前阶段文案**，长阶段有 ETA 提示。
3. 复用已存形象（F1）时能看到 `reusing_photo_avatar`→跳过建 avatar 的更短流程。
4. 口播模式不报错；视频页无控制台报错。

## 部署与验证
- 后端：`./ship "F3 job状态返回video phase" server/content_api.py`
- 前端：`./ship "F3 生成进度+ETA展示" site/workbench/video.html`
- 建议先合后端再做前端；上线后实测一次动作模仿全程看进度；确认漂移哨兵无新增告警。
