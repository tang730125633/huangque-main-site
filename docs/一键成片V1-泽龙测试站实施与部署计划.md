## 2. MVP 用户闭环

```text
选择本人已有视频资产
→ 创建一键成片项目
→ 自动转录和逐词时间轴
→ 检测开头/结尾静音、长停顿、短气口、重复和疑似片尾补录
→ 用户确认 EDL
→ 生成 clean master
→ 选择 viral-talking-head-v1

→ HyperFrames 渲染
→ QA

```

第一批不包含任意外部 URL、自动生图、B-roll、BGM/SFX、自由模板代码和多人对话。

## 3. 运行架构

### 3.1 后端

- `video_compose.py`：HTTP 合同、权限、状态转换
- `video_compose_store.py`：独立 `video_compose.db`
- `video_compose_analysis.py`：候选检测与 EDL
- `video_compose_media.py`：FFmpeg clean master、时间重映射
- `video_compose_asr.py`：ASR 时间戳适配器
- `video_compose_render.py`：冻结模板准备、HyperFrames 调用、QA
- 不修改 `users.db` 或 `content_jobs.db` schema

### 3.2 ASR

泽龙没有本地 Whisper。MVP 使用现有 OpenAI 配置调用 `whisper-1` 的 verbose JSON / word timestamps。

安全规则：

- 只读取当前用户拥有的视频资产；
- 只上传从本地受保护资产抽取的临时音频；
- 临时音频在请求完成后删除；
- 最大视频时长首版 180 秒；
- 最大上传音频限制；
- ASR 失败不创建付费渲染任务；
- 部署和健康检查不调用 ASR；
- 用户实际点击“开始分析”时会产生供应商成本，测试站需在 apply 确认中明确接受。

### 3.3 HyperFrames 运行时

固定版本：`hyperframes@0.7.90`

隔离路径建议：

```text
/home/ubuntu/.local/hq-node/
/home/ubuntu/.cache/hyperframes/
/home/ubuntu/content-api/video_compose_templates/
```

约束：

- Node 使用固定官方 Linux x64 tarball和 SHA-256；
- 不覆盖系统 Node；
- HyperFrames 固定版本；
- 首次 bootstrap 预下载浏览器；
- `--workers 1 --low-memory-mode`；
- 同时最多一个模板渲染；
- 渲染目录按项目隔离；
- 任务结束删除中间帧；
- 模板只允许注册表中的冻结版本。
