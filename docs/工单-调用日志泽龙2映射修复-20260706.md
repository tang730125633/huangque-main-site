> 来自 kongli 实测反馈：后台用户调用日志里，部分作图记录只显示"作图"两个字、没有具体引擎。

## 根因（已用线上 jobs 数据核实）
ADMIN-6 的 `call_func_name` image 分支里，泽龙只判断了 `provider == "zelong"`。但泽龙升级后实际 provider 值有 **`zelong2`**（线上现有 3 条），未命中 → 回退到通用"作图"。
> 另有 94 条历史 image 任务 payload 里**根本没有 provider/model 字段**（ADMIN-5 之前生成的旧数据），无法追溯，显示"作图"是合理兜底、**不在本单范围**；今后新任务都带字段、正常显示。

## 改动（`server/admin_api.py` 的 `call_func_name`）
把泽龙判断从**精确等于**改为**前缀匹配**，兼容 zelong / zelong2 / 未来 zelongN：
```python
# 原：
if provider == "zelong":
    return "作图 · 泽龙"
# 改为：
if provider.startswith("zelong"):
    return "作图 · 泽龙"
```
- 注意保持判断顺序：先 `model`(nb2/pro)、再 `provider`(openai/zelong*)、最后兜底"作图"。
- provider 已 `.strip().lower()`，前缀匹配安全。

## 边界
- 只改这一处映射，不动其它逻辑、不动前端、不改生成主流程。
- role=admin 门控、payload 白名单读取都不变。
