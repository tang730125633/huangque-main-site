# 工单 · 前端组件化 + 四态范式 + 可访问性基线（Issue #203，epic·工程）

> 冲突组：**shell（排他大组）+ 全部前端页（B/C/E/admin）**。⚠️ **排他性极强**，占它期间禁止一切前端页任务并行——**必须与其它前端 PR 错峰**，一次做一块别贪大。先读 §0+看板冲突组表。

## 现状（技术债）
- 各页内联 JS 重复（token/轮询/上传/缓存戳/下载/登录触发各写一遍）。
- 巨型单文件（video 1283 行 / assets 1285 行）。
- 交互元素普遍 `<div onclick>`，全站键盘几乎不可达（无 a11y）。
- 缓存戳不统一（手工 `?v=8` vs 哈希）。

## 子项（务必分小块、错峰做，别一个大 PR 动全站）
1. **抽公共 JS**（shell/新建 shared 模块）：轮询/上传/缓存戳/下载/登录触发 → 单一实现，各页引用。⚠️ 已有 cloud-shell.js 承载部分公共逻辑，优先扩展它而非新造。
2. **抽公共 UI 组件**：引擎卡 / 比例 / 数量 / 结果区 / 提示条 → 统一样式（对齐 DESIGN.md）。
3. **四态范式**：以 **leads/audio** 为标杆确立「加载 / 空 / 失败 / 未上线」四态，全站对齐（延续 FAKE-UI 假控件收口）。
4. **可访问性**：交互元素 `<div onclick>` → `<button>` + `aria-label`，键盘可 Tab/回车。
5. **统一缓存戳**：手工 `?v=` → 自动化 hash（stamp_assets.py 已有基础，扩成全站 hash）。

## 验收
- 公共逻辑单一实现；四态统一；键盘可达；发版缓存自动更新。

## 备注
- **纯工程债，无直接业务 ROI，但降后续所有前端改动成本 + 修 a11y 合规**。优先级：velocity 疼/合规需要时做。
- ⚠️ **排他大组风险最高**：改 cloud-shell.js 触发全站戳 bump，与任何前端页 PR 冲突。**一次只做一个子项、与业务 PR 错峰**，别阻塞增长功能。分子项工单/PR。完成关 #203。
