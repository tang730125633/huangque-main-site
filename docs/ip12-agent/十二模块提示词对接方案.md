# 十二模块提示词 → IP12 Skill 对接方案

> 2026-08-30 · 基于《IP打造十二模块_提示词全集》与 IP12 现状评估
> 目标：让十二个模块提示词都能作为 Skill 被正常调用

## 一、现状断链（为什么现在"调用不正常"）

| 问题 | 后果（今天实测） |
|---|---|
| ① 各模块"输入格式"是固定字段清单，且 44 个字段全堆在 intake | 20+ 轮卡在基础信息，兴趣/受众/技能等模块 1 字段被提前问掉 |
| ② "断点：等待用户确认"未对接 IP12 确认门 | 自由对话式断点与 revision/pending 状态机脱节 |
| ③ 模块 7-12 在 IP12 无注册 | 执行类模块（形象/脚本/发布/销售/商业化）没有落点 |

## 二、三档改造

### A 档：模块 1-4 → Skill 引导合同（本次实施）
- "输入格式"改为**采集责任合同**：优先复用已采集字段，只追问本模块名下缺失字段（与 `MODULE_FIELD_OWNERSHIP` 对齐）
- 断点映射 IP12 确认机制（pending → confirm，revision CAS）
- 产出：四个改造后的 Skill 提示词（`docs/ip12-agent/skills/`），供 Grok 接入 `coaching_skills.py` 的 instructions

### B 档：模块 5-6 接现有流程
- 模块 5 选题 ↔ content_topics；模块 6 文案 ↔ 文案三篇确认流程
- 提示词作为生成时的 instructions 补强（后续）

### C 档：模块 7-12 → 生产子 Agent 委派
- 模块 7 形象设计 → 数字人形象能力；模块 8 脚本分镜 → script/文案成片；模块 9/10 发布运营 → 矩阵发布类能力；模块 11/12 销售商业化 → 获客/CRM
- 诊断完成（1-6）后，由主 Agent 通过 `production_content_agent` 委派（桥接已通）

## 三、A 档改造要点

1. **字段归属**（已在 `ip12_harness.py` 实现）：
   - intake 核心：姓名/性别/年龄/城市/手机号 + 职业/年限/经历/收入来源/区间
   - 模块 1：挫折、成就、被夸、被吐槽、技能×2、赛道、受众、痛点、差异化、账号、长期兴趣
   - 模块 2：性格词、风格偏好、讨厌风格、内容习惯
   - 模块 3：金句、自我介绍、信任原因
   - 模块 4：翻身/踩坑/逆袭/奇葩故事、团队经历
2. **每个 Skill 提示词统一结构**：角色 → 字段归属（只问缺失）→ 进入条件 → Step 流程（断点=IP12 确认动作）→ 边界约束 → 输出落点
3. **去重硬规则**（写入每个 Skill）：`已采集字段（profile_updates/facts）不得以任何说法重复追问`
